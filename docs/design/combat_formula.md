# 战斗公式：DMG1 / DMG2 / DMG3

确认日期：2026-10-18。本文记录本项目用户明确裁定的规则，覆盖 Idle-Diablo 原公式，以及本项目旧的单步减法伤害说明。数值配置仍为原型值，不代表最终平衡。

## 1. 决策及唯一执行入口

用户确认：保留三阶段；DMG1 为减法且保底 1；DMG2 按闪避→格挡→暴击处理事件；DMG3 使用下述五池；300% 技能加 30% 为 330%；格挡与暴击可以同时成立；基础暴击倍率先用 1.5；首版所有类型统一减护甲，不另计算元素抗性。

普攻、主动技能、骨甲反击、分身和灼烧共用：

```text
Skill / Effect
  → GameSession.SettleDamage
  → DamagePipeline.Resolve（DMG1 → DMG2 → DMG3）
  → GM 承伤修正 / 无敌 → 护盾吸收
  → 实际扣血一次 → 击杀经验 / 待拾取掉落
  → 后置事件安排后续 Effect
```

`Scripts/Core/DamagePipeline.cs` 是唯一数值公式；`SkillRuntime.cs` 中的 `SettleDamage` 是唯一 HP 和击杀奖励应用入口。UI、Buff、弹道和表现层不得直接扣敌方 HP 或重复发放奖励。角色累计攻击和护甲仍存于 `Actor.Attack` / `Actor.Defense`，后者的语义现在是护甲。

## 2. DMG1：攻击减护甲

`B = max(minimum_base_damage, 有效攻击 − 有效护甲)`，当前配置下限为 1。

所有 Physical / Fire / Cold / Lightning / Poison 都执行该式。没有物理非线性护甲公式，没有元素抗性额外乘区，也没有真实伤害旁路。伤害类型是条件增伤的匹配信息；名字包含“火雨”“冰霜”不自动改变伤害类型。本批源技能没有元素类型字段，因此保留源项目实际实现的 Physical。

技能输出倍率不在 DMG1 预乘攻击。例如 100 攻击、20 护甲、300% 技能，先得到 80，再由技能池乘 3，结果 240；不是 `100×3−20=280`。

## 3. DMG2：事件瀑布

1. 闪避成功：最终伤害为 0，结束该次结算，不再判定格挡或暴击。
2. 未闪避：按防守方格挡率判定格挡。
3. 按攻方暴击率判定暴击。格挡和暴击相互独立，可以同时成立。

初始单位闪避、暴击、格挡率均为 0，来自 `combat/unit_attributes.csv`，不是隐藏的随机默认值。概率的合法数学范围为 [0,1]，属性规则可进一步限制。0 和 1 的确定事件不消耗随机数；其他概率从独立战斗随机源取数，不占用掉落随机序列。

`CombatOutcome` 只保存事实，不在 DMG2 中预乘最终伤害。格挡减伤在 DMG3 应用。支持命中、暴击、格挡、正伤害、击杀等后置通知；闪避不是命中，命中也不保证实际扣血。无敌、护盾、100% 格挡可以使实际扣血为 0。

导入技能每一发保存攻方属性快照；暴击在该发首次未闪避的命中结算中确定，此后同一发及其派生灼烧沿用这一暴击事实，仍按目标逐次判定闪避/格挡。这是遵循本次 DMG2 瀑布对源项目“出手即预掷暴击”的适配，不混称为完全逐字复制。基础普攻每次结算重新判定。

## 4. DMG3：五类乘区

先过滤本次技能 ID、伤害类型、远程、BOSS、目标 Debuff 等资格，再聚合。

| 池 | 公式 | Value 的含义 |
|---|---|---|
| 技能 | `S = 本体系数 + Σ技能加值` | 300% 填 3；“该技能伤害+30%”填 0.3 |
| 通用增伤 | `G = 1 + Σ符合条件的通用加值` | 火焰、远程、对 BOSS 等同池加算 |
| 暴击 | 暴击时 `C = 基础暴击倍率 + 额外暴击伤害 + Σ暴击池加值`；否则 1 | 额外暴伤+30%填 0.3，基础1.5时得到1.8 |
| 倍率增伤 | `M = Π独立倍率` | ×1.5 填 1.5，×2 填 2；不能写成0.5或1 |
| 易伤 | `V = Π每类Debuff(1 + Σ该类Debuff加值)` | 同稳定 Debuff ID 加算，不同 ID 叠乘 |

格挡因子：成功格挡为 `Q = 1 − block_reduction`，否则为 1。它是防守修正，不是新增进攻池。

`最终公式伤害 D = B × S × G × C × M × V × Q`。

保留当前项目浮点结算，不引入 Idle-Diablo Demo 的向下取整。保底只在 DMG1；系数为 0、闪避或完全格挡均可得到 0，不能在最后再强制至少 1。非有限值、负倍率、乘法溢出明确拒绝。

### 可手算验收例

攻击100、护甲20；技能300%及该技能+30%；火焰、远程、BOSS增伤各30%；暴击基础1.5、额外暴伤0.5、另一暴击加值0.2；独立倍率1.5及2；易伤状态加值20%与30%；重创状态加值40%；成功格挡减伤50%：

`80 × 3.3 × 1.9 × 2.2 × 3 × [(1+0.2+0.3)×(1+0.4)] × 0.5 = 3476.088`。

若没有重创，重创的因子不能生效；未匹配技能 ID 的增伤不能进入技能池。相同数值的两条独立倍率记录仍按两条来源计算，不能按值去重。

## 5. 来源和快照边界

攻方快照保存当时有效攻击、事件属性和进攻乘区；目标护甲、格挡、闪避、当前状态和条件生命比例在命中时读取。斩杀倍率及“目标已有状态”增伤进入独立倍率修正，不挤入技能加算池。灼烧沿用原因攻击快照及暴击，不再次叠加斩杀/已有状态条件。

`DamageModifier` 是已投放来源的结算输入，不是“新属性自动生效”机制。每条包含桶、数值和资格；易伤必须绑定稳定 DebuffId。Buff 的相同 ID 刷新会替换旧实例，避免旧来源残留。`fightattr.csv` 注册属性并约束合法操作，具体来源绑定仍由技能/Buff/后续装备系统负责。

## 6. GM、HP 与奖励

GM 怪物攻击倍率在 DMG1 前乘入攻击；有效血量倍率在公式结算后除以玩家造成的伤害。无敌阻止怪物扣血，护盾随后吸收剩余伤害。`DamageBreakdown.FinalDamage` 是公式值，可能与实际扣血不同；过量伤害只扣到 0。

怪物首次死亡后立即增加击杀并给上阵英雄（含倒地者）按各自等级差发放经验，候补不参与；同目标死亡后拒绝再次结算。金币和杂物只生成待拾取掉落，仍须清房、救援后走近入库。不得把 Effect、OnKill 或表现事件变成第二个奖励入口。

- 公式及事件顺序：`DamagePipeline.cs`，配置 `combat/damage_rule.csv`。

- 实际扣血、护盾和奖励：`SkillRuntime.cs/SettleDamage`。
- 验收算例、概率顺序、零伤害及五池：`tests/CombatSkillChecks.cs`。
- 现有救援、拾取、快照和备份恢复：原核心回归继续保留。
