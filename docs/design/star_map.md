# 星图与 GM 节点编辑器

## 来源与首版规则

玩家星图及 GM 星图编辑器都占满顶部功能栏以下的全局内容区，隐藏游戏页货币、交互、小队和药剂 HUD；编辑器的画布与字段面板共享全屏内容区，保留滚动及草稿保护。

根据用户授权只读参考 E:/Git/Idle-Diablo 的 config/talent/README.md、docs/reviews/2026-10-17/talent_migration.md、docs/systems/ui/settings_gm_audio.md，以及 TalentConfiguration、TalentProgression、TalentEditorDocument、TalentEditorStore、TalentCanvas、BattleDemoTalentUi。迁移保留三表合同、稳定 ID、任一前置、唯一根、无环、网格布局、画布交互与编辑草稿/保存保护；未修改参考工程。

玩家入口为顶部“星图”。消耗金币单击节点升一级，不自动加点。首批 7 节点仅每级全队攻击 +1 或生命上限 +1，金币价目和最大等级均为临时 CSV 配置。生命上限增加不治疗，阵亡队员不会因此复活；三名队员统一获得加成，伤害继续使用既有实现。节点任意一条前置点亮一级即可开放，不要求满级；玩家只显示已点亮和前置已满足的节点。占位节点不能购买。

画布支持拖拽平移、鼠标中心滚轮缩放、重置视图。悬停显示当前到下一级效果、费用、金币不足/满级等原因。购买保留视图位置，先验证全部队员属性，再一并提交金币和等级并请求后台保存；失败不扣钱。玩家星图保持放置逻辑运行。编辑器和 GM 菜单暂停主线，不补跑暂停时间。

## GM 与编辑器

“GM”位于设置左侧，作为今后所有调试功能的统一菜单。目前只放“星图节点编辑器”，玩家星图页不暴露开发入口。编辑器可在开局选队前使用，只有源码工程（res://Idle-CRPG.csproj 存在）允许保存源配置；导出游戏不能写源表。

- 选择模式点节点选择，点空格创建无效果占位节点。稳定 ID 使用 GUID，删除后不会复用。
- 移动、复制：选择节点后切换模式，再点目标空格。复制继承内容和意图，但得到新 ID。
- 连线：先选下游节点，切换模式，点击上游节点添加/移除前置。可用字段直接编辑分号分隔前置列表。
- 修改名称、编辑标签、最大等级、逐级金币价目、属性、操作、每级数值、图标和意图，点“应用字段到草稿”。当前效果仅支持 attack/hp 的 flat，保留字段结构供未来扩展。
- 支持设根、删除、撤销、重做。删除时子节点继承被删节点的前置；草稿允许临时未连线，保存时完整校验。
- “保存三表”校验唯一根、环、ID 对应、格子占用、引用、价目与效果，并验证当前已购等级和最终角色属性。无法删除已购节点、降低上限使已购等级非法，或破坏其前置。
- 保存后立即刷新当前会话，按星图贡献差量调整属性，不重复叠加或清掉等级成长。外部修改源表时拒绝覆盖；“重新加载 / 丢弃”重读源表。未保存草稿离开编辑器或跳页会被阻止并提示，先保存或明确丢弃。

三文件先写临时文件再替换，进程内失败尝试回滚；不保证断电时跨三个文件的事务原子性。意图侧车仅供编辑，启动游戏不读取；缺失可按空意图编辑，存在但损坏则拒绝加载/保存并保留原文件。草稿和 GM 工具状态不进入玩家存档。

## 配置与持久化

config/star/star.csv 为节点内容，star_layout.csv 为布局/前置，star_plan.csv 为意图侧车；使用标准 CSV 引号与换行转义，列表字段用分号。字段见 technical/config.md。文档只在 docs，不放 config。

玩家存档保存稳定 ID/等级，以及上次已应用的攻击与生命贡献。已有聚合属性在读取时按贡献差量重算，避免重复叠加；旧档没有星图字段按零点数读取，不退款或自动丢弃未知/非法节点。战斗中购买也保留金币扣除、节点等级和属性收益，房间重开仍保留星图。确认重置进度会清空星图购买，但不修改三张源配置或显示/音频设置。

## 检查入口

核心检查包含金币不足、逐级费用、满级、OR 前置、全队属性、保持生命、存读档不重复、坏存档、属性失败不扣费、创建复制移动删除/继承前置、撤销重做、设根、CSV 换行引号、外部修改与已购节点保护。Godot --smoke-test 操作真实画布、GM 入口、应用/保存按钮，只写 artifacts/qa 下的配置副本。--capture --capture-stars 和 --capture --capture-star-editor 提供原生窗口截图。
