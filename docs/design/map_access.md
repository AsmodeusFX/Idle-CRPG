# 地形阻断与区域前置

2026-10-18最新确认：区块为单格，区域为同一统治要塞的全部可进入格子。每个区域独立配置解锁方式：`any`表示任一前置通关，`all`表示全部前置通关。两种模式可在同一地图混用，旧配置默认any。

在本章 `world/areapart.csv` 设置：

```csv
id,castle_id,initially_unlocked,unlock_mode
ap4,A04-C01,0,all
```

前置项目仍逐行放在region_prerequisite.csv（显式地牢条件）或areapart_prerequisite.csv（旧统治要塞条件）。例如ap4配置两个前置时，any满足一个即可，all必须两个全部通关。非初始区域无前置时保持锁定，不能利用“空集合全部满足”开放。初始区域保持默认开放。

选中区域详情明确显示“满足以下任一条件”或“满足以下全部条件”，逐项列出地牢/要塞名称及✓已完成、·未完成；内容可滚动查看，城堡行悬停也显示同样规则。地图通路、自动选目标和挑战入口共用核心门禁判定，UI不自行授予解锁。

## 不可进入地块

各地图 `world/region.csv` 新增必填 `enterable`（0/1）。格子仍覆盖完整矩形；enterable=0用于勾勒山脉、海洋等轮廓，不允许配置地牢、村庄、统治归属或区域前置。出生格必须可进入。mountain/ocean两种地形必须配置为不可进入，其他地形也可单独设为0。

阻断格不参与章节通关、统治区占领、自动选目标和探索。整个格子对应的所有8×8寻路子格都不可走，起终点也不能落入。地图与连续室外场景绘制山脉/海洋，不能穿过；地图点击允许查看“不可进入”说明，不安排移动。它们可常显以勾勒地貌，但不揭示邻格怪物或探索状态。

第四章保留已有山脉/海洋边缘格示例；第一章已按正式规划替换为8×8，见 [第一章规则](act1.md)。其余地图仍可按相同字段逐格配置。统治区连续性只计算可进入格，不能跨山脉计算接壤。

## 显式地牢前置

新增每章 `world/region_prerequisite.csv`：

```csv
id,region_id,required_dungeon_id
gate_1,25,c1
gate_2,25,d1
```

id为唯一行ID；region_id为本章可进入格；required_dungeon_id引用本章普通地牢或统治要塞。示例在any模式下表示c1或d1任一通关，在all模式下表示二者均通关。同一区域多个格上的前置按所属区域unlock_mode聚合，开放/锁定范围始终是整个统治区域，不能只开放一个格。

区域有该表配置时，以它作为完整门禁，覆盖该区域原 `areapart_prerequisite.csv` 条件；没有新配置时读取原areapart前置，同样按unlock_mode计算。初始区域默认开放且不得另配门禁。无条件的非初始区域不能因“相邻”“曾探索”或“自身城堡已记录占领”自动开放。显式前置不要求引用相邻区域，但最终必须存在遵守门禁的实体通路。

区域解锁与攻城解锁是两件事：区域前置满足后可进入扫荡；其统治要塞仍要求本区域所有普通地牢通关，且由玩家主动点击安排挑战。普通地牢前置只有在配置直接引用该地牢时有效，不能把附近任意地牢通关当作开放条件。

地图详情和城堡行悬停显示当前配置的前置及完成标记。配置表可只有表头，表示没有格子级覆盖规则。每张地图独立引用，不跨章节或难度借用完成记录。

## 校验与旧进度

拒绝重复前置、失效引用、阻断格引用、初始区域门禁、自身区域内地牢前置，以及门禁/阻断共同导致的推进死锁。加载时从出生格逐轮模拟可达区域及可完成地牢，确保所有配置地牢最终可达；此检查针对格子级地形及前置，不替代已有细网格障碍检查。

WorldSnapshot新增TerrainVersion=1。旧档缺字段时，过滤新增阻断格探索记录和已移除地牢记录；若当前位置、目标或路线失效，保留角色成长、技能、金币、背包和有效通关记录，放弃旧现场并回初始村庄补给交易。新增阻断格上旧的未拾取战利品随被放弃现场消失。新版本档位置/路线落在不可走格直接拒绝，不静默穿越。已完成章节历史同步清理移除的占位内容，仍须通过完整性检查。

旧 `Generate-WorldLayout.ps1` 只用于复现原16×16全可走地图。检测到阻断格或显式地牢前置时拒绝覆盖，避免生成器按邻接重写策划关系。

验证：`tests/TerrainGateChecks.cs` 覆盖全部阻断子格、实际寻路、普通地牢/要塞OR、整区域开放、探索/自身占领不能绕门禁、不可推进地图拒绝和旧档安全迁移。Godot章节冒烟同时点击第四章阻断格核对详情与清单。
