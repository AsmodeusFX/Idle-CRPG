# 召唤物跟随与脱队闪现（V0.1）

2026-10-22 实现，数值均为原型，最终平衡由用户统一重算。规则来源：用户《Steam D2｜召唤单位跟随与脱队闪现 V0.1》。行为入口为 `Scripts/Core/SummonRuntime.cs` 的 `FollowDungeonSummons`，只在地牢逻辑步执行。

## 三档移动

- 正常跟随：主人与召唤物同处一室且距离不超过跟随距离时完全不动；超出后朝“主人身后跟随距离处的落点”等距尾随。目标是落点而不是主人坐标，因此不会贴到主人身上，也不会在 3 单位边界上每步启停。
- 加速追赶：距离超过跟随距离时，本步速度取 `max(召唤基础Speed, 主人当前行走速度×catchup%)`；回到跟随距离内立即恢复基础 `Speed`。追赶只是临时移动策略，不改写 `Actor.Speed`，也不写入存档。
- 脱队闪现：满足“非战斗、当前房间已清理、主人位于合法房间、召唤物未施法/未接敌/未被锁定、距离超过闪现距离并持续超过延迟”时，把召唤物同步到主人附近。同主人的多只召唤物按黄金角螺旋分配互不重叠的虚拟站位；闪现只同步坐标并释放旧接敌占用，保留 HP、Buff、数量与冷却，不重新召唤、不产生伤害/命中/击杀/拾取事件。

## 配置

`config/system/config.csv` 新增四条必填整数规则，均由 `TalentConfiguration.Load` 校验；越界或缺失直接拒绝加载。

| id | 原型 value | 含义 |
|---|---|---|
| summon_follow_distance_milli | 3000 | 千分之一世界单位；正常跟随距离，同房内该距离内不动 |
| summon_catchup_speed_pct | 120 | 追赶速度相对主人当前行走速度的百分比，必须≥100 |
| summon_blink_distance_milli | 8000 | 千分之一世界单位；超过此距离才可能闪现，必须大于跟随距离 |
| summon_blink_delay_milli | 500 | 毫秒；持续脱队达到该时长才闪现，任一条件中断即清零 |

## 战斗与跨房

- 未清房且召唤物在本次房间内时沿用原有规则：不参与跟随、不闪现；战斗 AI 自身走位仍受基础速度限制。清房后重新按距离判定，脱队计时从 0 累积。
- 跨房、走廊继续沿真实房门与走廊连续移动，禁止朝主人直线穿墙；换层与进房由 `PlaceSummonsNearParty` 统一落位，保留实际 HP，不补满。
- 闪现落点限制在主人所在房间边界内；若主人在走廊等无房间坐标的位置则只追赶、不闪现。
- 召唤物基础 `Speed`、接敌容量、怪物锁定规则均未改动；闪现只释放该召唤物自身的旧锁，怪物对其他目标的锁不变。

## 表现插值

`MotionPresentation.BeforeTick` 同时记录召唤物上一逻辑步的位置，使其与英雄、怪物使用同一套固定步插值。此前缺少这一步会让召唤物每个逻辑步冻结再跳变，是预览中“严重卡顿”的根因；本次一并修复。

闪现是瞬时位移，若照常插值会被画成横穿地图的滑行，因此 `GameSession.SummonBlinkedThisTick` 只在该逻辑步内标记闪现对象，表现层对它们直接取新坐标。该标记是临时表现状态，不进入存档。

## 验证

- Core：`tests/SkillBdSummonChecks.cs` 覆盖跟随距离内静止、超距提速且不超上限、持续脱队 0.5 秒后闪现、闪现保留 HP/数量且不产生击杀经验掉落、未清房不闪现、同主人两只召唤物落点不重叠，以及原有跨门/跨房/回城清理回归。
- 界面：`dotnet build` + Godot `--smoke-test`；预览确认召唤物移动连续、无逐帧顿挫。
