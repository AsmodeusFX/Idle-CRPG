## 新旧数据与ID迁移

1. **冻结旧测试基线。** 归档skill目录全部CSV及有关combat/system配置，记录来源、日期和哈希；用显式旧回归入口加载副本或测试覆盖，正式新角色和章节不能误用。新公式下的旧样例必须标为旧输入对照，旧伤害期望不能当新公式回归标准。
2. **单独拟定新技能目录。** 17个草案ID和职业三系为设计输入，为每个新节点列最终稳定ID、类型、学习前置、主动槽、效果、来源资格及数据状态。保留ID或新ID逐项决策，不因名称相同就强制继承旧行为。旧48节点和15导入技能退出正式配置的范围分别列清。
3. **玩家兼容先表后码。** 逐旧ID提供映射、替代、退款或仅旧测试保留的处置。包括Talents、SkillIds、SkillLevels、TalentBonuses目标、SkillSwapLocks、StartingSkillGranted、初始技能表和树前置；不得把未知ID直接删掉、把初始化标记重置后多送一点，或覆盖已装配技能。
4. **角色与星图不重置。** 保留个人等级/经验/资源、候补、已购星图、最多5人、1到5技能槽；技能点仍按已确认预算，新增总上限另批。换队流程维持NPC执行和旧地牢放弃。
5. **唯一正式入口切换。** 新目录、加载校验、存档迁移、初始创建、UI及回归通过后，同次变更切换正式引用；旧数据只经显式TEST_ONLY入口使用。引用清单验证无遗漏后移出旧生产配置，删除清理清单须与最终实施范围一起审阅；不保留可被误调用的双套战斗管线。

尚未裁决的旧点数退款/映射、骨系类型、三系布局和技能数值不能在本轮先编成迁移常量。实际搬移配置前提供完整文件清单、ID映射、受影响旧档样例和回滚方案；[迁移前置清单](../reviews/2026-10-22_skill_bd/06_migration_inventory.md)已列出拟改文件、17技能稳定ID建议、五职业存档字段样例、加性/重排两种策略与回滚边界，待M1～M7裁决后才实施。

## 持久化与唯一状态约束

SkillBattleState仍是短期房间现场，正式CaptureProgress不保存怪物现场。跨房召唤需要在现有SessionSnapshot内设计持久实体与进房检查点，不能保存整个SkillState绕过重开。范围Buff/光环的权威仍在现有Buff数据，持久召唤的唯一实体状态在Core，不在Godot Node。

光环/召唤卸槽、主人死亡、全灭、换队时如何清理需专项决定；在此之前不生产投放召唤存档。尸体token归本房死亡事实，不和视觉尸体或独立“尸体库存”并行。经验/实物拾取沿唯一入口，不修改原房间重开允许再次击杀经验的规则。
