## 1 执行与测试覆盖

| 项 | 值 |
|---|---|
| 入口 | `tests/EconomySimChecks.cs`，命令 `dotnet run --project tests/IdleCrpg.Checks.csproj -- --economy-sim --economy-minutes=240` |
| 驱动方式 | 真实 `GameSession.Tick(0.05f)`（20Hz），真实 `TickDungeon`/`WorldCampaign`/战斗/掉落/升级；无 GM 加成、无跳关、无改敌人属性 |
| 种子 | 20261023（A/B 相同） |
| 配置 | 正式 `Idle-CRPG/config`（`LegacySkillConfig.Load`，不叠加退役基线） |
| 账号初始 | 单英雄野蛮人、0 金币、1 技能槽、星图全空、天赋 0 点 |
| 时长 | 每策略 240 游戏分钟（288000 tick）；检查点 30/120/240 |
| 墙钟耗时 | 两策略合计 **16.3 秒**（4 小时游戏时间的模拟成本很低，4 小时档可常态复跑） |
| 移速修正 | 已生效：五章 `travel_speed=0.31`（大地图 ≈223 px/s）；本次模拟包含该修正 |
| 未覆盖 | 视觉/截图、内存与长稳、玩家真实点击节奏、装备（未实现） |

**策略定义**：A＝纯挂机无任何成长操作；B＝每游戏分钟调用正式接口尝试购买星图、学习天赋、装配技能、请求编队（失败不伪造）。

已知缺陷：B 的**星图购买时间戳**记录不可信（日志集中在最早一次成功购买附近），最终节点数与金币余额仍可由 summary 核对；时点请以 30 分钟汇总为准。

## 7 功能断点清单

1. **自动主线无法完成章节**：城堡挑战必须手动发起，纯挂机在第一章内循环；`GameSession.RequestCastleChallenge` 只能由玩家触发。
2. **升级路径依赖“换更高挑战等级的地牢”**，但自动选择器在同章内反复选低挑战地牢，导致等级差惩罚把经验压到 0。
3. **金币没有出口**：星图满级后无消费点（商店/赌博/雇佣兵均为“待开放”）。
4. **新英雄解锁后没有自动/提示编队**（有 `RequestFormation` 接口，但需要玩家在凯恩处操作）。
5. **无失败反馈/难度选择引导**：玩家只能靠手动改挑战目标突破停滞。

## 附：配置推算（与实测区分）

| 推算项 | 值 | 来源 |
|---|---|---|
| 每级属性 | +4 ATK / +18 HP | `hero/herolevel.csv` 差值 |
| 同级升级所需击杀 | 9 只（`18L ÷ 2L`） | `herolevel.exp` ÷ `spawn_rule.xp_base` |
| 星图属性收益 | +16 ATK / +15 HP（413 金） | 4 个攻击节点 + 3 个生命节点 |
| 星图属性≈英雄等级 | +16 ATK ≈ 4 级；+15 HP ≈ 0.8 级 | 与每级 +4/+18 对比 |
| 天赋点 | 1 + (等级−1)；L7 = 7 点/人 | `system/config.csv` |
| 怪物成长 | HP ×(1+0.18(L−1))、ATK ×(1+0.12(L−1)) | `monster/monsterlevel.csv` |

以上均为配置推算，不代表已实测；实测见第 2–4 节。
