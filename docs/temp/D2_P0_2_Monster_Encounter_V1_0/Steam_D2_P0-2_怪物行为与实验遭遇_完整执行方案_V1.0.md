# 02｜怪物行为原型 M01–M08：可实施规格 V1.0

## 0. 职责与非目标

**原型负责行为组合，正式五章怪物身份由后续07专项提供。** `Melee / Ranged / Flanker / Stationary` 是提议的行为语义，不代表要创建4个新的AI基类。`Swarm / Bruiser / Caster / Summoner / Support` 是可组合功能标签，不是另一套战斗调度器。

公用规则：怪物仍使用统一战斗单位/攻击/技能状态、技能CD/前后摇、现有HP/护甲/抗性与固定Tick、目标锁定；不引入仇恨表、不用实时寻路和真实单位间刚体推挤。范围与追击始终按已有战斗Core合法性检查。**激活时刻必须尊重当前敌人AI启动延迟与小队入场散开；旧文档“即刻攻击”已被用户实机方案修正。**

## 1. 通用 Monster 实例合同（应映射现有类型）

| 语义 | 要求 |
|---|---|
| MonsterIdentity | 原型ID（M01–M08）、怪物内容ID（五章之后关联）、实体唯一ID、阵营、等级/难度来源 |
| Behavior/TargetPolicy | 基础索敌策略＋显式特殊策略；不允许引入DPS/治疗仇恨 |
| AttackMode | 按当前普通攻击方式确定近战容量或远程最近合法目标；特殊技能可自带独立选目标规则 |
| Movement | 按当前1D X逻辑与有效房间边界移动；可使用现有视觉Y散开，不改变伤害合法性 |
| Skills | Skill/Effect/Buff/Trigger复用；CD开始时机与Windup→Commit→Recovery不变 |
| Activation | 读取既有敌AI启动延迟，入场散开和门口保护边界；单怪刷新/召唤的激活条件核实后复用 |
| Death/Reward | 每个实体最多一次有效死亡与收益；SummonedMinion独立奖励资格（待工程审计/用户批准具体策略） |
| Persistence | 当前房间有效敌人、刷怪进度、召唤物状态按现有Encounter完成/失败规则处理 |
| Diagnostics | 输出AI来源ID、TargetId、重选原因、当前动作、技能及失败原因、激活时间等可开关事实 |

**未知与待审批：** 具体移动速度/伤害/HP/攻击距离/CD/召唤间隔、怪物等级成长与真正房间坐标、技能是否可打断、追击边界、Boss特殊策略、奖励数值。测试配置可使用占位值，但禁止作为正式平衡。

## 2. M01 普通近战（Melee Basic）

- **用途：** 最小AI基准，承担T01与所有其他房间的基底。
- **攻击：** 单目标近战普攻；不默认额外Buff。
- **目标：** 正常近战容量优先；容量耗尽时优先选择其他合法对象；无其他目标时允许`Overflow`攻击满载前排；可被嘲讽`Forced`覆盖。
- **移动：** 有目标后接近至已有有效射程；目标不可达/死亡按既有合法决策时刻重新索敌。
- **可观测：** 稳定锁定、Normal/Overflow/Forced（若代码已有等价状态，以等价表达）、近战容量预占/释放。
- **不允许：** 受高伤害就改去打法师、每Tick平均分怪、容量为0的后排免疫近战、持续物理推挤。

## 3. M02 快速集群近战（Swarm Fast）

- **基类行为：** 完全复用M01普通近战索敌与攻击，不得仅因跑得快就越过容量规则。
- **差异：** 较快的移动节奏、相对较低的单体生存、数量优势（候选数值在TEST_ONLY中）。
- **能力价值：** 超出坦克接敌容量后压迫后排，使AOE/冰霜控制/前排成长具备可观感价值。
- **风险：** 门口极易拥挤；必须保留敌AI延迟、小队先散开、稳定虚拟站位和入口合法区域。移动速度不能突破现有合法追击/攻击射程限制。
- **验收：** T02群体分散、入口无堆叠卡死、CD内远程角色不无限退让。

## 4. M03 重型近战（Bruiser）

- **基类行为：** M01近战容量优先；即使体型大仍遵守普通容量，不默认突破前排。
- **差异：** 相对高HP/高单次攻击/较长攻击前摇/较慢移动与攻击节奏。
- **额外攻击：** 可用单体重击技能作为扩展；首版不需要专属击退/地形物理反应。
- **定位：** 检验前排物理百分比护甲、格挡、恢复和单体BD，而非只考验怪物数量。
- **验收：** T03记录伤害与承伤，怪物不会因攻击慢导致AI失效；护甲公式实际状态依P0-1，不在此修改。

## 5. M04 普通远程射手（Ranged Basic）

- **目标：** 选择最近合法目标；**完全不占近战接敌容量**，不因前排容量变化重分配。
- **移动：** 不满足射程时接近；射程内以站定攻击为主。**首版不持续后撤风筝**。
- **攻击：** 既有投射物/连续碰撞检测与合法墙体/攻击线，不能靠虚拟Y偏移改变是否命中。
- **重新索敌：** 当前目标失效/无法合法攻击时按现有决策规则处理；不默认优先后排。
- **验收：** T04射手不会使用容量表、不对入场法师频繁锁定抖动、不破坏投射物碰撞。

## 6. M05 远程范围施法者（Ranged Caster）

- **基础：** 可复用M04远程站定与最近目标，不能默认风筝。
- **特殊技能：** FireBolt或AreaStrike **示意**；独立的Skill TargetPolicy可瞄准有效单体附近范围/合法区域。以实际既有Effect能力为准。
- **目标规则：** 普通攻击与一次特殊AOE的目标独立，AOE不自动修改怪物普通目标锁定，不占接敌容量。
- **范围限制：** 不穿越禁用边界，不在非法地面生效；技能锁定后目标移动的结算按现行Skill Runtime，不为本包新增预判系统。
- **验收：** 远程受打击合法、AOE同时攻击多个目标但遵守技能命中次数与DMG协议。
- **用途：** 可作为T08特殊Boss技能的弱化测试基元，**不等于已经完成Boss**。

## 7. M06 后排猎手（Flanker Special）

- **身份：** 少量特殊近战敌人；与速度快的M02严格区分。
- **目标：** 专属显式`BacklinePriority`测试语义，优先在**现有合法范围/候选集**中寻找具有后排/远程战斗职责的对象；否则回退最近合法目标。不能直接穿墙或越过追击边界。
- **容量：** 使用特殊TargetPolicy时，**允许跳过普通前排优先承接步骤**（不等于目标免疫伤害）；如果其攻击意图仍是近战，如何记录锁定类型须映射既有系统并审计，不能伪造`Normal`占用后排0容量。
- **技能：** 可选有限范围冲刺/短突击；仅在现有Move/Skill/Effect支持时实施；不具备时可先测专属索敌并将冲刺列待审批。
- **反制：** 玩家`Taunt`或有限救场`Forced`有效；冻结/眩晕等照统一规则；不天然免疫。
- **验收：** T05出现明确后排压力；嘲讽与控制有价值；猎手不永久黏住不存在目标；无非授权传送或真实碰撞穿越。

## 8. M07 召唤/复活巫师（Summoner Enemy）

- **基础：** M04或现有Caster模板作为远程/低频普通攻击，独立召唤技能。
- **技能：** 有限CD召唤指定怪物（第一阶段建议仅复用M01或M02），或通过已有死亡/尸体记录复活；**是否使用尸体必须按实际现行合同审计。**
- **数量限制：** 每个召唤者或技能的同时存活单位数量上限；总刷新和连锁防刷护栏待配置，需不产生无限奖励链。
- **来源：** 每个召唤单位记录`OwnerId / SpawnSource / RewardEligibility`等语义；非主动奖励来源，不能按普通关卡怪无条件反复发放经验/金币/掉落。
- **核心风险：** 召唤单位被清理后继续召唤导致房间永远打不完；召唤者死亡与剩余仆从如何参与完结检查必须沿现有Encounter规则并请示不明确项。
- **验收：** T06观察生成→索敌→死亡→名额释放→奖励唯一→房间结束，无无限刷取。

## 9. M08 支援法师（Support Caster）

- **基础：** M04远程普通行为，特殊技能向有效友方怪物施加标准Buff或治疗（具体采用哪项由本包测试方案指定）。
- **测试技能：** 测试Buff给予队伍中的其他敌人明确可观测强化（建议提高攻击间隔或攻击属性的有限Modifier）；此处不用新伤害类型。
- **规则：** 能否自己受益、光环/瞬时Buff作用范围、同名Buff叠加以及施法者死亡时的失效/自然到期，都遵循当前Buff G01–G02合同。**不能硬编码所有Buff在施法者死亡时无条件删除**；区别持续源光环与施加后独立到期Buff。
- **自动目标：** 选取有提升价值且状态合法的友方怪物，不强制玩家角色优先集火支援者。
- **验收：** T07观察被强化怪物的状态/来源、作用随生命周期正常改变；Support死亡后无残留非法属性，也无技能每Tick重复施放。

## 10. 精英与Boss的接口边界

- `Elite`是M01–M08的能力叠加/词缀，不创建第9套基本移动AI。本包只预留语义，不做正式词缀池。
- Boss的普通攻击复用近/远程规则，**特殊技能**独立Skill TargetPolicy、范围、阶段条件；首个Boss T08采用现有工程真实Boss或**显式 TEST_ONLY 代理**。若当前没有Boss控制器，报告`BLOCKED`并给出最小实现审批选择，不要私建完整Boss系统。
- Boss控制抗性、异常伤害上限、阶段转变等数值及机制仍待07专项确定。

# 03｜八间标准实验房 T01–T08（独立测试场景规格）

## 0. 共同前提

- 这些房间为**专用开发测试内容**，不自动加入现有五章正式地图、怪物池、Castle、地牢收益表。
- 各房间遵守现有房间入口、玩家入场散开、敌AI激活延迟、房间界限与完成规则，不绕开现有Encounter/Area流程。
- 同一局测试的角色、怪物等级、属性、技能、装备、随机种子和测试配置冻结；**比较不同机制只改一项变量**（如Capacity=3→4）。
- 角色单人/双人/四人阵容必须适配**首发最多四人**的现行限制；技能未完成时可以在隔离测试用fixture注入模拟效果，不能宣称正式技能已实现。
- 真实战斗逻辑为Core权威，视觉Y散开不改变逻辑射程。这里“前后、左侧、入口”均需映射现有战场位置数据，**本包没有擅自制定可用坐标**。
- 怪物在合法激活时刻之前应表现出已有非主动/延迟行为，不因测试要求“积极战斗”而取消AI启动延迟。
- 标准测试流程：载入隔离场景 → 锁定参数/seed → 入场与展开 → 激活 → 至少一个完整决策与攻击周期 → 清理/死亡/重试 → 重跑比对日志与画面。

## 1. 测试用推荐队伍与变量

| 代号 | 建议队伍 | 验证目的 |
|---|---|---|
| P-SOLO-FRONT | 单前排（容量为测试值3） | 测Overflow合法追击，别等后排才激活 |
| P-SOLO-RANGED | 单法师/纯弓游侠（容量0） | 0容量仍可被多个敌人攻击；受击退让见真实版本 |
| P-PAIR | 前排(容量3)+后排(容量0) | 容量溢出迁移、后排退让 |
| P-FOUR | 两个可承接单位+两个后排（按已解锁名单组队） | 多承接容量与多目标锁定 |
| P-SUMMON | 死灵法师+已允许的其他角色+召唤物 | 召唤物死亡/新出现改变合法候选和接敌 |

数字“3”是**TEST_ONLY**：不修改正式职业Capacity平衡。

## 2. T01｜8只普通近战：容量与队员入场

**配置：** 8×M01，房间合法分布，不将8只堆在入口接触点。**角色：** P-SOLO-FRONT、P-SOLO-RANGED、P-PAIR、P-FOUR；对照容量2/3/4。

**步骤与预期：**

1. 小队开始入场，检查已部署的AI延迟与入场散开；延迟期不得突然在门口全体夹住队伍。
2. 当敌AI激活且只有容量3前排可被合法索敌，允许3个正常容量预约、其他为合法临时溢出（实际分配受可达/发现/动作边界影响）。所有能合法行动的怪不应无故待机。
3. 后排成为合法候选后，仅在既有安全行动边界促使需重评的Overflow怪重新选择；既有Normal稳定，不把所有怪强制洗牌。
4. 后排基础容量0，**可以有多只怪同时锁定**；不按“后排至多1只”或平均人数分摊。
5. 增加前排容量、保持其它因素一致，正常容量预约的潜在可承载量提高；不能把容量成长做成触发反常的大规模抖动。
6. 结束、队员死亡或重进房间，预约全部释放，不存在幽灵TargetId。

**核心断言：** `normalReservations(target) <= actualCapacity(target)`（容量临时下降期间按合法安全修正规则）；每只近战普通预约至多1份；容量0单位可被锁定；固定seed一致输出相同。另测仅剩容量0角色时不死锁。

## 3. T02｜12只快速怪：散开、堵门与退让回归

**配置：** 12×M02，分布式入场/分布，不用人为指定可引发拥堵的同坐标出生。**角色：** P-PAIR、P-FOUR、P-SOLO-RANGED。

**步骤与预期：**

1. 小队完成其现行入场展开，敌人按现行激活延迟开始索敌；视觉上入口不会形成持续卡死的“堵门块”。
2. M02 **与M01共用接敌规则**，只有速度/基础属性不同。容量超额后漏怪可逼近后排。
3. 远程角色被近战实际命中后，若已有V0.1退让且满足条件，短距离后撤；若未实现，记录为依赖`BLOCKED`，**不能在本包新增第二套退让AI**。
4. 保证退让目标不越过房间边界/入口保护区；怪物原目标锁定不能因为退让自动换人；CD内不持续后退。
5. 固定seed与FPS变化不得引起Core数值/索敌结果改变，画面仍可允许视觉插值差异。

**核心断言：** 不靠RigidBody推开队员；无永久相互卡住/逃出房间/无穷重新索敌；怪物不因高速跳过容限与攻击判定。

## 4. T03｜3只重型近战：物理承伤

**配置：** 3×M03。**角色：** P-SOLO-FRONT、P-PAIR、P-FOUR。

**步骤与预期：**

1. 重型怪使用M01索敌，普通攻击节奏慢但完整执行。
2. 比较有无被动护甲/格挡/团队恢复时的承伤与房间剩余HP，记录击中、暴击、格挡。
3. 如果现行工程仍是减法护甲，按P0-1单独标记`FORMULA_MIGRATION_PENDING`，不在本包纠正公式；调平结论必须注明用的实际版本。

**核心断言：** 伤害只由已有唯一伤害管线结算，不因不同怪物行为写第二套护甲规则。

## 5. T04｜4近战＋4普通射手：远程AI和范围施法变体

**标准：** 4×M01+4×M04。**变体T04-C（同一房间切换配置，不新增第9房）：** 4×M01+2×M04+2×M05。**角色：** P-PAIR、P-FOUR。

**步骤与预期：**

1. 所有M04选择最近合法目标；当前普通射程内站定射击，不不断后撤风筝。
2. 远程攻击不预占近战Capacity；M01仍遵循容量。
3. 投射物保留已有墙体、合法攻击线和1D连续命中；视觉Y错位不得制造合法性的假象。
4. T04-C验证M05基本远程索敌+合法AOE，不因一次技能特别选择就永久覆盖其普通TargetLock。

**核心断言：** `rangedEngagementReservations == 0`；射手原目标失效后正常改选；投射物无穿墙和失控重定向。

## 6. T05｜6近战＋2后排猎手：显式特殊TargetPolicy

**配置：** 6×M01+2×M06。**角色：** P-PAIR、P-FOUR。

**步骤与预期：**

1. M01正常被前排承接或溢出；M06在合法候选中按`BacklinePriority`显式策略优先后排。
2. M06只能通过现有合法移动/技能路径接近，不可穿墙或无限距离突进。
3. 玩家嘲讽/拦截（如果已经实现）能让指定数量M06短时进入Forced，过期在安全边界恢复选敌。
4. 远程目标退让不隐式改变M06锁定；无退让实现时不假装验收通过。

**核心断言：** M06和M02逻辑可从诊断中明确区分，受控后目标释放不泄漏；普通M01不会一起突然点名后排。

## 7. T06｜4近战＋1召唤巫师：召唤、防刷、完成条件

**配置：** 4×M01+1×M07；M07技能测试生成M01或M02，单召唤者存活上限为**TEST_ONLY可配置小值**。**角色：** P-FOUR、P-SUMMON。

**步骤与预期：**

1. M07召唤成功前检查活动区域、上限、Skill CD和合法位置。
2. 召唤物出现后持有来源身份、可攻击/死亡/正常AI；不会引入第二套MonsterRuntime。
3. 召唤物死亡释放对应接敌与目标引用；奖励按现行规则审计，缺少资格合同时必须审批（不能自动设置正式收益）。
4. 连续召唤、召唤者死亡、残留召唤单位与房间完成状态要产生**有限终止结果**，不允许无穷Spawn阻止通关。
5. 如果使用“复活”变体，必须用已批准尸体来源/唯一消费规则；否则标记复活变体BLOCKED，不创建专用第二尸体库。

**核心断言：** 同一召唤实体只死亡/奖励一次；满上限不产生额外单位；不存在无限刷金币/EXP/掉落路径；房间完成规则结果与已有Encounter合同相符。

## 8. T07｜4近战＋1支援巫师：Buff来源与清理

**配置：** 4×M01+1×M08；提供一个隔离测试用合法`Modifier` Buff（不锁正式数值）。**角色：** P-PAIR、P-FOUR。

**步骤与预期：**

1. M08对合法友军施加有视觉标记的强化；目标没有资格时不得不断空放技能。
2. 标记强化来源、Buff生效时间、目标属性快照Dirty更新。
3. M08死亡或出范围时，区分持续源光环和独立施放的定时Buff，按照现有Buff合同清除/到期；不无条件即时删掉所有Buff。
4. 相同来源重复施加遵循G01/G02，不重复永久叠加。

**核心断言：** 没有永久悬空Buff来源；伤害只结算一次；玩家没有手动集火支援者也能够完成或明确表现压力差异。

## 9. T08｜Boss＋近战小怪：特殊技能与基础索敌分离

**配置：** 1个当前真实工程现成Boss或显式`TEST_ONLY`代理＋若干M01（测试值建议4）；**不在此专项创建完整Boss系统**。**角色：** P-FOUR。

**步骤与预期：**

# 04｜配置结构、类型校验和既有模块映射

## 0. 本包的数据不是生产Schema

`data/*.csv`、`*.json` 是**TEST_ONLY配置语义与静态合同样例**，为了帮助 Claude Code 理解M01–M08/T01–T08并评估现有CSV/JSON/Resource；**不能直接复制到工程生产配置表**。字段名称不是对C# API的授权。Claude Code先输出“原工程字段→本包语义→差异”映射，并用项目已有加载/验证器校验。允许用户审批后做最小增量列/效果定义。

## 1. 数据责任归属

| 数据 | 推荐现有归属 | 不允许的行为 |
|---|---|---|
| 怪物基础属性 | 项目当前 FightAttr/monster基础CSV、等级难度计算 | 不用测试数值覆盖生产怪物模板 |
| 行为与AI目标策略 | 已有MonsterPolicy/AI决策配置 | 不写第二套目标管理器或敌人专属Tick |

| 刷怪组合/房间完成 | 已有Area/Encounter/Room场景配置 | 不另建强行凌驾原完成规则的新Director |
| 测试用场景 | `Game.Core.Tests` fixture、可选Godot开发测试场景 | 不无审核修改第一至第五章正式地牢 |

| 观测 | 当前调试输出/测试桩 | 不把Debug信息作为玩家永久存档真值 |

## 2. Monster Profile 示例语义

`data/monster_archetypes_TEST_ONLY.csv` 每行一个原型ID，包含：

- `behavior_base`：`Melee/Ranged/Flanker`只是逻辑语义，真实类名由审计映射。
- `target_policy_semantic`：近战容量优先、远程最近合法、后排优先等。
- `attack_mode_semantic`：普通攻击的近/远程，用于决定是否占容量。
- `move_semantic`：近身、保持射程、特殊后排趋近；不代表真实坐标算法。
- `skill_semantic`：对应现有Skill/Effect的行为键值，不是新增程序集名称。
- `trait_semantic`：Swarm/Bruiser/Caster/Summoner/Support作为组合功能标签。
- `reward_semantic`：正常生成与召唤子单位的奖励资格须依工程合同校验。
- `ai_activation_semantic`：默认 **`PROJECT_EXISTING_DELAY`**，绝不写一个全局固定秒数。

审计后必须确认怪物普通近战能同时带“主目标锁定”与“特殊技能临时目标”；只读报告中明确现有数据是否足以表示M06。

## 3. Encounter Profile 示例语义

`data/encounters_TEST_ONLY.csv` 用于测试房间总览；`data/encounter_members_TEST_ONLY.csv` 用于逐行展开原型/数量；避免把怪群CSV列表塞进一个包含复杂嵌套JSON的CSV字段。真正生产中若已有更适合的Room Resource，优先复用。

- `T04C` 是**T04的替换配置变体，不算新增第九个基础房间**。
- `T08` 的Boss为 `EXISTING_BOSS_OR_EXPLICIT_TEST_PROXY`，不假装真实Boss技能存在。
- `activation_profile=PROJECT_EXISTING` 与 `party_entry_profile=PROJECT_EXISTING`，两者完全复用当前工程。
- `completion_profile=PROJECT_EXISTING`，若测试发现召唤导致不可完成，则进入X07审批，不擅改完成规则。
- `reward_profile=TEST_DISABLED_OR_ISOLATED`是**测试隔离手段**，不是生产掉落政策。测试房间不向真实账号金币/经验/背包发放收益。
- 相对生成位置用`near_far_spread`等测试标记；实际空间坐标只能在审计确认房间合法边界之后生成。

## 4. 原型复用与运行时接口建议（不是强制创建接口）

```text

  → Existing Room Loader / Spawn Procedure
  → Existing Monster Actor/Entity + Current AI Policy
```

4. 为什么没有第二份并行真值；
5. 需要用户批准哪一项。

## 5. 禁止默认承诺的内容

- 不能默认8种原型都已有对应的模型/动画/音效。缺素材可以用**现有合法占位**测试视觉，明确标`VISUAL_PLACEHOLDER`。
