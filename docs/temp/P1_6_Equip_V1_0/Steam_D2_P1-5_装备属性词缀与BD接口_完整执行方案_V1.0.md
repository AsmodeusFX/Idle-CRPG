# 02｜装备、词缀、实例与装备资格设计

## 1. 四层数据（已有 S3/S4 合同优先）

```text
ItemDefinition          静态模板：Stable ID / ItemType / allowed slot / tags / 可掉落线索
AffixDefinition         静态词缀模板：允许来源、能力类别、roll规则、合法引用（候选）
ItemInstance            开箱成功后固定：InstanceId + ItemDefinitionRef + 每条词缀实际roll结果
CharacterEquipment      角色→槽位→ItemInstanceId；有效效果全部派生，不复制权威装备
```

**不允许**将开箱后已确定的词缀重新 RNG、穿戴时再滚词缀、将 ItemDefinition 范围当作实例值，或在战斗运行时以物品显示文字推断生效属性。

一个实例词缀应能固化其 `AffixDefinitionRef`、roll值及必要的配置版本语义；具体 DTO 是否显式存快照/模板版本、未来平衡改表后旧装备随表变化还是按生成时参数固化，**TBD-01，需要审批**。最小不变量是同一 ItemInstance 在装备/卸装/保存/读取后效果无非预期变化。

## 2. 词缀作用类型（通道而非新公式）

| 类别 | 数据责任 | 已批准基础 / 提案 |
|---|---|---|
| 基础属性 Flat/Pct | 合法 `attr_id`、operation 和固化数值 → AttributeModifier | S4已批准输入与来源；正式词缀池 PROPOSAL |
| 技能数值修饰 | 有限技能系数/范围/CD 等 → 既有 SkillModifier | 架构已确认；具体装备可修项 PROPOSAL |
| 技能行为修饰 | 额外弹道、穿透、弹射等 → 已有有限 SkillModifier+Effect 扩展 | 可配置能力方向已确认，正式组合与上限 TBD |
| 条件增伤威能 | 满足条件时贡献既有 M_power 池 | **不得建第5个常规增伤池**；实际效果和触发条件待批准 |
| 事件触发威能 | 合法击中/击杀/格挡后产生既有 Effect / Buff | G03/G06 基线已确认；每条概率、次数、ICD TBD |
| 召唤专属强化 | 召唤技能成长、单位属性/上限/继承规则 | 复用 Summon + SkillModifier + AttributeModifier；具体投放 TBD |

同一件装备可以有不同词缀通道，但每条效果**仅通过一个确定的归属入口**生效；装备具备什么词条和能否同时存在，取决于之后批准的合法 affix pools。

## 3. 词缀资格与生成（建议结构，不锁正式经济）

- `EquipmentTags` 决定允许装备类型；`AffixTags` 决定词缀能出现在哪类物品上；`ClassSkillTags` 约束技能专属词缀归属。实际 tag ID 必须沿用工程现有 ID 命名。
- `ExclusionGroup` 可限制前后缀中不该同时出现的冲突词条；但正式「前缀/后缀」池、同一件最大条数、稀有度、稀有词缀权重 **全部 TBD**。
- 不对历史物品批量新增随机词缀。旧存档迁移需显式方案；缺失定义或未知操作必须显示错误并拒绝无声清空。
- `ItemLevel`、怪物等级、难度、ChestType 与词缀池如何对应为提案，不允许暗定装备数值曲线。
- 同一个试验物品装备在两个角色身上会被 S4 唯一归属拒绝；不因新增 BD 效果绕过。

## 4. 装备部位与职业门槛（不可偷定）

- 目前**唯一已确认且可据此写准出测试**的是 S4 TEST_ONLY `Weapon + Armor` 两槽。**正式**头盔、胸甲、戒指、项链、饰品、双手武器、副手、套装件数均未获批准。
- 游侠只使用弓箭武器，不保留标枪/长矛或战斗中自动换武器；是否允许弩属于待定，**不得自行将弩当作弓**。
- 其他四职业可用武器类型、等级需求、职业专属装备类型都属于正式装备化阶段待审批内容，不能依据 D2 情怀擅自实现。
- 装备词缀影响的是拥有者或符合规则的召唤物；物品在背包中但未装备时不应贡献战斗 Modifier 或 Proc。

## 5. 装备操作的完全生命周期

```text
OpenChest 成功→单个新的权威 ItemInstance（随机属性已经固化）
Equip→GameSession 校验实例/部位/角色→安全边界完整应用来源
  ├─ AttributeModifier：Source=ItemInstanceId
  ├─ SkillModifier：Source=ItemInstanceId+AffixToken
  └─ Trigger/Proc listener：Source=ItemInstanceId+AffixToken
Replace/Unequip→同一边界整体撤销旧来源、注册新来源，确保不半应用
Save→保存权威 ItemInstance+槽位引用+必要随机状态
Load→先校验版本/引用/来源唯一性，再**重新构建派生效果**（只一次）
```

不得以客户端 Godot 动画、UI 字段或固定数值代替 Core 权威效果。非法命令/重复命令都不能造成叠加、重复注册或物品克隆。

# 03｜装备 Modifier / SkillModifier / Power / Proc 唯一归属

## 1. DMG 官方合同：4+1，不允许简化覆盖

`DAMAGE_FORMULA.md` 的固定常规增伤因子：

- `M_skill`：技能系数／技能乘区（按已存在公式定义）。
- `M_general`：通用百分比增伤池（全伤、技能增伤、物理/元素增伤、合法条件通用增伤等同类加算）。
- `M_power`：满足条件时**数值型装备威能**增伤池。
- `M_vulnerable`：易伤增伤池。
- `M_critical`：仅 DMG2 判定为暴击时适用的独立暴击事件因子。

**池内加算、固定池间乘算**，护甲/抗性/格挡是防御而非隐藏池。每条词缀必须指定 `DamageContributionCategory`，普通「装备+火伤%」归 `M_general`，不会只因来自装备而进入 `M_power`。改变技能系数本身（如火球系数 +0.2）归入对应技能系数，不再另加 `M_general`。

护甲已确认：`DR=Armor/(Armor+K(攻击者等级))`，但 `K(L)`正式配置须审批，绝不通过 P1-5 本包创建默认值。元素抗性直接百分比，负抗允许，上下限 TBD。

## 2. SkillModifier 的范围

- 支持引用已有技能定义和已有标准 Effect 类型，不生成任意脚本或一个装备专属技能引擎。
- Skill 的最终有效规格 = 不可变 SkillDefinition + 当前合法技能点/被动/装备 SkillModifier → 有效 SkillSpec；在合法安全边界更新 Dirty/版本。
- 可修饰内容例：火球数量+1、多重箭分支、连锁弹跳+1、旋风攻击范围调整、召唤物数量上限+1、特定技能 CD 修正（在已批准上限内）。**均为候选词条，不是自动允许任意值无限叠加。**
- 禁止通过装备直接修改独立的 Godot Projectile 节点生成数量，而 Core SkillSpec 不知情。
- SkillSlot 的数量、已装备技能/已学技能、前置条件依现有技能树规范；**装备不能隐式授予免费技能槽**。
- 装备是否允许「技能尚未学会即可提供技能等级或直接授予技能」是 **TBD-02**，禁止偷偷实现。
- 通用全局 CDR FightAttr 可能在历史 Schema 里存在，但当前玩法决定为**首版不广泛投放全局 CDR**；首批装备仅考虑特定技能修饰，不能因为字段存在而投全局 CDR。

## 3. Proc 来源与判定

事件链：`Skill/Cast → Hit/Damage/Kill 等合法 fact → TriggerRule (资格/频率) → EffectQueue → Effect → DMG1/DMG2/DMG3`。

- `ProcEligibleHit` 不等于每个视觉碰撞；DoT、地面 Tick 默认不算普通击中资格，特例需配置。
- 每条词缀自有 TriggerRule：`Event`、`SourceFilter`、`TargetFilter`、`Chance`、`InternalCooldown`、`MaxPerCast`、`MaxPerTarget`、`CanTriggerFromProc` 等**语义维度**；实际 Schema 必须先读代码，不强制全部新建字段。
- 默认为：**Proc 产生的额外伤害不自动再次触发同类 Proc**。只有显式批准的有界连锁可继续派生，并遵循 G06 链深、总次数、重复目标约束。
- 持续效果/光环/诅咒遵循 G01/G02：相同来源不重复注册，同类可选择刷新/取强；不同光环、不同主要诅咒可共存。
- `OnKill` 由唯一死亡事实提供；多伤害同时致死只发放一次金币/宝箱/经验，不以 Godot 粒子回调触发奖励。
- 内置 CD、触发上限及 ProcChance 不锁正式数值；`data/` 样例均 TEST_ONLY。

## 4. 装备来源与角色、召唤物

- 装备的独立 Source 身份建议是 `ItemInstanceId + AffixOccurrenceIndex`（概念，不强制接口字段），保证两件同名装备、同一件装备多条重复名字词缀也能分别注册和完整撤销。
- 主人临时 Aura/Buff 不默认进入召唤继承基数，避免圣骑狂热经主人快照+召唤物直接受光环而双计；召唤本体仍可依 Aura 资格正常受益。
- 推荐继承输入来自基础成长与合法的**装备/永久成长来源**，而非当前所有运行时状态；具体「召唤已存在时更换装备，是否重新算继承属性」未批准，属 **TBD-03**。
- 玩家更换召唤专属装备时：技能有效数量上限若下降，超出数量的存活召唤物如何处理 **TBD-04**；**不允许默认直接杀死、永久保留或变成隐藏容量**。
- 召唤物由主人关联击杀，但已部署队员按原已确认经验规则共同获得击杀 EXP（包括已阵亡但仍部署者）。召唤物被杀不产生可刷奖励/可消费尸体（除明确批准例外）。

## 5. 高频弹道 / 触发条款

| 技能 | 危险点 | 必要测试 |
|---|---|---|
| 游侠多重箭/穿透 | 同次多箭贴身对同一目标爆发、附魔每箭无限触发 | 同 Cast/Target 命中去重和 Trigger 界限 |
| 野蛮人旋风 | 高频命中大规模 Proc | 合法真实伤害保留、Proc ICD 生效 |
| 法师充能弹/暴风雪 | 多投射物或 DoT 按命中滥发威能 | Hit vs DotTick 区分 |
| 死灵尸爆 | 击杀→尸体→爆炸→击杀递归 | 尸体唯一消费、链深/总事件上限 |
| 圣骑多光环+死灵多诅咒 | 来源注册次数和乘区重复 | 取强/刷新、不同合法状态共存、M 组内加算 |

## 6. 不得悄悄做出的设计决定

- 固定数值、总 CDR 上限、全套装备词缀数、道具品质、正式掉率。
- 技能被装备提升上限突破、冲突词缀互斥/套装套数、负数属性、物理穿透等新计算类别。
- `OnEquip` 触发永久效果或叠加不随卸装删除的 Buff。
- 装备一物品跨角色重复生效、词缀独立于物品可交易等新资产规则。

# 04｜Loot → OpenChest → ItemInstance → Equip → Save/Load 全链路

## A. 正式已批准流程，绝不重建

```text
BattleSimulation 唯一 KillFact
  → GameSession / Loot 判定是否掉宝箱（判定仅一次）
  → ChestInstance 进入有限 ChestStorage
      └─ 满仓时「战斗继续，额外宝箱丢失且不补发」
  → 玩家明确手动 OpenChest
  → 验证箱资格/物品奖励配置，使用确定性 RNG 准备奖励与词缀实际结果
  → 成功提交：原子地消费箱、将固化属性的新 ItemInstance 加入唯一权威池
  → Equip/Replace/Unequip 在合法 Core 安全边界原子更新槽位引用与来源
  → Save 保存 ItemInstance 已确定数据 + Slot→ItemId + 必要 Ledger/RNG/版本
  → 新进程 Load 验证引用并重建 Modifier/SkillModifier/Trigger listener
```

- 本轮扩展的“装备词缀抽取”只能属于 OpenChest 原子事务内的**装备实例准备阶段**。`ChestInstance` 不应提前持有正式已掷好的随机装备实例，除非未来单独批准新的奖励锁定时点。
- 生成失败不扣箱、不新增 ItemInstance，不能用重复错误操作重抽出好结果。可依现有 RNG 回滚、单次候选流水等 S3 已有设计实现；具体事务技术先审计，不自选正式随机策略。
- 复演 `TEST_ONLY` 战斗不得向真实玩家背包发奖；同一合法新战斗可再次获得新宝箱，不应被旧 KillFact Ledger 阻断。

## B. 随机词缀生成：建议最小结构

`ItemDefinition` / `AffixPool` / `RollPolicy` / `ItemInstanceAffix` 是语义名称，实际工程如已有等价类型**必须复用**。

1. 获取本次开箱奖品的合法 ItemDefinition、奖励可用池及已有上下文（宝箱类型、章节、难度等）。**具体池选择/难度权重 TBD**。
2. 校验权重表、适用 ItemTags、职业或技能标签、排他组、允许数量；未知模板/字段/非法概率报错，不以空词缀静默回退。
3. 在同一次合法 OpenChest 的受控 RNG 中生成所选词缀及各自实际数值。
4. 成功提交时，固化所有已抽出的词缀 ID、值、引用；之后穿戴/换装/重启不再掷骰。
5. 展示层仅渲染固化内容，不由 UI 计算正式装备属性。

**强约束**：`data/` 的测试池“允许一个武器/一个防具，每件至多若干测试词条”只为演示。正式品质（普通/魔法/稀有/传奇/套装）、前后缀分布、词缀个数、权重、总掉率均属 **TBD-05**。

## C. 随机的可复现性与反刷

- 两次独立合法开箱允许不同结果；相同测试 Profile + RNG + 业务命令次序应复现一致的生成结果。
- 相同箱重复点击第二次不生成物品；开箱失败/回滚不能产生新的免费抽奖机会。
- 同一 ItemInstance 重复 Equip/Unequip/Load 不改变已经生成的 affix rolls。
- 使用新版本 AffixDefinition 时旧已生成实例的兼容策略、被移除词缀引用、版本缺失时的错误策略需在修改 Save DTO 前经审批。

## D. 战斗中换装边界

S4 已确认：战斗中可换装，但必须在**确定性安全边界**生效，且整套旧/新来源一次切换，不打断 Action、不重启技能 CD、不追溯已受理 DamageRequest。

以下在 S4 仍待定，P1-5 **不得替 S4 偷定**：

- 当前 Tick 还是下一 Tick / 具体 phase 应用装备请求；多命令先后。
- Windup 期间换装，后续 Commit 是新还是旧攻击属性。
- 已发射尚未命中的 Projectile 的伤害快照时点。
- 有效 Buff/Proc/召唤 SkillSpec 是否立即重建或等待什么安全边界。
- 正在触发的 Proc 的来源装备在同 Tick 已卸下时，取消还是完成既有已入队 Effect。

遇到这些案例必须输出 **局部冲突 + 不同备选 + 对存档/回归影响**，先实现无争议路径，不编造默认行为。

## E. 恢复后注册恰好一次

- 保存权威 `ItemInstance` 固化结果和 `CharacterEquipment` 引用；Derived FightAttr、EffectiveSkillSpec、Proc listener 的运行时对象**不得作为第二份可编辑真值**。
- 读档先检查：实例存在、槽位类型合法、同一 ItemInstance 不在两个槽/两个角色重复占用、词缀定义引用存在、roll 数据合法。
- 只读加载失败必须可见地报错；不能把坏数据当作空白新档，自动丢失玩家物品。
- 成功读档后建立正确的 AttributeModifier/SkillModifier/TriggerRule Source；反复重建不双重注册。
- 真正验收需要**保存磁盘→退出原进程→新进程启动→加载→确认装备与战斗一致**。

## F. 示例配置不能污染生产

所有 `TEST_` 示例都不应与生产 drop tables、正式 ItemDefinition 或存档迁移工具共用同一发布环境。用 Game.Core.Tests 的隔离 Profile 注入，不借 Godot Inspector 直接改全局正式设置。

# 05｜五职业装备 BD 候选能力与验收导向

> 本文是**BD 方向与技术接口实例**，并非已审批掉率、唯一装备清单、正式词缀池。所有示例以不破坏已有职业特色为原则。

## 1. 职业专属方向

| 职业 | 候选装备词缀/威能 | 接口 | 必须防止 |
|---|---|---|---|
| 野蛮人 | 旋风作用范围、战吼有效范围、有限接敌容量提升、格挡后反击 | SkillModifier/AttributeModifier/TriggerRule | 旋风自动额外接敌；无上限嘲讽；格挡每次无限 Proc |
| 圣骑士 | 光环范围、祈祷恢复、盾击硬直、狂热强化、信念减抗 | SkillModifier/Buff Modifier/Effect | **多光环被误设互斥**、多角色重复同 Aura 叠加、减抗乘区重复 |
| 法师 | 火球额外弹道、冰霜新星范围、连锁闪电弹跳、单技能 CD | SkillModifier/Effect | 高频 Hit 每跳完整 Proc、冻结 Boss 常驻、全局CDR过量 |
| 死灵法师 | 骷髅数量/生命、石魔接敌、尸爆半径、诅咒覆盖 | SummonSpec/SkillModifier/AttributeModifier | 召唤永久免费回满、尸体重复消费、多诅咒被强制互斥 |
| 游侠 | 多重箭散射、穿透、炮轰频率、导引箭追踪、女武神属性 | SkillModifier/Hit/Trigger/Summon | 误恢复标枪系、贴脸多箭无限同目标命中、远程基础退让变收费技能 |

游侠**仅使用弓箭**，不兼容历史标枪、长矛或近战充能一击方案。是否允许弩不由本轮推定。

## 2. 四种有辨识度的测试 BD（示例行为，不锁正式属性）

**BDE-01：多重穿透射手**：装备贡献多重箭+1弹道与一次穿透能力。必须能看到 Core 合法发射数改变、命中目标规则正确；同一释放对同一目标的重复命中/Proc 受控。

**BDE-02：火球爆裂**：装备增加额外火球或攻击击杀时合法派生爆炸。必须使用现有 SpawnProjectile / TriggerRule；额外爆炸不能无限自触发。

**BDE-03：圣骑+死灵联动**：多光环同时有效，每种占技能槽；两诅咒同一敌人共存；相同 Aura 同时来自两人不能无限堆叠；减抗通过同一元素抗性计算，不能再独立造成新增伤乘区。

**BDE-04：骷髅装备继承**：主人穿戴永久召唤物攻击加成，骷髅依约定继承；外部狂热光环独立生效一次，不能先进入主人继承值又给骷髅再加一次。

## 3. 装备词缀与长期成长职责

- 英雄升级 → 基础保障；技能点 → 机制与独立强化；装备 → 深度 BD 与可辨认的属性成长。这是已确认的分工。
- 不把“多重箭增加1箭”做成全局 fightattr 行；属于技能参数强化。
- 不把“物理伤害+10%”误写成 `M_power`，应依据语义进入普通通用增伤。
- 不直接为「升级技能装备」提供强制免费技能槽；主动技能仍受已解锁槽位限制。
- 受击退让是远程角色通用 AI，**不能通过专属装备或技能点才启用基础退让**；装备可在未来明确配置额外退让增益，但不是本轮默认词缀。

## 4. 装备阶梯与经济风险（尚未正式落地）

- 基础装备应让攻击/护甲/抗性可读；中期装备开始体现技能专属；后期稀有能力与条件触发 BD 提供显著差异。
- 但正式等级区间、品质层级、词缀生成分布、概率、通用与职业专属装备比例、套装、强化、镶嵌、交易、分解、掉落表均 **TBD**。
- 不得为了本包“看上去 D2 完整”将这些作为当前开发必须实现。

**依赖**：现有技能系统 SkillModifier 及有效技能规格缓存；不强制所有五职业技能已完成。

**范围**：优先 2–3 条行为明确、已实装技能可验的词缀（如多重箭合法额外弹道、火球技能系数或额外弹道、召唤类属性之一），从装备实例注册有限 SkillModifier；卸装撤销；技能未学会、未装备时的可用性由原技能规则决定。

**准出**：Core EffectiveSkillSpec 与表现一致，合法条件下改变技能行为；战斗中换装不破坏已受理动作；存档后重新注册一次；不产生新的伤害乘区；未实现的技能标 `BLOCKED` 或 `NOT_RUN`。

## E3：条件威能与 Proc

**依赖**：G01–G06 的实际 TriggerRule / EffectQueue 与事件因果链已被审计。

**范围**：至少一个直接合法命中触发（有 ICD/限次）和一个有界击杀效果（如合法爆炸）；支撑单目标重复击中、跨多人击杀、延迟投射物等回归。不得新增无限事件递归与重复 Loot。

**准出**：基础伤害与 Proc 伤害分别归档，Trigger eligible 与 damage hit 区分，M_power/M_general 等归属测试，来源卸装后没有悬空监听；旧已入队效果卸装并发的精准处理如果旧合同无定论，应阻塞并审批。

## E4：召唤装备继承与团队协同

**依赖**：召唤物、主动光环、多诅咒已真正完成或隔离测试夹具可用。

**范围**：合法主人基础/装备来源继承、外部 Aura 单次作用、合法召唤数量上限、跨房间存续与死亡；同步记录 TBD-03/04（存活召唤物在装备变化后的行为）。未批准前只做不触及这两个争议的快照测试。

**准出**：装备/召唤属性没有重复继承，怪物接敌容量统计正确，无无限召唤战损恢复和无限奖励/尸体；主人/召唤单位杀怪不重复发经验。

## E5：整体验收与清理

- `dotnet build`、`dotnet test Game.Core.Tests`（以工程实际命令为准），记录版本、日志和测试列表。

| EQ-08 | Unequip | 同一 Source 的 AttributeModifier 完整撤销 |
| EQ-09 | Replace | 旧来源撤销和新来源应用原子；不出现半状态 |
| EQ-10 | 跨角色重复装备 | 同一个实例不可能被两人共同装备 |
| EQ-11 | 词缀非法 attr/operation | 强类型校验错误，不静默丢字段 |

| EQ-13 | 护甲公式 | 固定合法 K(L) TEST_ONLY 时验证百分比递减，攻击者等级为 L |
| EQ-14 | 4+1乘区 | 技能、通用、威能、易伤各自组内加算，暴击独立，无额外池 |
| EQ-15 | 火伤普通词条 | 即使来自装备也进入 M_general，不进入 M_power |
| EQ-16 | SkillModifier 绑定 | 同装备上合法技能强化仅生效一次，卸装失效 |
| EQ-17 | 未学/未装主动技能 | 装备不偷偷提供免费技能槽/非法施放 |
| EQ-18 | 直接 Hit Proc | 按资格/概率/ICD/每 Cast 每 Target 限制 |
| EQ-19 | DoT Tick | 默认不是直接 Hit Proc 资格 |
| EQ-20 | Proc 派生伤害 | 默认不再次无界触发 Proc；允许链按配置有限结束 |
| EQ-21 | 唯一 Kill Fact | 爆炸连锁不重复金币/经验/宝箱 |
| EQ-22 | 死亡尸体 | 尸爆和复活只能一方消耗同一尸体 |
| EQ-23 | 双 Aura 单角色 | 两种已装备光环都生效，分别占槽 |
| EQ-24 | 双诅咒目标 | 不同主要诅咒合法共存，重复相同效果受叠加规则约束 |
| EQ-25 | 多召唤来源 | 外部 Aura 在召唤物上只生效一次，主人继承不双计 |
| EQ-26 | 召唤属性继承 | 合法主人基础/装备属性输入生效，明确版本和来源 |
| EQ-27 | 随装备临时变化的召唤 | 若 TBD-03/04 未批，只在不冲突案例验证，相关测试 BLOCKED |
| EQ-28 | Save 与 Load | 固化实例词缀/装备引用合法，重建派生来源且不重roll |
| EQ-29 | 连续重复 Load 重建 | 不二次注册 Effect/Buff/Trigger |
| EQ-30 | 装备时钟边界 | 无效命令不打断 Windup/Commit/Recovery，无既有 Damage 追溯 |

## 对照实验统计口径

- 装备 A/B：角色等级、基础装备、敌人及逻辑时间、Seed、技能点与怪物池尽量一致。只变化被验证的装备词缀。
- 记录：物品实例 ID、生成词缀与 roll 值、所有有效来源 ID、属性快照版本、SkillSpec、Trigger 资格/次数、被拒绝原因、Hit/Kill、DMG 四乘区+暴击、有效扣除 HP、TTK、死亡和异常。
- DPS 建议按**实际扣减 HP**计算，不以超杀溢出伤害冒充实际输出；多场随机路径不同要注明。
- 正式词缀“几率多少、增伤多少、掉落多少”均没有本轮准出阈值，属于后续 08 数值平衡任务。
