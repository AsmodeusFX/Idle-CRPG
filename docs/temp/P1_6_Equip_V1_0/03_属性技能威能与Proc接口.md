# 03｜装备 Modifier / SkillModifier / Power / Proc 唯一归属

## 1. DMG 官方合同：4+1，不允许简化覆盖

`DAMAGE_FORMULA.md` 的固定常规增伤因子：

- `M_skill`：技能系数／技能乘区（按已存在公式定义）。
- `M_general`：通用百分比增伤池（全伤、技能增伤、物理/元素增伤、合法条件通用增伤等同类加算）。
- `M_power`：满足条件时**数值型装备威能**增伤池。
- `M_vulnerable`：易伤增伤池。
- `M_critical`：仅 DMG2 判定为暴击时适用的独立暴击事件因子。

**池内加算、固定池间乘算**，护甲/抗性/格挡是防御而非隐藏池。每条词缀必须指定 `DamageContributionCategory`，普通「装备+火伤%」归 `M_general`，不会只因来自装备而进入 `M_power`。改变技能系数本身（如火球系数 +0.2）归入对应技能系数，不再另加 `M_general`。

护甲已确认：`DR=Armor/(Armor+K(攻击者等级))`，但 `K(L)`正式配置须审批，绝不通过 P1-5 本包创建默认值。元素抗性直接百分比，负抗允许，上下限 TBD。

## 2. SkillModifier 的范围

- 支持引用已有技能定义和已有标准 Effect 类型，不生成任意脚本或一个装备专属技能引擎。
- Skill 的最终有效规格 = 不可变 SkillDefinition + 当前合法技能点/被动/装备 SkillModifier → 有效 SkillSpec；在合法安全边界更新 Dirty/版本。
- 可修饰内容例：火球数量+1、多重箭分支、连锁弹跳+1、旋风攻击范围调整、召唤物数量上限+1、特定技能 CD 修正（在已批准上限内）。**均为候选词条，不是自动允许任意值无限叠加。**
- 禁止通过装备直接修改独立的 Godot Projectile 节点生成数量，而 Core SkillSpec 不知情。
- SkillSlot 的数量、已装备技能/已学技能、前置条件依现有技能树规范；**装备不能隐式授予免费技能槽**。
- 装备是否允许「技能尚未学会即可提供技能等级或直接授予技能」是 **TBD-02**，禁止偷偷实现。
- 通用全局 CDR FightAttr 可能在历史 Schema 里存在，但当前玩法决定为**首版不广泛投放全局 CDR**；首批装备仅考虑特定技能修饰，不能因为字段存在而投全局 CDR。

## 3. Proc 来源与判定

事件链：`Skill/Cast → Hit/Damage/Kill 等合法 fact → TriggerRule (资格/频率) → EffectQueue → Effect → DMG1/DMG2/DMG3`。

- `ProcEligibleHit` 不等于每个视觉碰撞；DoT、地面 Tick 默认不算普通击中资格，特例需配置。
- 每条词缀自有 TriggerRule：`Event`、`SourceFilter`、`TargetFilter`、`Chance`、`InternalCooldown`、`MaxPerCast`、`MaxPerTarget`、`CanTriggerFromProc` 等**语义维度**；实际 Schema 必须先读代码，不强制全部新建字段。
- 默认为：**Proc 产生的额外伤害不自动再次触发同类 Proc**。只有显式批准的有界连锁可继续派生，并遵循 G06 链深、总次数、重复目标约束。
- 持续效果/光环/诅咒遵循 G01/G02：相同来源不重复注册，同类可选择刷新/取强；不同光环、不同主要诅咒可共存。
- `OnKill` 由唯一死亡事实提供；多伤害同时致死只发放一次金币/宝箱/经验，不以 Godot 粒子回调触发奖励。
- 内置 CD、触发上限及 ProcChance 不锁正式数值；`data/` 样例均 TEST_ONLY。

## 4. 装备来源与角色、召唤物

- 装备的独立 Source 身份建议是 `ItemInstanceId + AffixOccurrenceIndex`（概念，不强制接口字段），保证两件同名装备、同一件装备多条重复名字词缀也能分别注册和完整撤销。
- 主人临时 Aura/Buff 不默认进入召唤继承基数，避免圣骑狂热经主人快照+召唤物直接受光环而双计；召唤本体仍可依 Aura 资格正常受益。
- 推荐继承输入来自基础成长与合法的**装备/永久成长来源**，而非当前所有运行时状态；具体「召唤已存在时更换装备，是否重新算继承属性」未批准，属 **TBD-03**。
- 玩家更换召唤专属装备时：技能有效数量上限若下降，超出数量的存活召唤物如何处理 **TBD-04**；**不允许默认直接杀死、永久保留或变成隐藏容量**。
- 召唤物由主人关联击杀，但已部署队员按原已确认经验规则共同获得击杀 EXP（包括已阵亡但仍部署者）。召唤物被杀不产生可刷奖励/可消费尸体（除明确批准例外）。

## 5. 高频弹道 / 触发条款

| 技能 | 危险点 | 必要测试 |
|---|---|---|
| 游侠多重箭/穿透 | 同次多箭贴身对同一目标爆发、附魔每箭无限触发 | 同 Cast/Target 命中去重和 Trigger 界限 |
| 野蛮人旋风 | 高频命中大规模 Proc | 合法真实伤害保留、Proc ICD 生效 |
| 法师充能弹/暴风雪 | 多投射物或 DoT 按命中滥发威能 | Hit vs DotTick 区分 |
| 死灵尸爆 | 击杀→尸体→爆炸→击杀递归 | 尸体唯一消费、链深/总事件上限 |
| 圣骑多光环+死灵多诅咒 | 来源注册次数和乘区重复 | 取强/刷新、不同合法状态共存、M 组内加算 |

## 6. 不得悄悄做出的设计决定

- 固定数值、总 CDR 上限、全套装备词缀数、道具品质、正式掉率。
- 技能被装备提升上限突破、冲突词缀互斥/套装套数、负数属性、物理穿透等新计算类别。
- `OnEquip` 触发永久效果或叠加不随卸装删除的 Buff。
- 装备一物品跨角色重复生效、词缀独立于物品可交易等新资产规则。
