# 09｜P0-1 护甲固定减法→递减百分比：独立执行补遗 V1.0

> 这份补遗填补原主Todo始终未核实交付的**独立护甲改造执行规范**。它不是“护甲已经改好”的报告。全部实际行为由用户本地Godot源码审计确认。

## A. 已批准业务合同

- 物理护甲使用递减百分比减伤：`DR=Armor/(Armor + K(L))`，其中 **L为攻击者等级**；物理伤害`D_postArmor = D_preArmor * (1 - DR)`。
- `K(L)` 应可配置为明确等级曲线，最终生产值与定义由用户审批。
- 角色、怪物与召唤统一物理护甲规则；元素伤害按各元素抗性，不被Armor二次削减；五伤害类型不新增魔法/真实绕过。
- 4常规增伤乘区`M_skill/M_general/M_power/M_vulnerable` + 独立暴击`M_critical`，不因护甲迁移改组/增删。
- DMG2事件（闪避/暴击/格挡/击中/击杀）与DMG3数值结算保留现有权威流程，不另建DamageCalculator。
- 玩家已明确不使用固定减法Armor作为正式物理减伤模型；当前源码仍可能有减法分支必须通过审计证实。

## B. Q0必须只读审计

搜索`Armor`, `Damage`, `Physical`, `Resistance`, `Hit`, `Block`, `Crit`等的**实际C#代码引用与配置**；定位 Hero、Monster、Summon、装备Buff影响护甲、快照版本、UI的战斗详情与旧单元测试。

列出每条计算路径；确定：是否先减法后百分比、是否存在怪物特殊旁路、如何处理负Armor、K为0、等级0或超出曲线、逐击取整和最小伤害。**这些边界未获批不得偷偷选择。** 若原先确已使用正确百分比模型，仅补差异测试，不重复修改。

## C. 正式与TEST_ONLY的分界

单元测试可以注入`K=100`、`Armor=100`、`RawPhysical=100`作为**代数验证夹具**，预期减伤50%、剩余50；这绝不意味着等级1或任意等级生产 `K(L)=100`。

对于`Armor=0`、`K>0`物理减伤应为0；`Armor>0,K>0`时`0<DR<1`，随Armor增大DR递增但收益递减（相同K下）。`Armor=100,K=100`时`DR=0.5`。对攻击者等级L增加导致K变大一事，**必须在审批正式曲线后才断言全区间单调**。

## D. 向Claude请求的具体方案

1. 提交最小替换位置：现行伤害管线已有的物理减伤步骤；任何公式复制分支必须提出清理方案。
2. 给两至三套可配置 `K(L)` 候选曲线及覆盖低/中/高等级怪物伤害的对照，不锁正式数值；同时提供越级/低级刷怪跨级曲线的变形风险。
3. 要求用户批准：`K(L)`曲线、异常等级/护甲处理、逐击取整、旧存档/旧配置迁移策略、UI面板说明。
4. 批准后只修改被审计证实的最小伤害环节与配置加载/校验；删除授权废弃的减法公式来源，不留下两个结果或额外伤害乘区。
5. Core测试覆盖：Hero→Monster、Monster→Hero、Summon→Monster、元素护甲隔离、Crit/Block、穿戴装备护甲、负抗、异常K、确定性复演、跨进程存档读取。
6. Godot/Mini录屏：同一护甲值、同一Raw物理输入，显示的HP扣减与Core一致；同样场景两攻击者等级的差异与已批准曲线一致。
