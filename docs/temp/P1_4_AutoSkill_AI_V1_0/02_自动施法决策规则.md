# 02｜P1-4 自动施法决策合同 V1.0

## 0. 决策层级与状态标签

- **[C 已确认]**：来自 2026-10-15 Battle AI/S2 与后续用户确认，必须保持一致。
- **[R 推荐]**：本包提供的最小具体方案，若当前代码没有等价实现，G0 审计后取得用户批准才新增。
- **[T 待定]**：参数、精确排序、失败成本、对象语义，不能随意写正式默认配置；TEST_ONLY 场景允许注入明确值。

当前唯一目标：**在已有 Game.Core PlayerPolicy 的合法决策窗口，为已装备技能选出合适的 CastSkill 意图；否则回到 BasicAttack / Move / Wait**。不开发自定义策略编辑器、行为树或不稳定“智能评分器”。

## 1. 核心职责和权威边界 [C]

```text
Player chosen: 已学技能+已装备技能槽(1→5)
      + 已存在 AI/Skill/Buff 配置(只读)
                         │
Core Fixed Tick ─ Action/SkillRuntime 判定 CanDecide（单活动动作）
                         │
PlayerPolicy 读取主TargetLock/战场/有效技能快照
       ├── 状态与权限预筛
       ├── 候选技能的CastCondition
       ├── 技能专属临时TargetPolicy（不覆盖主TargetLock）
       ├── Priority确定性排序
       └── ActionRequest.CastSkill / BasicAttack / Move / Wait
                         │
Action/SkillRuntime 唯一权威复核 → Windup→Commit→Recovery
                         │                           │
                     拒绝理由                  Effect、CD(Commit)
                         └── 事实反馈、状态重评标记（禁止回调递归决策）
```

AI 不能直接申请 Damage/Heal/Buff、修CD、改装备、改主锁定、切Area、自动开箱；负责伤害公式的是 DMG 体系。玩家自行决定装备哪些技能；AI不能自行加点、换技能或占更多槽。

## 2. 首先排除“根本不允许决策”的状态 [C]

| 条件 | 处理 | 禁止行为 |
|---|---|---|
| Actor死/无有效战斗上下文 | 无新的Cast/BasicAttack | 死亡单位仍放技能 |
| Action忙于Windup/Commit/Recovery | 等待现有动作结算；可标记待重评 | 抢占/重置动作 |
| 眩晕/冻结/沉默/控制限制 | 根据现有 Runtime 对动作分类的权限判断 | 由AI自创控制打断时序 |
| 小队入场散开阶段 | 沿用现有入场状态与敌 AI 延迟，按已实现合法窗口行动 | 恢复入口堵门 |
| 受击退让进行中 | 由现有移动/动作Runtime处理退让，到合法边界再决策 | AI同时发退让与施法命令 |
| 切房间/回城/换人 | 由 GameSession / Encounter / 队伍换人流程决定可行动状态 | AI擅自切区或复制召唤对象 |

**[T]** 实际“入场散开时角色能否放技能、怎样与敌人激活延迟衔接”以现有代码行为审计为准，不在此回退任何旧规则。

## 3. 主动技能候选合法性 [C + R]

| 检查顺序（建议） | 条件 | 不通过的处理 |
|---|---|---|
| 1 | 技能已学习、当前装备的有效槽、已解锁、技能ID可解析 | 跳过候选，记录原因；配置坏引用加载时报错 |
| 2 | 技能 Runtime Ready / CD完成，且行为类别允许 | 跳过；不修改CD |
| 3 | 对应施法者状态允许该类别动作 | 跳过；不直接解除控制 |
| 4 | 技能 CastCondition 成立（例如缺血/有近敌/召唤未满/未有效覆盖） | 跳过，不“为了CD”空放 |
| 5 | 技能 TargetPolicy 能找出合法技能目标/区域/位置（允许不需要敌人的自施法技能） | 跳过，记录 NO_VALID_SKILL_TARGET |
| 6 | 技能射程、合法站位、LoS与技能要求满足当前动作申请 | 不允许无视射程；下一动作如何移动见C01 |
| 7 | 优先级与平局稳定排序 | 选出一个 CastSkill 请求；Runtime再复核 |

任何一个条件通过只证明 **AI 可以尝试提出请求**；真正 Commit 仍归 Runtime。绝不能把“CD Ready”视作“可以绕过当前Recovery”。

## 4. 技能顺序与普攻兜底 [C]

[C] 按配置的技能优先级扫描满足条件的主动技，匹配后发出至多一个申请；否则继续检查下一技能；无合法主动技能时尝试普攻；普攻不合法时按已有射程驱动移动/等待。这不是承诺总会立即输出伤害：移动、动作时间、攻击条件是真实成本。

[R] 推荐保留三类优先级语义（是否已有等价实现必须G0核实）：

| 类别 | 举例 | 使用原则 |
|---|---|---|
| 救场 / 防御条件 | 嘲讽、冰霜新星、诱饵、紧急治疗 | **仅当有真实威胁/失血需要**进入候选，不在平安时抢行动 |
| 重要循环 | 火球、连锁闪电、炮轰、范围控制 | 只有目标条件足够好才参与排序 |
| 常规输出/维护 | 重击、导引箭、合格诅咒/召唤补员 | Ready且条件成立时使用 |

**这三类不是新增硬编码固定权重**。同类具体技能优先级仍由玩家的当前合法配置/技能Profile决定。禁止写死“职业=法师则冰霜新星必优先”。

### 技能饥饿（Starvation）原则 [R]

- 首版不设隐藏“累计N秒没施法就强制释放”的公平调度，以免违反玩家配置优先级。
- 通过 CastCondition 控制是否进入候选；测试观察某技能长期 Ready 却被压制的占比与原因。
- 若确实出现必须解决的饥饿问题，报告具体复现与可选机制（最小间隔、配权、用户配置排序），由用户选择，**不可擅自引入 Utility/动态评分AI**。

## 5. 射程外高优先级技能的处理 [R；审批C01]

**推荐候选策略：** 高优先级技能射程外时，不让 AI 为追这一个技能而忽视已可使用的低优先级技能/普攻；先寻找当前能合法执行的动作。若无可攻击动作，再遵照现有主目标与 MovePolicy 接近目标。

| 场景 | 推荐结果 | 需要审计的冲突 |
|---|---|---|
| 陨石Ready，目标射程外；火弹可命中 | 尝试火弹（若其优先级扫描到） | 旧行为是否强制追技能射程 |
| 远程法师只有一个主动技能，射程外，普通攻击也射程外 | 按现有射程追近 | 移动决策唯一来源 |
| 治疗技能Ready，但队友血量满 | 跳过治疗，继续攻击 | 现有Heal是否误放满血目标 |
| 队友急需治疗但在治疗射程外 | 不瞬移施法；是否移动救援为专项审批 | 团队队列路径/角色职位边界 |

**注意**：第一行仅在已有多技能扫描语义相符时采用。是否允许“为治疗/召唤/救场移动”和具体移动目标也须先审批，不能默默增加跑位策略。

## 6. 目标与范围收益 [C + R]

[C] 主目标锁定与技能临时目标分开，技能的合法范围中心/友军/召唤位置等由Skill TargetPolicy选择，选择结果不默认改变主TargetLock；没有合法目标不能创造虚假命中。

[R] 首版只实现**有限枚举式条件和目标策略**，不做可写公式解释器和全局效用函数。选择举例：

| 选择方式（概念） | 输入 | 候选筛选 | 确定性排序 |
|---|---|---|---|
| 当前主锁定 | mainTargetID | 合法+范围满足 | 只一个合法目标 |
| 最近合法敌人 | enemy list | 当前房/可选/可攻击 | 边缘/现行距离升序、稳定EntityID |
| 多目标优先 | skill范围+敌群 | 合法落点覆盖目标数≥阈值 | 覆盖数降序，再按现有距离/ID稳定排序 |
| 最近受威胁友军 | ally list+近战威胁 | 当前可治疗/可保护 | 威胁数降序，低血量比例/ID作为稳定兜底 |
| 最低生命比例友军 | ally list | 有效失血且未死亡/可被治疗 | 当前HP/MaxHP升序、稳定EntityID |
| 无需敌人的自身/范围技能 | self/area | 当前作用对象与覆盖条件合法 | 自身或合法固定作用点 |
| 补充召唤 | owned summons+slot limit | 存活数量不足、位置合法 | 现有有效生成位置/ID排序 |
| 保持诅咒覆盖 | enemy list+curse source/status | 存在未被同类有效覆盖的合法目标 | 当前主目标→合法缺失覆盖目标（仅R） |

**[T]** 距离算法、范围中心候选集、并列优先顺序、不可见敌人/LoS与Boss优先级等必须复用现有合同；若代码未定义且影响正式玩法先报审批。测试夹具可以显式定义并列排序以验证确定性，不能当作正式产品默认。

## 7. 何时重新评估 [C]

| 事件 | 行为 |
|---|---|
| 当前Action完成或进入下个合法Ready点 | 有资格重新决策 |
| 主目标死亡、消失、不再合法 | 标记NeedsReevaluation；动作中断仍遵从Runtime |
| 技能CD变为Ready | 不等于中断当前动作；下次合法窗口可重新检查 |
| HP变化/新近战威胁/队员进入/召唤物出现或死亡 | 更新合法候选数据，必要时标记重评；不递归执行AI |
| 新的有效Buff、光环范围变化或诅咒消失 | 在确定性边界重新检查状态与技能条件 |
| 施法请求被Runtime拒绝 | 记录拒绝；按现有去重/下次合法重评策略，避免同Tick无限重复请求 |

[R] 推荐“脏标记 + 下次合法动作边界”而非每Tick重排所有技能。RNG受Core控制；全部状态存于各单位运行态，不在共享Definition泄漏。

## 8. 动作合同与技能无效目标 [C]

- 同一角色一次只有一个主动动作；活动Action执行 `Windup→Commit→Recovery`；投射物Commit后独立于角色动作推进。
- **CD在Commit才开始**；不能在Begin/Windup或飞弹Impact时再额外计CD。
- 旧S2已确认：**原目标在Commit前死亡/消失/不再可选时，该次施法取消，不产生Commit、CD、投射物**。不应让Godot动画私自产生射击事件。
- [T] Windup期间目标只是**离开射程**、施法者被控制、治疗对象变满血、AOE预选点过时、取消后恢复时长以及多目标目标重建，旧规则未一概批准；**要逐个场景审计和审批，不准直接套用“取消无CD”**。
- AI不擅自重定向已Commit的飞弹，不修改原本的发射后目标失效规则；导引箭有自身合法弹道特例，须依已批准的技能实现。

## 9. 防止技能消耗无意义动作 [R]

| 技能 | 资格建议 | 不合法时怎么办 |
|---|---|---|
| 恢复型技能 | 合法友军存在实质生命缺口（阈值T） | 不Cast，继续下一技能 |
| 冰霜新星 | 自身周围有近战威胁/覆盖足够敌人（阈值T） | 不空放 |
| 嘲讽 | 有未被保护的合法队友受威胁、或合格敌人需转移 | 不对已被自己稳定接住的怪无意义嘲讽（例外T） |
| 骷髅/女武神 | 当前本人召唤数量低于目标数，有合法生成位置 | 已满时不施放，避免无限替换 |
| 诅咒 | 目标不具备有效同类诅咒或需合法刷新（窗口T） | 不每Tick刷新同名诅咒 |
| 多光环 | 当前已装备有效槽且应维持；采用现有光环生命周期 | **不每Tick浪费施法动作重新开光环** |
| AOE | 实际可能覆盖至少N个合法目标或1个高价值目标 | 缺少收益时继续合法单体/普攻 |
| DoT | 目标尚未被适当覆盖且状态刷新合法 | 不盲目重复上毒 |
| 尸爆 | 有当前房间合法可消费尸体且消耗资格 | 无尸体跳过，不凭空造爆炸 |

此表中的“什么叫实质生命缺口、高价值目标、刷新窗口、补召优先级”都是**条件类推荐，数值T**。可以用测试数据注入值证明规则能力，但不锁定正式上线阈值。

## 10. 与三类现有系统的对齐

**普通攻击：** 不因新增技能AI而失效；普攻按AttackSpeed计算 Windup/Recovery，主动 CD 由自身配置管理；不引入统一 Mana 或高额全局CDR。

**小队/怪物：** 目前多人上阵（首发最多4）、个人等级与经验独立；每个单位独立技能/动作状态；攻击人选要尊重已批准的接敌/溢出/Forced锁定；怪物默认近战/远程行为不受本包新技能策略影响。敌AI延迟、入场散开与受击退让不被本包覆盖。

**跨场景：** 保留存活召唤物跨房间HP；光环/诅咒/技能目标换场景时生命周期由现有 GameSession/Encounter 决定；玩家换人需等当前房间结束或全队死亡，再回城换人并回到原房；本包不可私自重置冒险进度。

## 11. 参考伪代码（仅语义，不承诺接口名称）

```csharp
// 本代码是审查用伪代码，不可未经G0审批直接复制为新的并行组件。
Decision DecidePlayerAction(BattleSnapshot world, HeroRuntime hero)
{
    if (!ExistingActionRuntimeCanDecide(hero)) return Defer();
    var main = ExistingTargetLockOrCurrentLegalFallback(world, hero);

    foreach (var equippedSkill in ExistingOrderedEquippedSkills(hero))
    {
        if (!ExistingSkillEligible(hero, equippedSkill)) continue;
        if (!ApprovedCastConditionIsTrue(world, hero, equippedSkill)) continue;
        var target = ExistingSkillTargetSelection(world, hero, main, equippedSkill);
        if (!ExistingTargetAndRangeLegal(world, hero, equippedSkill, target)) continue;
        return ExistingActionRequestCastSkill(equippedSkill, target);
    }

    if (ExistingBasicAttackCanRequest(hero, main)) return ExistingBasicAttackRequest(main);
    return ExistingMovementOrWaitPolicy(world, hero, main);
}
```

强调：真实运行中 `ActionRuntime` 必须**再次复核**（同 Tick 目标可能死亡）。该伪代码不能取代已有施法生命周期、技能效果、主目标更新或入场散开机制。
