# Steam D2｜P1-4 角色自动技能 AI 执行交接包 V1.0

**交付对象：Claude Code（Windows，Godot 4.7 .NET / C#）**  
**性质：设计/实现交接文件，不代表已经执行本地工程修改。**

## 唯一推荐入口

1. 先读 `00_主Todo与状态.md`，确认这次只处理 P1-4，已有 P0-2、P0-3 交付与实现状态尚待核实。
2. 再读 `01_现有工程审计与冲突审批.md`、`CLAUDE_CODE_FIRST_PROMPT.md`，**执行只读 G0 并停在审批点**。
3. 经用户确认后参考 `02_自动施法决策规则.md`、`03_目标选择与技能类型适配.md`、`04_数据接口与测试夹具.md`、`05_验收与调平测试.md`、`06_分阶段实施与交付.md`。
4. `data/*_TEST_ONLY.*` 是**语义与无头测试样例**，不是正式项目配表或已有 C# 接口定义。`data/validate_examples.py` 用于静态检查，不会连接或修改游戏工程。

## 本轮实现边界

**在授权后允许的方向：** 扩展已有 `PlayerPolicy` 的技能资格筛选、优先级、技能目标选择和最小状态记忆；复用现有 ActionRequest、Action/SkillRuntime、Buff/Effect、TargetLock、召唤与光环能力；提供可复现测试和有界观测。

**本包不得擅自实现：** 第二套 AI/技能管理器；通用可编程行为树；游戏 UI 可编程技能宏；新的伤害公式或乘区；新怪物 AI；新职业技能或装备词缀；打断动作/扣 CD 的自创规则；切换关卡/挂机策略；更改召唤/光环/诅咒的已批准规则。

## 已确定的核心合同

- 角色行动基于现有 `PlayerPolicy → ActionRequest → Action/SkillRuntime`；`MonsterPolicy` 和 `IdlePolicy` 不属于本轮重写范围。
- 一次只执行一个主动动作：`Ready → Windup → Commit → Recovery`；主动 CD **由 Commit 启动**；投射物独立运行。
- 玩家决定已学习和装备技能；初始 1 个槽，通过全局星图逐步最多 5 个；被动不占槽。
- 按配置优先级尝试可合法使用的主动技能；没有适合技能时普通攻击兜底；没有合法普攻再走现有移动/等待。
- 当前主锁定稳定；技能可以选临时独立目标，不默认更改主锁定。
- 圣骑士同时允许**多种主动光环**（每种占槽）；死灵允许**多种不同主要诅咒并存**。
- 死灵基础骷髅**不消耗尸体**，存活召唤物跨房间保持生命；女武神独立召唤；游侠只装备弓、远程作战。
- 现有敌人 AI 启动延迟 + 小队入场散开不回退；远程受近战直接伤害后的退让 V0.1 应先核实现有落地，不重复实现。
- P0-1 护甲采用递减百分比，`K(L)` 的 L 为攻击者等级，但该公式的代码迁移属于**独立专项**，本轮不触碰。

## 本包验收的正确含义

`Config validation PASS` ≠ `Game.Core.Tests PASS` ≠ `dotnet build PASS` ≠ `Godot Mini 实机 PASS`。当前只会执行包内静态校验；后续四种结果需由 Claude Code 按真实输出分别标记，无法执行则用 `BLOCKED/NOT RUN`。

## 4. 禁止产生垃圾代码的工程纪律

- 优先扩展现有 `PlayerPolicy` 和当前已存在配置/状态对象；没有用户批准不新增 `AutoCastManager`、`SkillAIService`、`SmartTargetDirector` 等并行实体。
- 决策只生成已批准 `ActionRequest`；不得另造 `ApplyDamage/ApplyBuff/CastDirect` 快捷方法。
- 只有 `Action/SkillRuntime` 负责动作许可和 CD；只有 Buff/Effect 管状态和治疗；只有目标系统管理主锁定。
- 不为8怪物/17技能分别写17个独立AI控制器；只用已有参数、有限合法条件与少量专门策略。
- 配置版本迁移涉及稳定ID、存档和旧文件时必须先报审批；**不能因为标“废弃”就直接删除旧表/旧字段**。
- 需要替换既有方法时，提交旧→新调用点清单，确认替代路径正常后才删除冗余分支，最后跑全部回归。
- 严禁通过牺牲其他分支的合法结果让新测试通过，例如跳过技能 CD、禁用怪物、隐藏失败分支、硬编码当前测试角色ID。
- 一切运行结果必须注明真实命令、退出码、失败日志摘要、未运行原因。

# 02｜P1-4 自动施法决策合同 V1.0

## 0. 决策层级与状态标签

- **[C 已确认]**：来自 2026-10-15 Battle AI/S2 与后续用户确认，必须保持一致。
- **[R 推荐]**：本包提供的最小具体方案，若当前代码没有等价实现，G0 审计后取得用户批准才新增。
- **[T 待定]**：参数、精确排序、失败成本、对象语义，不能随意写正式默认配置；TEST_ONLY 场景允许注入明确值。

当前唯一目标：**在已有 Game.Core PlayerPolicy 的合法决策窗口，为已装备技能选出合适的 CastSkill 意图；否则回到 BasicAttack / Move / Wait**。不开发自定义策略编辑器、行为树或不稳定“智能评分器”。

## 1. 核心职责和权威边界 [C]

```text
Player chosen: 已学技能+已装备技能槽(1→5)
      + 已存在 AI/Skill/Buff 配置(只读)
                         │
Core Fixed Tick ─ Action/SkillRuntime 判定 CanDecide（单活动动作）
                         │
PlayerPolicy 读取主TargetLock/战场/有效技能快照
       ├── 状态与权限预筛
       ├── 候选技能的CastCondition
       ├── 技能专属临时TargetPolicy（不覆盖主TargetLock）
       ├── Priority确定性排序
       └── ActionRequest.CastSkill / BasicAttack / Move / Wait
                         │
Action/SkillRuntime 唯一权威复核 → Windup→Commit→Recovery
                         │                           │
                     拒绝理由                  Effect、CD(Commit)
                         └── 事实反馈、状态重评标记（禁止回调递归决策）
```

AI 不能直接申请 Damage/Heal/Buff、修CD、改装备、改主锁定、切Area、自动开箱；负责伤害公式的是 DMG 体系。玩家自行决定装备哪些技能；AI不能自行加点、换技能或占更多槽。

## 2. 首先排除“根本不允许决策”的状态 [C]

| 条件 | 处理 | 禁止行为 |
|---|---|---|
| Actor死/无有效战斗上下文 | 无新的Cast/BasicAttack | 死亡单位仍放技能 |
| Action忙于Windup/Commit/Recovery | 等待现有动作结算；可标记待重评 | 抢占/重置动作 |
| 眩晕/冻结/沉默/控制限制 | 根据现有 Runtime 对动作分类的权限判断 | 由AI自创控制打断时序 |
| 小队入场散开阶段 | 沿用现有入场状态与敌 AI 延迟，按已实现合法窗口行动 | 恢复入口堵门 |
| 受击退让进行中 | 由现有移动/动作Runtime处理退让，到合法边界再决策 | AI同时发退让与施法命令 |
| 切房间/回城/换人 | 由 GameSession / Encounter / 队伍换人流程决定可行动状态 | AI擅自切区或复制召唤对象 |

**[T]** 实际“入场散开时角色能否放技能、怎样与敌人激活延迟衔接”以现有代码行为审计为准，不在此回退任何旧规则。

## 3. 主动技能候选合法性 [C + R]

| 检查顺序（建议） | 条件 | 不通过的处理 |
|---|---|---|
| 1 | 技能已学习、当前装备的有效槽、已解锁、技能ID可解析 | 跳过候选，记录原因；配置坏引用加载时报错 |
| 2 | 技能 Runtime Ready / CD完成，且行为类别允许 | 跳过；不修改CD |
| 3 | 对应施法者状态允许该类别动作 | 跳过；不直接解除控制 |
| 4 | 技能 CastCondition 成立（例如缺血/有近敌/召唤未满/未有效覆盖） | 跳过，不“为了CD”空放 |
| 5 | 技能 TargetPolicy 能找出合法技能目标/区域/位置（允许不需要敌人的自施法技能） | 跳过，记录 NO_VALID_SKILL_TARGET |
| 6 | 技能射程、合法站位、LoS与技能要求满足当前动作申请 | 不允许无视射程；下一动作如何移动见C01 |
| 7 | 优先级与平局稳定排序 | 选出一个 CastSkill 请求；Runtime再复核 |

任何一个条件通过只证明 **AI 可以尝试提出请求**；真正 Commit 仍归 Runtime。绝不能把“CD Ready”视作“可以绕过当前Recovery”。

## 4. 技能顺序与普攻兜底 [C]

[C] 按配置的技能优先级扫描满足条件的主动技，匹配后发出至多一个申请；否则继续检查下一技能；无合法主动技能时尝试普攻；普攻不合法时按已有射程驱动移动/等待。这不是承诺总会立即输出伤害：移动、动作时间、攻击条件是真实成本。

[R] 推荐保留三类优先级语义（是否已有等价实现必须G0核实）：

| 类别 | 举例 | 使用原则 |
|---|---|---|
| 救场 / 防御条件 | 嘲讽、冰霜新星、诱饵、紧急治疗 | **仅当有真实威胁/失血需要**进入候选，不在平安时抢行动 |
| 重要循环 | 火球、连锁闪电、炮轰、范围控制 | 只有目标条件足够好才参与排序 |
| 常规输出/维护 | 重击、导引箭、合格诅咒/召唤补员 | Ready且条件成立时使用 |

**这三类不是新增硬编码固定权重**。同类具体技能优先级仍由玩家的当前合法配置/技能Profile决定。禁止写死“职业=法师则冰霜新星必优先”。

### 技能饥饿（Starvation）原则 [R]

- 首版不设隐藏“累计N秒没施法就强制释放”的公平调度，以免违反玩家配置优先级。
- 通过 CastCondition 控制是否进入候选；测试观察某技能长期 Ready 却被压制的占比与原因。
- 若确实出现必须解决的饥饿问题，报告具体复现与可选机制（最小间隔、配权、用户配置排序），由用户选择，**不可擅自引入 Utility/动态评分AI**。

## 5. 射程外高优先级技能的处理 [R；审批C01]

**推荐候选策略：** 高优先级技能射程外时，不让 AI 为追这一个技能而忽视已可使用的低优先级技能/普攻；先寻找当前能合法执行的动作。若无可攻击动作，再遵照现有主目标与 MovePolicy 接近目标。

| 场景 | 推荐结果 | 需要审计的冲突 |
|---|---|---|
| 陨石Ready，目标射程外；火弹可命中 | 尝试火弹（若其优先级扫描到） | 旧行为是否强制追技能射程 |
| 远程法师只有一个主动技能，射程外，普通攻击也射程外 | 按现有射程追近 | 移动决策唯一来源 |
| 治疗技能Ready，但队友血量满 | 跳过治疗，继续攻击 | 现有Heal是否误放满血目标 |
| 队友急需治疗但在治疗射程外 | 不瞬移施法；是否移动救援为专项审批 | 团队队列路径/角色职位边界 |

**注意**：第一行仅在已有多技能扫描语义相符时采用。是否允许“为治疗/召唤/救场移动”和具体移动目标也须先审批，不能默默增加跑位策略。

## 6. 目标与范围收益 [C + R]

[C] 主目标锁定与技能临时目标分开，技能的合法范围中心/友军/召唤位置等由Skill TargetPolicy选择，选择结果不默认改变主TargetLock；没有合法目标不能创造虚假命中。

[R] 首版只实现**有限枚举式条件和目标策略**，不做可写公式解释器和全局效用函数。选择举例：

| 选择方式（概念） | 输入 | 候选筛选 | 确定性排序 |
|---|---|---|---|
| 当前主锁定 | mainTargetID | 合法+范围满足 | 只一个合法目标 |
| 最近合法敌人 | enemy list | 当前房/可选/可攻击 | 边缘/现行距离升序、稳定EntityID |
| 多目标优先 | skill范围+敌群 | 合法落点覆盖目标数≥阈值 | 覆盖数降序，再按现有距离/ID稳定排序 |
| 最近受威胁友军 | ally list+近战威胁 | 当前可治疗/可保护 | 威胁数降序，低血量比例/ID作为稳定兜底 |
| 最低生命比例友军 | ally list | 有效失血且未死亡/可被治疗 | 当前HP/MaxHP升序、稳定EntityID |
| 无需敌人的自身/范围技能 | self/area | 当前作用对象与覆盖条件合法 | 自身或合法固定作用点 |
| 补充召唤 | owned summons+slot limit | 存活数量不足、位置合法 | 现有有效生成位置/ID排序 |
| 保持诅咒覆盖 | enemy list+curse source/status | 存在未被同类有效覆盖的合法目标 | 当前主目标→合法缺失覆盖目标（仅R） |

**[T]** 距离算法、范围中心候选集、并列优先顺序、不可见敌人/LoS与Boss优先级等必须复用现有合同；若代码未定义且影响正式玩法先报审批。测试夹具可以显式定义并列排序以验证确定性，不能当作正式产品默认。

## 7. 何时重新评估 [C]

| 事件 | 行为 |
|---|---|
| 当前Action完成或进入下个合法Ready点 | 有资格重新决策 |
| 主目标死亡、消失、不再合法 | 标记NeedsReevaluation；动作中断仍遵从Runtime |
| 技能CD变为Ready | 不等于中断当前动作；下次合法窗口可重新检查 |
| HP变化/新近战威胁/队员进入/召唤物出现或死亡 | 更新合法候选数据，必要时标记重评；不递归执行AI |
| 新的有效Buff、光环范围变化或诅咒消失 | 在确定性边界重新检查状态与技能条件 |
| 施法请求被Runtime拒绝 | 记录拒绝；按现有去重/下次合法重评策略，避免同Tick无限重复请求 |

[R] 推荐“脏标记 + 下次合法动作边界”而非每Tick重排所有技能。RNG受Core控制；全部状态存于各单位运行态，不在共享Definition泄漏。

## 8. 动作合同与技能无效目标 [C]

- 同一角色一次只有一个主动动作；活动Action执行 `Windup→Commit→Recovery`；投射物Commit后独立于角色动作推进。
- **CD在Commit才开始**；不能在Begin/Windup或飞弹Impact时再额外计CD。
- 旧S2已确认：**原目标在Commit前死亡/消失/不再可选时，该次施法取消，不产生Commit、CD、投射物**。不应让Godot动画私自产生射击事件。
- [T] Windup期间目标只是**离开射程**、施法者被控制、治疗对象变满血、AOE预选点过时、取消后恢复时长以及多目标目标重建，旧规则未一概批准；**要逐个场景审计和审批，不准直接套用“取消无CD”**。
- AI不擅自重定向已Commit的飞弹，不修改原本的发射后目标失效规则；导引箭有自身合法弹道特例，须依已批准的技能实现。

## 9. 防止技能消耗无意义动作 [R]

| 技能 | 资格建议 | 不合法时怎么办 |
|---|---|---|
| 恢复型技能 | 合法友军存在实质生命缺口（阈值T） | 不Cast，继续下一技能 |
| 冰霜新星 | 自身周围有近战威胁/覆盖足够敌人（阈值T） | 不空放 |
| 嘲讽 | 有未被保护的合法队友受威胁、或合格敌人需转移 | 不对已被自己稳定接住的怪无意义嘲讽（例外T） |
| 骷髅/女武神 | 当前本人召唤数量低于目标数，有合法生成位置 | 已满时不施放，避免无限替换 |
| 诅咒 | 目标不具备有效同类诅咒或需合法刷新（窗口T） | 不每Tick刷新同名诅咒 |
| 多光环 | 当前已装备有效槽且应维持；采用现有光环生命周期 | **不每Tick浪费施法动作重新开光环** |
| AOE | 实际可能覆盖至少N个合法目标或1个高价值目标 | 缺少收益时继续合法单体/普攻 |
| DoT | 目标尚未被适当覆盖且状态刷新合法 | 不盲目重复上毒 |
| 尸爆 | 有当前房间合法可消费尸体且消耗资格 | 无尸体跳过，不凭空造爆炸 |

此表中的“什么叫实质生命缺口、高价值目标、刷新窗口、补召优先级”都是**条件类推荐，数值T**。可以用测试数据注入值证明规则能力，但不锁定正式上线阈值。

## 10. 与三类现有系统的对齐

**普通攻击：** 不因新增技能AI而失效；普攻按AttackSpeed计算 Windup/Recovery，主动 CD 由自身配置管理；不引入统一 Mana 或高额全局CDR。

**小队/怪物：** 目前多人上阵（首发最多4）、个人等级与经验独立；每个单位独立技能/动作状态；攻击人选要尊重已批准的接敌/溢出/Forced锁定；怪物默认近战/远程行为不受本包新技能策略影响。敌AI延迟、入场散开与受击退让不被本包覆盖。

**跨场景：** 保留存活召唤物跨房间HP；光环/诅咒/技能目标换场景时生命周期由现有 GameSession/Encounter 决定；玩家换人需等当前房间结束或全队死亡，再回城换人并回到原房；本包不可私自重置冒险进度。

```csharp
// 本代码是审查用伪代码，不可未经G0审批直接复制为新的并行组件。
Decision DecidePlayerAction(BattleSnapshot world, HeroRuntime hero)
{
    if (!ExistingActionRuntimeCanDecide(hero)) return Defer();
    var main = ExistingTargetLockOrCurrentLegalFallback(world, hero);

    foreach (var equippedSkill in ExistingOrderedEquippedSkills(hero))
    {
        if (!ExistingSkillEligible(hero, equippedSkill)) continue;
        if (!ApprovedCastConditionIsTrue(world, hero, equippedSkill)) continue;
        var target = ExistingSkillTargetSelection(world, hero, main, equippedSkill);
        if (!ExistingTargetAndRangeLegal(world, hero, equippedSkill, target)) continue;
        return ExistingActionRequestCastSkill(equippedSkill, target);
    }

    if (ExistingBasicAttackCanRequest(hero, main)) return ExistingBasicAttackRequest(main);
    return ExistingMovementOrWaitPolicy(world, hero, main);
}
```

# 03｜技能类型适配、17个代表技能与跨职业兼容

> **注意状态：** 17个技能是前一份P0-3执行包的**开发候选清单**，不是“全都已实现”；名称、技能ID只作为跨文档映射。玩家未正式批准的技能数值、动画、具体AI阈值不可凭本文件定稿。AI只确定“何时提出CastSkill请求”，效果和强度归已存在的技能/Effect规格。

## 1. 必须复用的技能目标大类

| 类别 | 必须回答的问题 | 目标合法性 | 行动原则 |
|---|---|---|---|
| 近战单体 | 目标是否仍可命中、在近战射程？ | 敌方实体 | 范围不够按现有Move规则，禁止瞬移 |
| 远程单体 | 目标是否合法、在射程且满足LoS？ | 敌方实体 / 弹道方向 | 主TargetLock稳定，技能临时目标可不同 |
| 多弹道/多段 | 发射方向与有效目标是哪些？ | 多个敌方实体 / 合法方向 | AI仅决定发射，不在每发弹丸回调里重复施法 |
| 范围AOE | 目标数是否达到收益门槛？ | 合法目标/范围中心 | 先候选过滤再稳定选择区域，不全图挑敌作弊 |
| 自身周围控制 | 是否真的有附近威胁？ | Self + 合格敌群 | 没有敌人不空放，不新增专用怪物仇恨 |
| 近战救场/嘲讽 | 该目标是否正威胁队友，距离是否可达？ | 限定范围与目标数 | 强制锁定由现有技能/TargetRuntime执行 |
| 主动治疗 | 是否存在合法缺血队友？ | 有效友军 | 依固定目标策略；不凭空恢复已死队员 |
| 持续光环 | 是否已装备、应维持、效果来源合法？ | Self/AuraRange | 多种同时共存，各自占槽，不每Tick重新释放 |
| 诅咒 | 目标是否缺少有效同种诅咒？ | 有效敌方单位或合法范围 | 多种共存，同种去重/刷新 |
| 召唤 | 本人召唤名额是否空缺？ | 合法召唤位置 | 已满不重复施放；召唤物跨房续存 |
| 尸体消耗 | 是否有当前房间未消费尸体？ | 尸体ID/位置 | Commit 才由唯一消费权威决定结果，AI不得预消费 |

## 2. 17个代表技能：可直接配置的条件语义

| 草案SkillID | 资格条件（示例，T值测试注入） | 建议临时目标策略 | 应跳过的场景 | 核心回归 |
|---|---|---|---|---|
| `BAR_BASH` | 合法近战敌人、Ready | 当前主锁定，失效才复用既有重选 | 不在近战射程、不可攻击 | 近战距离+CD/普攻共存 |
| `BAR_TAUNT` | 队友受到当前范围合法近战威胁/明确特殊命令 | 有限数量合格威胁怪物 | 无需转移的怪群、目标范围外 | Forced不破坏接敌稳定 |
| `BAR_WHIRLWIND` | 有当前有效近战敌群/行动路径合法 | 已批准的移动方向+路径范围目标 | 没有效目标、被控或路径不合法 | 动作期间不反复请求技能 |
| `PAL_SMITE` | 目标在近战范围且角色可行动 | 当前主锁定 | 目标越界/死亡 | 不无距离“拦截” |
| `PAL_PRAYER` | 已装备且当前光环需要激活/保持（具体生命周期待审计） | 自身+合法光环范围友军 | 已正确维持时不可每Tick重新 Cast | 治疗只按真实HP缺口 |
| `PAL_FANATICISM` | 已装备且激活资格成立 | 自身及符合条件友军/召唤 | 已维持，无需反复重开 | 同时与Prayer并存、各占槽 |
| `PAL_CONVICTION` | 已装备且激活资格成立 | 光环范围内合格敌人 | 已维持不重复附加独立乘区 | 与降低抵抗共存 |
| `SOR_FIREBALL` | 至少一个合格目标，AOE收益门槛可配置 | 覆盖最多合法敌人的候选落点/主目标 | 无敌人、不可合法命中 | 火伤不自动燃烧 |
| `SOR_FROST_NOVA` | 施法者附近近战威胁成立（或覆盖满足门槛） | 自身中心 | 没有近敌 | 不强制打断受击退让/当前前摇 |
| `SOR_CHAIN_LIGHTNING` | 有有效起跳目标；是否要求至少2敌人是可配置条件 | 本次合法弹射收益最佳起点 | 无合法首目标或越界 | 跳数、唯一命中与Proc独立 |
| `NEC_RAISE_SKELETON` | 已装备且存活骷髅未达到指定数量、位置合法 | 合法生成位置 | 已满/场景不可召唤 | 不耗尸体、跨房HP保留 |
| `NEC_AMPLIFY_DAMAGE` | 目标尚无有效同种诅咒或可合法刷新 | 当前重要目标→缺覆盖敌人 | 有同种足额覆盖且未到刷新条件 | 多种不同诅咒可共存 |
| `NEC_LOWER_RESIST` | 同上，合法敌人可诅咒 | 元素输出队优先关注的合法目标（实际AI依测试配置） | 同类已经有效覆盖 | 与Conviction进入统一抗性解析 |
| `NEC_CORPSE_EXPLOSION` | 有合法未消费的当前房间尸体、敌人处于有效爆炸范围 | 合法尸体ID | 无尸体/尸体已消费/无受益目标 | 仅SkillRuntime/尸体权威可以消费 |
| `RAN_MULTISHOT` | 弓类武器已装备，存在可射击的合法敌人 | 有效敌群方向 | 没弓、无有效目标 | 1D逻辑+二维演出不等于2D弹道命中 |
| `RAN_GUIDED_ARROW` | 弓类武器、有效单体目标、Ready | 当前合法追踪目标 | 目标不合法或射程外 | 跟踪命中与主锁定分离 |
| `RAN_VALKYRIE` | 已装备且女武神数量未到上限 | 合法生成位置 | 数量已满/不能召唤 | 独立召唤HP/容量/跨房跟随 |

**不能默默给职业增加新的技能：** 祈祷不是紧急高强度治疗、狂热不是全职业通用CDR、旋风不天然增加接敌容量、火球火伤不天然燃烧、女武神近战不代表游侠本人可以使用近战武器。

## 3. AI 典型组合验证

### A：野蛮人+法师被漏怪追击

1. 小队遵照现有入场散开和敌AI启动延迟，进入正常合法战斗状态。
2. 野蛮人基础接敌容量与怪物Normal/Overflow继续由既有敌AI管理。
3. 漏怪近战命中法师→通用退让模块可在合法窗口申请Move，**不强制**让所有敌怪重新选目标。
4. 野蛮人嘲讽如已装备、CD完成、满足距离/目标数量和CastCondition，提出CastSkill；强制转移归技能Effect。
5. 法师冰霜新星若附近有威胁，可在**可开始新行动时**施放；不得打断其当前不可取消施法或退让。

### B：圣骑士多主动光环+死灵多个主要诅咒

- 圣骑士在合法槽中同时装备祈祷、狂热、信念，**三项允许维持**，各占一槽，不要求每Tick重新Cast。
- 诅咒伤害加深、降低抵抗可同一目标并存；应用已有Buff叠加分组，不应互相驱逐。
- 同种重复来源按G02策略去重/取强（细节需已有Buff合同核实）；改变光环来源、范围后撤销准确对应 Modifier，不允许残留。
- 骷髅在狂热范围内如果符合资格可受益，但临时光环不从主人快照再继承一次。

### C：先召唤骷髅，再尸爆清群

- 死灵技能槽中同时有骷髅和尸爆；不足上限可在合法窗口补骷髅；尸爆没有尸体时**不入候选**。
- 骷髅杀死正式敌人，死亡事件按原规则生成唯一尸体；在下一合法窗口AI可以申请尸爆。
- 两个尸爆请求竞争同一尸体时，只允许一个成功消费；若第二个在Commit前目标失效，按审批后的当前技能取消语义结算，不能在AI里先扣尸体。
- 尸爆造成的死亡与后续BD链效果只由已有TriggerRule/EffectQueue结算，AI不参与一层层派生施法。

### D：游侠持续弹道+受击退让

- 远程游侠只有弓技能，不引入标枪动作；炮轰如果后续增加，持续动作不能被普通施法策略强制改写。
- 近战怪直接攻击后，若受击退让模块合法，角色在安全边界退让后再恢复原技能优先级扫描。
- 导引箭的投射物飞行不会占用角色持续的施法动作；Commit 后原目标死亡时的飞弹命运由既有弹道规则决定。

## 4. 不批准自动添加的新机制

- 不做“法师必先冰霜新星”“游侠必打最低血”这类未确认硬编码职业AI。
- 不新增手动拖拽式技能宏 UI、复杂 DSL、自动切天赋、动态升级技能。
- 不开发战斗之外的刷图/切地图/回城指挥，保持 IdlePolicy/GameSession 边界。
- 不把主动光环维持语义偷换为纯被动免费获得：**技能槽占用是正式成本**。
- 不因技能属于诅咒而互斥：不同诅咒共存是正式规则。
- 不为提高AI「聪明」而修改敌方 TargetLock、接敌容量、护甲伤害公式或召唤物奖励归属。

# 04｜配置接口、强类型校验与TEST_ONLY数据语义

## 1. 原则

**本包给出能力和测试数据，而不是要求新增同名的工程 CSV 表、DTO 类或 JSON 格式。** Claude必须先找出现有SkillDefinition、有效技能规格、玩家技能槽、AIProfile/TargetPolicy、AIRuntimeState、Buff/TargetRuntime和原Loader路径，形成字段映射表，用户审批后增量修改。配置应复用原定 CSV 基础、JSON 复杂规则、Godot Resource 表现，Core统一校验；不要开发第二个配置解释器。

`data/skill_ai_profiles_TEST_ONLY.csv`：技能AIProfile的最小语义样例；`data/hero_loadouts_TEST_ONLY.csv`：已解锁技能槽中的装配测试夹具；`data/ai_test_cases_TEST_ONLY.csv`：无头验收输入和期望行为；`data/cast_condition_semantics_TEST_ONLY.json`：支持的有限条件词典及已批准/待批准边界。

## 2. 最小字段语义（待工程映射）

| 字段概念 | 作用 | 限制 |
|---|---|---|
| `skill_id` | 指向合法技能定义 | 稳定ID，缺失引用必须报错 |
| `priority` | 有限确定性尝试顺序 | 不等于玩家UI可编辑 |
| `condition_id` | 映射现有可校验的条件策略 | 不能字符串eval/脚本执行 |
| `target_policy_id` | 映射现有合法目标选择策略 | 不可改玩家主目标锁定真值 |
| `enabled` / `required_slot` | 测试技能是否真的装备 | 测试夹具不应改变生产星图 |
| `fixture_threshold` | TEST_ONLY注入人数/HP阈值 | 正式值T，不能从测试表默默转入上线表 |
| `fallback_reason` | 可观测跳过原因 | 使用现有诊断接口或批准的最小扩展 |
| `runtime_reject_reason` | 真正Runtime拒绝原因 | 不得谎称AI请求已经成功Commit |

## 3. 推荐的最小配置条件库 [R]

**可在既有系统有等价能力时复用：**

| 条件语义ID | 核心意义 | 用例 |
|---|---|---|
| `HAS_LEGAL_ENEMY` | 至少一个当前合法攻击敌人 | 重击、火球、导引箭 |
| `ENEMY_COUNT_IN_EFFECT_AREA` | 有限候选区域目标数达到TEST阈值 | 火球、多重箭 |
| `MELEE_THREAT_NEAR_SELF` | 有合法近战威胁在范围内 | 冰霜新星 |
| `ALLY_HP_BELOW_THRESHOLD` | 可治疗友军生命比例低于阈值 | 未来直接治疗 |
| `ALLY_UNDER_MELEE_THREAT` | 有合法队友受到近战威胁 | 野蛮人嘲讽 |
| `SUMMON_ALIVE_COUNT_BELOW_CAP` | 该召唤技能的本人存活单位数小于上限 | 骷髅、女武神 |
| `CURSE_NOT_EFFECTIVELY_COVERED` | 同种诅咒缺失或符合合法刷新窗口 | 伤害加深、降低抵抗 |
| `ACTIVE_AURA_EQUIPPED` | 当前有效槽内存在可维持的主动光环 | 祈祷、狂热、信念 |
| `CORPSE_AVAILABLE_WITH_TARGETS` | 合法未消耗尸体且附近有有效敌人 | 尸爆 |

**不做自定义脚本引擎**。超过有限条件库的需求优先看已有SkillEffect是否自带合法条件；实在需要再向用户申请增加一种配置语义，并单独附测试。

## 4. 预校验与Runtime复核

**加载期需要报错**：重复或空SkillID、条件ID/目标策略未识别、无对应Skill引用、非法Priority或阈值、测试夹具引用不存在角色、槽位非法、同时为同一槽装配两技能、非法武器（纯弓游侠）、循环依赖（若模型允许）。

**行动期正常跳过而不是报配置错误**：技能CD中、队友满血、怪物暂时不存在、召唤已满、已有效覆盖诅咒、AOE人数不够、射程外、当前被控。

**Runtime复核与诊断**：输入世界状态可能在筛选后/Commit前变化；AI生成意图时不能预先伤害、预先消耗尸体、预先开始CD。若Runtime拒绝，应留真实原因与确定性下次检查边界。

## 5. TEST_ONLY样例的使用说明

- `hero_loadouts_TEST_ONLY.csv` 中的槽位可用于 **隔离测试** 模拟技能槽已解锁，**不能将5槽强开写回生产星图进度**。
- `skill_ai_profiles_TEST_ONLY.csv` 的 `priority` 只用于测试确定性选择；不代表所有职业生产优先级已批准。
- `ai_test_cases_TEST_ONLY.csv` 每条都是“输入事实/期望请求”的测试契约，**不是 Godot 工程中已可运行的测试**。Claude应在 G0 审计后映射成现有 Core.Tests fixture。
- 相关 T 条件（治疗阈值、AOE覆盖人数、诅咒刷新提前量、召唤期望数量等）必须由测试上下文明确注入；没有正式产品审批时不允许使用 TEST_ONLY 值作为产品默认。

## 6. 推荐的诊断输出（非新接口强制命名）

| 字段 | 用途 |
|---|---|
| `tick` / `actor_id` | 确定时间与实例 |
| `main_target_id` / `selected_skill_target_id` | 观察目标分离 |
| `slot` / `skill_id` / `priority` | 看到技能顺序与槽位 |
| `candidate_result` / `reject_reason` | 为什么跳过当前技能 |
| `action_request` / `runtime_result` | AI选择与实际执行的区别 |
| `action_phase` / `cooldown_remaining` | 不被CD/动作假象误导 |
| `threat_reason` / `retreat_state` | 与受击退让/接敌AI交互 |
| `active_auras` / `active_curses` / `summon_count` | 团队持续能力与动态目标 |
| `evaluation_reason` / `decision_window` | 是否因为状态变化在合法边界重评 |

**长期挂机日志必须有界，可配置禁用/抽样/环形缓存（沿用已有诊断框架）；不要把每Tick候选遍历无上限写磁盘。**

## 7. 局部世界快照示例

`data/scenario_fixtures_TEST_ONLY.json` 提供10个更具体的 World Snapshot 语义示例（角色状态、部分CD、威胁、召唤数量和期望请求），用于降低Claude在编写测试时的猜测。实际C#测试不能直接把这些JSON对象当已存在的 `BattleSnapshot` 架构；必须经G0映射到真实构造器/Fixture。具体目标范围合法性、同Tick动作顺序及测试阈值在快照中属于受控输入，不代表正式平衡值。
