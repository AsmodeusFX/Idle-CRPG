# 05｜P1-4 自动技能 AI 验收矩阵 V1.0

**目的**：既测“AI申请什么”，也测“Runtime真正接受什么”和“战斗事实结果”。只要缺一层，不可以仅凭动画显示宣布通过。必要时先在 Game.Core.Tests 用明确TEST_ONLY场景执行，再到 Godot Mini 的多人战斗房做观感检查。

## 1. 无头Core测试（P1-4-01～30）

| ID | 场景与固定输入 | 必须观测/断言 |
|---|---|---|
| AI01 | 单角色已装技能CD Ready且目标有效 | 提出一次合法CastSkill请求，Runtime接受后按既有Windup/Commit |
| AI02 | 最高优先技能CD中，后续技能可用 | 跳过CD中技能，选择后续可用技能，不修改CD |
| AI03 | 所有技能不可用但普通攻击合法 | 提出BasicAttack；禁止永久Wait |
| AI04 | 技能与普攻都射程外 | 经既有MovePolicy移动或明确Wait，不对空造成伤害 |
| AI05 | 两个技能都Ready但角色忙于Recovery | 无新技能/普攻请求，不强制结束Recovery |
| AI06 | 技能Windup中另一技能CD结束 | 不立即取消/切技，后续合法动作边界再评估 |
| AI07 | 技能合法Commit | CD仅在Commit恰好启动一次，Windup/Impact不重复启动 |
| AI08 | 单体目标在Commit前死亡或从战场失效 | 按旧S2取消，无Commit/CD/投射物（其他目标变化按审批） |
| AI09 | AI目标筛选后Runtime认为射程非法 | Runtime拒绝可诊断，无伤害/Effect/擅改CD |
| AI10 | 当前主目标可用，但AOE选择其他敌群 | 技能目标可以不同于主锁定，主锁定不自动重选 |
| AI11 | 近似相同候选位置/敌群，固定ID和种子 | 两次运行选择相同，平局具体次序使用现有或审批规则 |
| AI12 | Buff/HP变化请求重评，当前施法忙 | 只标记待重评，不在事件回调递归进入AI |
| AI13 | 近距离没有敌人，冰霜新星Ready | 不为耗CD空放；尝试后续技能/普攻 |
| AI14 | 近战威胁进入冰霜新星范围 | 在下个合法决策时机进入合格候选并以配置优先级竞争 |
| AI15 | 祈祷光环已在合法槽维持 | 不每Tick重施法；治疗按Buff/Heal实际来源结算 |
| AI16 | 圣骑士合法槽同时有祈祷+狂热+信念 | 多光环可共存、各占槽；无隐藏1光环上限 |
| AI17 | 光环提供者移出范围/死亡/退出 | 原有光环来源失效或按生命周期撤销，无重复Modifier残留 |
| AI18 | 同目标已存在伤害加深，另有降低抵抗候选 | 两种不同诅咒能并存，不互相覆盖 |
| AI19 | 同种诅咒仍有效 | 不每Tick重复施法叠加；合法刷新窗口受配置控制 |
| AI20 | 骷髅数量已满、技能Ready | 不无意义额外召唤；原单位不被偷偷替换 |
| AI21 | 骷髅缺员且有合法位置 | 可以请求补召；不需要尸体；CD和动作由Runtime管 |
| AI22 | 召唤物跨房且存活 | 保留HP与数量；AI基于真实现存数量决定补召 |
| AI23 | 场上没有合法尸体 | 尸爆不入候选，攻击或其他行为正常继续 |
| AI24 | 同一尸体被两次技能请求瞄准 | 唯一消费在Commit权威生效，最多一次；另一次不能重复造成伤害 |
| AI25 | 法师火球伤害/技能目标通过条件 | 火伤不因类型本身自动燃烧；AOE不改主目标 |
| AI26 | 多重箭/连锁闪电造成多个有效Hit | 真实多段伤害与Proc触发资格分离；不会无上限派生 |
| AI27 | 游侠没弓但装备弓技能（非法配置） | 失败或明确合法拒绝，不绕过武器限制 |
| AI28 | 有弓的游侠被近战命中，当前在合法退让流程 | 不同时发Cast与Move，不改怪物目标锁定 |
| AI29 | 同一实例里2–4名英雄独立动作/CD/目标 | AI状态不跨实例污染，不受旧单英雄假设限制 |
| AI30 | Core固定Tick + 相同配置/输入种子重放 | 有序Decision/Action/Combat事实一致，与Godot FPS无关 |

## 5. 手工Mini观测标准

- 单角色进入房间后能自然普攻/释放合法主动技能，CD中不原地等待。
- 法师有近战威胁时才尝试冰霜新星；游侠受近战命中能按已实现退让在安全边界后退，正常恢复射击。
- 圣骑士3种光环可同时维持且各占槽，回城/卸槽/死亡后按实际生命周期撤销对应效果。
- 死灵骷髅不足时合理补员，跨房间保留；死灵诅咒不互相排斥也不疯狂重复刷新。
- 远程持续炮轰/法师施法前摇不被AI每Tick打断，飞弹在Commit后独立运行。
- AI的选择、实际Runtime的拒绝、状态变化有可诊断原因，不依赖 Godot Debug 绘制本身作为逻辑真值。
