# 06｜P1-4 分阶段实施流程、变更门禁与交付

## 1. 交付 ≠ 编码批准

完整包给Claude只意味着**授权 G0 只读审计**；每个 A 切片要么有用户明确的实施批准，要么等待审批。任何需要修改已签旧合同的地方都先提交版本差异及对所有引用方的影响。

| 阶段 | 内容 | 允许的事 | 停止点/准出 |
|---|---|---|---|
| **G0 只读** | 定位真实 `PlayerPolicy`、SkillRuntime、Target/装备/控制/移动等 | 搜索/阅读、测试现状报告（若用户允许运行只读测试） | **提交C01–C12冲突与审批问题；不编辑工程** |
| **A1 核心选技** | 合法窗口、优先级、技能资格、普攻兜底 | 在白名单内最小扩展原有 Policy / Config / Tests | AI01–AI12、29–30，相关回归PASS或如实BLOCKED |
| **A2 价值判断与目标** | 条件库、AOE/救场/治疗/光环/临时目标与退让协作 | 复用现有 TargetPolicy/Buff/Effect | AI13–20、25–28，相关回归PASS或如实BLOCKED |
| **A3 复杂自动维护** | 召唤补员、多诅咒覆盖、尸体资格、跨房角色状态 | 复用现有Summon/Corpse/Encounter接口；经审批补最少能力 | AI21–24、G01–G06及跨房回归 |
| **G4 验收与清理** | Core Tests、dotnet build、Godot Mini、清理废分支与更新Todo | 只在审定白名单与迁移授权内清理 | 提交真实命令、证据、版本、未通过项、主Todo更新 |

## 2. 模块所有权与不得重写清单

| 单一真值 | 只能由什么组件负责 | P1-4许可操作 |
|---|---|---|
| 玩家技能槽/已学技能 | 现有角色/星图/Loadout | 只读取，不自动加点/换技能 |
| 主目标锁定 | 已有TargetRuntime/AI当前逻辑 | 只读取/调用现有合法选敌，不创建第二份锁定 |
| 技能临时目标 | 现有Skill TargetPolicy与合法性接口 | 必要的轻量选择扩展需审批 |
| 动作/CD/打断 | Action/SkillRuntime | 提出ActionRequest，不写动作状态/扣CD |
| 伤害/治疗/控制 | DMG/Skill Effect/Buff/Trigger | 只提出合法意图，不新增乘区 |
| 召唤物生命周期 | 已有Summon/Encounter/GameSession | AI读取存活数量发合法补员请求 |
| 光环/诅咒 | Buff/Modifier源管理 | AI只负责激活/维护请求，不直接叠效果 |
| 怪物与房间 | MonsterPolicy/Encounter | 不能同时做P0-2新怪物或关卡导演 |
| 区域推进与箱仓 | IdlePolicy/GameSession/Loot | 严禁AI切地图/开启宝箱 |
| 护甲K(L)曲线 | P0-1专项 | 本包只记录当前版本，不作修改 |

## 3. 一次实施的严格步骤

1. 给 Claude Code 本包的 `CLAUDE_CODE_FIRST_PROMPT.md`，让它读真实工程并标证据。
2. Claude 报告已存在能力与 C01–C12，标明 **Confirmed / Recommended / TBD**；用户选择必要的策略分支。
3. 提交一个按切片、按文件列出的最小 diff 计划；用户批准后再编码。
4. 仅在当前白名单文件中修改，不应新建 `AutoSkillDirector` 平行管理器。
5. 每改一个功能运行对应Core测试，不能最后统一跑一次就当全部验证。
6. 每个切片执行真实构建与原战斗回归；需要Godot图形验收时注明可执行条件与截图/视频路径。
7. 提供旧逻辑引用搜索清单，**只有明确批准的废弃分支才可删除**；禁止把有风险旧逻辑直接注释掉留着。
8. 更新 `00_主Todo与状态.md` 的 Claude实施与测试状态，同时记录下份07需要哪些已验收能力。

## 4. 特别注意原项目正在并行开发

- P0-3 17个技能包已交Claude，**它的实际完成状态未知**。P1-4不能把未完成的技能当作存在；缺依赖要报告，测试用夹具需显式隔离。
- P0-2 怪物AI包已交付，但尚未收到实施结果；P1-4不得侵入MonsterPolicy重新做怪物索敌。
- 远程受击退让 V0.1 用户已计划交Claude，**代码是否存在待核实**；若不存在，不能在本包偷加第二套RetreatRuntime。
- 当前房间AI延迟+小队进门散开是实际工程基线，不得按旧文档重置为进门即强袭。
- P0-1 护甲百分比公式确定，但当前工程具体版本不明；P1-4不处理护甲、火抗、伤害乘区。

## 5. 不允许在报告中使用的错误结论

- “项目测试通过”——若只运行了本包CSV脚本，必须写“TEST_ONLY配置静态校验通过，未编译Godot”。
- “修复所有冲突”——用户尚未逐项审批的C项不能自行取舍。
- “技能AI已智能化”——须列出哪些具体条件策略、跳过原因与决策结果已落地；不能把建议伪代码冒充已有实现。
- “没有垃圾代码”——必须提供没有并行管理器、重复配置加载与孤儿字段的引用搜索/差异证据。
