# 04｜配置接口、强类型校验与TEST_ONLY数据语义

## 1. 原则

**本包给出能力和测试数据，而不是要求新增同名的工程 CSV 表、DTO 类或 JSON 格式。** Claude必须先找出现有SkillDefinition、有效技能规格、玩家技能槽、AIProfile/TargetPolicy、AIRuntimeState、Buff/TargetRuntime和原Loader路径，形成字段映射表，用户审批后增量修改。配置应复用原定 CSV 基础、JSON 复杂规则、Godot Resource 表现，Core统一校验；不要开发第二个配置解释器。

`data/skill_ai_profiles_TEST_ONLY.csv`：技能AIProfile的最小语义样例；`data/hero_loadouts_TEST_ONLY.csv`：已解锁技能槽中的装配测试夹具；`data/ai_test_cases_TEST_ONLY.csv`：无头验收输入和期望行为；`data/cast_condition_semantics_TEST_ONLY.json`：支持的有限条件词典及已批准/待批准边界。

## 2. 最小字段语义（待工程映射）

| 字段概念 | 作用 | 限制 |
|---|---|---|
| `skill_id` | 指向合法技能定义 | 稳定ID，缺失引用必须报错 |
| `priority` | 有限确定性尝试顺序 | 不等于玩家UI可编辑 |
| `condition_id` | 映射现有可校验的条件策略 | 不能字符串eval/脚本执行 |
| `target_policy_id` | 映射现有合法目标选择策略 | 不可改玩家主目标锁定真值 |
| `enabled` / `required_slot` | 测试技能是否真的装备 | 测试夹具不应改变生产星图 |
| `fixture_threshold` | TEST_ONLY注入人数/HP阈值 | 正式值T，不能从测试表默默转入上线表 |
| `fallback_reason` | 可观测跳过原因 | 使用现有诊断接口或批准的最小扩展 |
| `runtime_reject_reason` | 真正Runtime拒绝原因 | 不得谎称AI请求已经成功Commit |

## 3. 推荐的最小配置条件库 [R]

**可在既有系统有等价能力时复用：**

| 条件语义ID | 核心意义 | 用例 |
|---|---|---|
| `HAS_LEGAL_ENEMY` | 至少一个当前合法攻击敌人 | 重击、火球、导引箭 |
| `ENEMY_COUNT_IN_EFFECT_AREA` | 有限候选区域目标数达到TEST阈值 | 火球、多重箭 |
| `MELEE_THREAT_NEAR_SELF` | 有合法近战威胁在范围内 | 冰霜新星 |
| `ALLY_HP_BELOW_THRESHOLD` | 可治疗友军生命比例低于阈值 | 未来直接治疗 |
| `ALLY_UNDER_MELEE_THREAT` | 有合法队友受到近战威胁 | 野蛮人嘲讽 |
| `SUMMON_ALIVE_COUNT_BELOW_CAP` | 该召唤技能的本人存活单位数小于上限 | 骷髅、女武神 |
| `CURSE_NOT_EFFECTIVELY_COVERED` | 同种诅咒缺失或符合合法刷新窗口 | 伤害加深、降低抵抗 |
| `ACTIVE_AURA_EQUIPPED` | 当前有效槽内存在可维持的主动光环 | 祈祷、狂热、信念 |
| `CORPSE_AVAILABLE_WITH_TARGETS` | 合法未消耗尸体且附近有有效敌人 | 尸爆 |

**不做自定义脚本引擎**。超过有限条件库的需求优先看已有SkillEffect是否自带合法条件；实在需要再向用户申请增加一种配置语义，并单独附测试。

## 4. 预校验与Runtime复核

**加载期需要报错**：重复或空SkillID、条件ID/目标策略未识别、无对应Skill引用、非法Priority或阈值、测试夹具引用不存在角色、槽位非法、同时为同一槽装配两技能、非法武器（纯弓游侠）、循环依赖（若模型允许）。

**行动期正常跳过而不是报配置错误**：技能CD中、队友满血、怪物暂时不存在、召唤已满、已有效覆盖诅咒、AOE人数不够、射程外、当前被控。

**Runtime复核与诊断**：输入世界状态可能在筛选后/Commit前变化；AI生成意图时不能预先伤害、预先消耗尸体、预先开始CD。若Runtime拒绝，应留真实原因与确定性下次检查边界。

## 5. TEST_ONLY样例的使用说明

- `hero_loadouts_TEST_ONLY.csv` 中的槽位可用于 **隔离测试** 模拟技能槽已解锁，**不能将5槽强开写回生产星图进度**。
- `skill_ai_profiles_TEST_ONLY.csv` 的 `priority` 只用于测试确定性选择；不代表所有职业生产优先级已批准。
- `ai_test_cases_TEST_ONLY.csv` 每条都是“输入事实/期望请求”的测试契约，**不是 Godot 工程中已可运行的测试**。Claude应在 G0 审计后映射成现有 Core.Tests fixture。
- 相关 T 条件（治疗阈值、AOE覆盖人数、诅咒刷新提前量、召唤期望数量等）必须由测试上下文明确注入；没有正式产品审批时不允许使用 TEST_ONLY 值作为产品默认。

## 6. 推荐的诊断输出（非新接口强制命名）

| 字段 | 用途 |
|---|---|
| `tick` / `actor_id` | 确定时间与实例 |
| `main_target_id` / `selected_skill_target_id` | 观察目标分离 |
| `slot` / `skill_id` / `priority` | 看到技能顺序与槽位 |
| `candidate_result` / `reject_reason` | 为什么跳过当前技能 |
| `action_request` / `runtime_result` | AI选择与实际执行的区别 |
| `action_phase` / `cooldown_remaining` | 不被CD/动作假象误导 |
| `threat_reason` / `retreat_state` | 与受击退让/接敌AI交互 |
| `active_auras` / `active_curses` / `summon_count` | 团队持续能力与动态目标 |
| `evaluation_reason` / `decision_window` | 是否因为状态变化在合法边界重评 |

**长期挂机日志必须有界，可配置禁用/抽样/环形缓存（沿用已有诊断框架）；不要把每Tick候选遍历无上限写磁盘。**

## 7. 局部世界快照示例

`data/scenario_fixtures_TEST_ONLY.json` 提供10个更具体的 World Snapshot 语义示例（角色状态、部分CD、威胁、召唤数量和期望请求），用于降低Claude在编写测试时的猜测。实际C#测试不能直接把这些JSON对象当已存在的 `BattleSnapshot` 架构；必须经G0映射到真实构造器/Fixture。具体目标范围合法性、同Tick动作顺序及测试阈值在快照中属于受控输入，不代表正式平衡值。
