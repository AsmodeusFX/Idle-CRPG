# 01｜G0只读审计、历史规则对照与冲突审批门禁

## 0. 最高约束

**此文件不是立即编码授权。** 第一轮只读检索，输出证据与改造建议，**不得修改源文件、配表、存档、测试夹具或工程配置**。用户逐项批准 A1/A2/A3 后才能动获批文件。版本冲突、已有功能不明、需要替换接口/删除代码，必须先问用户，不按文档偏好强推。

## 1. 必须审查的真实工程模块（使用实际路径与代码行证明）

| 审计对象 | 必须查什么 | 容易冲突的历史口径 |
|---|---|---|
| `Game.Core` 战斗主循环 | fixed Tick、行动决策阶段、同Tick执行顺序、实体稳定ID | 不能在事件回调中递归决策 |
| `PlayerPolicy` / 公共AI | 已有优先级筛选、`NeedsReevaluation`、主目标锁定、射程移动 | 旧 `BATTLE_AI.md` 曾只支持单人上阵；当前是1→最多4人 |
| `ActionRequest` | `Move/BasicAttack/CastSkill/Wait` 或现行等价请求 | AI不是动作执行方，不能偷发 Effect |
| `Action/SkillRuntime` | `Ready→Windup→Commit→Recovery`、CD Commit时刻、取消、失败请求结果 | 不允许修改 CD 开始时机；原目标失效有已签合同 |
| `Skill/Effect/Buff` | 技能有效规格、治疗、光环、召唤、嘲讽、诅咒、前摇/打断边界 | G01–G06不可被第二套状态管理覆盖 |
| `TargetPolicy` | 单体、AOE、队友、随机/最近、召唤点/尸体合法性，现有筛选接口 | 技能目标与主目标锁定须隔离 |
| 角色技能配装/星图 | 已学与已装备的真值、1→5槽、被动、玩家换人审批 | 不得自动替换技能/升点/改星图 |

| 诅咒 | 不同主要诅咒共存、同种刷新/去重、Buff来源 | 不能自动互斥不同诅咒 |
| 房间/遭遇 | 敌AI启动延迟、小队入场散开、门口/攻击窗口、房间完成事件 | 不得恢复“进门怪物立即冲门”旧口径 |

| `Game.Core.Tests` | 决策确定性、CD、普攻、目标失效、多人并发、性能用例 | 无运行证据不能声称测试已通过 |

## 2. 需要显式提交的差异报告

1. **已有能力表：** `支持/部分支持/不存在/不确定`，每项附具体文件/方法/行号/测试名称；文档不能代替真实代码。
2. **行为差异表：** 已确认旧合同、当前代码事实、本包建议行为、是否真正冲突、风险与最小修改方案。
3. **审批阻塞表：** 一项一个 ID；给出选项A保留现状、B最小扩展、C调整设计，说明影响与回滚/迁移；**不可替用户选**。
4. **文件白名单：** 拟新增/修改/删除文件（包括表、测试、序列化）、具体理由；需要删旧逻辑必须附引用搜索与迁移验证。
5. **单一真值图：** 技能槽、AI决策、主目标、动作状态、CD、Buff、召唤、战斗事件各由谁唯一管理。
6. **测试计划：** 先存在什么测试、补什么、哪些只能 Godot Mini 验收、阻塞条件。

## 4. 禁止产生垃圾代码的工程纪律

- 优先扩展现有 `PlayerPolicy` 和当前已存在配置/状态对象；没有用户批准不新增 `AutoCastManager`、`SkillAIService`、`SmartTargetDirector` 等并行实体。
- 决策只生成已批准 `ActionRequest`；不得另造 `ApplyDamage/ApplyBuff/CastDirect` 快捷方法。
- 只有 `Action/SkillRuntime` 负责动作许可和 CD；只有 Buff/Effect 管状态和治疗；只有目标系统管理主锁定。
- 不为8怪物/17技能分别写17个独立AI控制器；只用已有参数、有限合法条件与少量专门策略。
- 配置版本迁移涉及稳定ID、存档和旧文件时必须先报审批；**不能因为标“废弃”就直接删除旧表/旧字段**。
- 需要替换既有方法时，提交旧→新调用点清单，确认替代路径正常后才删除冗余分支，最后跑全部回归。
- 严禁通过牺牲其他分支的合法结果让新测试通过，例如跳过技能 CD、禁用怪物、隐藏失败分支、硬编码当前测试角色ID。
- 一切运行结果必须注明真实命令、退出码、失败日志摘要、未运行原因。
