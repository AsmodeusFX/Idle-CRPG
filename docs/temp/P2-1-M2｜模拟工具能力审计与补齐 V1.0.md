# Steam D2｜P2-1-M2 模拟工具能力审计与补齐｜执行方案 V1.0

**执行对象：** Claude Code（当前 `Idle-CRPG` 工程）  
**阶段：** P2-1 模拟测试环境建设 · M2  
**前置状态：** P2-1-M1（AUD-001/AUD-002 入口死锁修复）已完成并回归。  
**本轮属性：** 测试工具开发；不做数值设计、不做数值投放、不评价系统强弱。

## 1. 目标与边界

在现有 `tests/Simulation/SimulationRunner.cs`、A/B/C/D/E JSON、Core Checks、`RoomCombatStats` 和正式 `GameSession.Tick(0.05f)` 的基础上，补齐一套**可复用、可配置、可追溯、能主动暴露异常**的模拟运行工具。未来正式数值填入后，沿用同一工具验证配置读取、机制运作和数值结果。

**本轮验收重点：**

1. 模拟玩家行为可以被**准确指定**，而非只能通过四个总开关近似表达；能解释“执行了什么、为何成功或被拒绝”。
2. 游戏发生异常时能自动给出有边界的**现场诊断**，能区分真实卡死、正常交互门槛、经验收益归零和战斗失败。
3. 关键收益与推进数据来自**正式运行事实**，有可校验的事件链和对账关系，不能靠余额快照臆测。
4. 输出统一、可复跑的机器数据与**一份有结论的 Markdown Review**。

**禁止：** 修改正式城堡手动点击规则；调整经验公式、怪物/英雄/技能/金币/星图数值；增加 GM 资源或跳关；新建独立战斗/经济模拟规则；为适配测试重构生产架构；依据现有占位数值提出平衡结论。

> 本轮不进行“全系统数值配置普查”。那是下一完整阶段的工作。此处仅建立**工具对运行系统的观测覆盖能力**，不得把计划中的未实现功能当作已实现。

## 2. 已知事实与遗留问题

- M1 已将房间入口死锁修复：A/B/C/D/E 单 Seed 240 分钟均无冻结；单人×8 Seed 未再冻结；旧死锁存档可恢复；Core Checks 与 Godot 无头冒烟通过。
- A 场景不点击城堡且 Lv7 对 Lv1–2 怪的经验等级差倍率为 0%，属于**当前正式规则下的纯挂机平台**，不可自动判为 Bug；正式城堡仍必须玩家点击。
- 修复后的 C/D 存在大量**合法战斗失败/重试**，不能与死锁混淆。
- 当前 E 场景无法准确指定“仅买 `s_root`、`s_party_1`、`s_party_2`”；实际运行采用了更宽的星图购买策略，**旧 E 与新 E 不能直接做严格数值对照**。
- 已有模拟事件/快照并不等于完整收益流水：逐次实得经验、经验分数精度、金币毛收入/支出、城堡真实开战和失败事件等仍需核实与补齐。
- M1 将 `RoomBoundary` 定为 0.01U、`MoveArrival` 为 0.001U；这是已批准的入口修复。本轮保留，不扩展到站位和镜头改造。

## 3. 执行原则（必须遵守）

1. **先审计当前代码，再补缺口。** 对以下内容逐一标记：已具备 / 部分具备 / 缺失 / 不适用，不重复建设现有统计、事件和校验。
2. **测试环境只模拟合法玩家操作。** 所有操作走正式接口、校验、支付和状态机；失败必须记录拒绝原因，不可静默视为成功。
3. **测试与正式运行隔离。** 行为策略、诊断和文件输出只在测试入口启用；配置默认关闭；不得写入正常玩家存档。
4. **单一权威事实源。** 事件优先取实际结算和真实状态变更；不得根据 CSV 预估怪物投放、根据当前经验条倒推累计有效经验、或把城堡“接受排队”当成“已开战/胜利”。
5. **异常应可解释。** 只因“600秒无击杀”发出可疑提示，不足以证明卡死。必须结合行动、状态、位移/HP/伤害变化、玩家门槛以及副本合法等待条件再分级。
6. **最小扩展。** 优先写在 `tests/Simulation/`；若必须向 Core 增加只读观测钩子、事件回调或有界计数器，先在 Review 中说明修改文件、必要性、性能和存档影响，获得审批再改正式 Core；不得为统计重写结算逻辑。
7. **结果版本化。** 数据带 Seed、场景配置、配置目录/版本指纹、有效策略摘要、代码版本（可获取则记）和模拟时钟。缺失信息必须写 `unavailable`，不可填 0。

## 4. 工作分解

### M2-A｜现有模拟能力审计（先完成，再动代码）

核对真实工程，至少包括：

- `tests/Simulation/SimulationRunner.cs`、场景 JSON 及加载校验；原 `--economy-sim` 的现状与是否仍有复用价值。
- 模拟策略：城堡点击、星图购买、天赋/技能配置、编队/职业解锁；运行中的调用频率、顺序、拒绝重试行为。
- 状态和统计：玩家成长、经验结算、金币结算、地牢/地图、怪物生成及击杀、失败与返村、Boss/城堡推进、已有 `RoomCombatStats`、存档及运行诊断。
- CSV/MD 导出、时间戳精度、Seed复现、异常提示、配置和四开关隔离。

先输出一张**模拟工具能力清单**：`能力 | 真实代码/字段 | 已有证据 | 缺口 | 最小方案 | 是否涉及 Core`。

注意：该清单是工具能力审计，**不是下一阶段的全部数值配置清单**。不要因为未实现的装备或商店玩法而判定 M2 不合格。

### M2-B｜可组合的合法玩家策略

保留已有四开关作为兼容入口，但增加**受校验的策略配置**（例如 `player_policy` 对象；最终字段由真实代码审计决定）。至少支持：

| 策略能力 | 最低要求 |
|---|---|
| 城堡交互 | 允许/禁止模拟点击；检查周期；记录解锁、请求、排队、正式进入/结束及拒绝理由 |
| 星图购买 | 可选择旧自动策略或指定 `node_id` 顺序、每节点最大等级、停止规则；按正式前置与金币约束执行 |
| 编队操作 | 配置职业候选/顺序与期望人数；只能编入已解锁且可合法上阵的角色；记录解锁但未编入的原因 |
| 天赋/主动技能 | 可选择不操作、现有自动策略或明确的合法节点/技能装配计划；尊重天赋点、行门槛和槽位 |
| 时序 | 每种动作可指定尝试间隔；保持确定性顺序，避免同 Tick 多动作导致不可解释差异 |

**关键验收例：** E 场景能够严格表达“只购买 `s_root` 1级、`s_party_1` 1级、`s_party_2` 1级（如正式前置关系仍如此），编入 warrior/ranger/mage，不执行额外天赋学习或技能装配”；所有前置、花费、实际购买列表均在报告中可核验。不能只把开关关掉后假称符合 E 原定义。

建议保留 A/B/C/D/E 的语义不变；若现存 E 文件实际内容与历史定义不同，**明确版本化或另建精确 E 场景**，不要静默覆盖历史语义。场景配置必须拒绝未知字段、非法策略名、不存在的节点/职业/技能或不合法的周期参数；合法但尚未解锁的目标应在运行时被拒绝并记原因。

### M2-C｜统一的事实级数据采集与对账

复用现有指标；缺项按“价值/成本”优先补齐以下**必要事实**：

| 数据域 | 最低输出事实 | 校验口径 |
|---|---|---|
| 运行与策略 | Tick/模拟秒、场景、Seed、实际请求/接受/拒绝/成功及原因 | 模拟时钟来自完成 Tick，禁止外层整数分钟代替事件时间 |
| 英雄经验成长 | 每个英雄的等级、当前经验**及分数部分**、累计**实得经验**、来源怪物等级、等级差倍率/零收益原因、升级事件 | 来自正式授予/结算链；余额不是累计经验；不得把 `0` 经验条认作“本次 0 经验” |
| 金币流水 | 战利品拾取、杂物售卖、其他已实现合法收入，星图购买、洗点及其他已实现支出 | `期初+分项入账−分项扣款=期末`，差额必须为0或有明示原因 |
| 战斗遭遇 | 真实刷怪/实际击杀（职业、怪物ID、等级、Boss/精英）、房间开始/完成、战斗时长、有效伤害/失血与死亡/复活 | 运行事实优先；规划预算和实刷数量严格分列 |
| 推进与阻断 | 地图/区域/POI/难度/章节、普通/城堡挑战开始与结束、胜败、失败返村、重试、不可继续的合法门槛 | `城堡请求被接受`≠`已开战`≠`已胜利`；失败和未采集不能记为0 |
| 技能与召唤 | 优先接入已有技能施放、AOE/治疗/补召、AI跳过与接敌容量汇总 | 不复制一套技能逻辑；没有可靠来源的字段标注未采集 |

可采用：`metadata.json`、`snapshots.csv`、`events.csv`、`ledger.csv`、`diagnostics.csv`/`diagnostics.md` 等组合；字段与命名以最少文件满足对账和分析为准。结构要稳定，有字段说明和单位。大体量逐击杀/逐技能事件允许按类别配置是否输出，但**完整内部累计数必须仍可对账**。

性能要求：禁止逐 Tick 把完整战斗状态写入日志；普通运行用事件/有界汇总，发生异常时只截取必要现场，确保 240 分钟模拟仍可快速复跑。诊断不进入正式玩家存档。

### M2-D｜自动异常诊断与分类

新增测试侧“可疑停滞”观察器，优先基于现有 World/GameSession 状态与 GM 诊断字段。要求：

1. 可配置监视窗（默认可沿用600游戏秒，**仅作为嫌疑触发条件**）；追踪至少击杀、金币、章节、移动/目标、房间/阶段推进、战斗伤害或 HP 变化。
2. 触发时保存**固定大小**诊断快照：当前 Stage、章节/POI/房间、门线与 `SpatialTolerance` 判定、英雄生死/坐标/速度/目标/技能状态、敌方存活与HP、追击/通行/等待原因、城堡门槛、重试/救援状态。
3. 结果分类至少：`MANUAL_GATE`（正常手动城堡门槛）、`XP_RATE_ZERO`（仍有战斗但经验0）、`COMBAT_FAILURE_LOOP`（持续失败重试）、`SUSPECTED_STUCK`（无合法理由的不进展）、`RUNNING`、`UNDETERMINED`。若存在多种情形，可同时带诊断标签，不要强迫单一根因。
4. 对 `SUSPECTED_STUCK` 生成明确证据：缺少哪项进展、持续多久、当前角色/敌人/空间状态；可以标记测试失败或警告，但不能在没有证据时直接宣称 Core Bug。
5. 同一冻结现场不无限重复打印；采用首次报警、限频复查和结束汇总。

**特别保护：** A 不点击城堡导致 Lv7 停升级，仍持续合法击杀/拾取，必须标记为设计平台而非死锁；C/D 合法失败返村不能被判定为永远冻结。回归用例应包含 AUD-001 旧卡门现场（检查器要能识别），修复后的运行不得误报。

### M2-E｜标准场景与输出规范

保持五个基础场景，并完善配置可追溯性：

- A：纯挂机，不模拟城堡点击/成长操作；**只用作无干预基线**，不得作为后续完整主线成长基线。
- B：模拟合法完整成长操作与城堡点击；当前脚本职业候选有限，必须在报告标注策略边界。
- C：单英雄，仅模拟城堡点击；允许合法失败重试。
- D：单英雄、合法天赋/技能成长、城堡点击；不强行补队员。
- E：**精确指定的最小合法扩编**；区分历史 E 和修复后的场景语义。

可新增最多 1–2 个针对**工具缺口**的定向场景，如：合法技能/召唤事件覆盖、明确购置列表/拒绝理由验证。不要以本轮为由制造几十个平衡场景。

采样建议：`t=0`、首30分钟每1分钟、此后每30分钟；关键事件始终用 Tick 时间。所有机器数据放在忽略的 `artifacts/` 下，不覆盖上一轮有价值的原始报告；工作报告按 `AGENTS.md` 规范只形成**一份 Markdown 统计/Review**并附可复跑命令与原始数据路径。无文件的引用不得写入正式归档。

## 5. 测试与验收

**M2 的通过条件是“工具能力补齐且准确”，不是“游戏内容/数值达标”。**

| 检查 | 必须通过的标准 |
|---|---|
| 工程构建 | 游戏/Checks 构建 0 错误；全量 Core Checks 通过；Godot headless smoke 通过 |
| 配置兼容 | 旧 A/B/C/D 场景仍可加载；未知/非法策略拒绝并给明确错误；默认关闭模拟操作 |
| E 策略精确性 | 实际节点购买、升级、花费、编队及技能操作**完全等于配置允许范围**；未经配置的额外操作为失败 |
| 正式接口隔离 | 所有城堡、星图、天赋、编队操作经过正式校验；正式客户端未获得测试自动化行为；玩家存档不受影响 |
| 事实/时钟 | 关键事件准确到 Tick；至少抽样核对经验实得、金币账本、挑战请求→开战→结果，不伪造不存在的运行事实 |
| 数据对账 | 金币每场全程收支差额0；英雄经验和击杀事件能够解释累计数，若不能则必须报告具体缺口，不得宣布“全通过” |
| 自动诊断 | 纯挂机经验平台、合法失败重试和 AUD-001 异常现场能够被区分；异常现场数据有界且足以复核 |
| 可重复性 | 至少B、C、E各双跑同Seed，关键机器输出规范化比较一致；文件名/时间元信息不参与业务一致性哈希 |
| 基本覆盖 | A/B/C/D/E 各运行240游戏分钟，记录运行结果和诊断标签；**不设具体等级、击杀、金币或章节作为验收阈值** |
| 报告 | 一份 Review：能力矩阵、补齐内容、修改文件、实际覆盖/未覆盖项、配置示例、测试结果、异常证据、下一阶段阻塞项 |

如果部分采集必须依赖 Core 改动，且本轮没有取得审批，应交付测试侧能完成的部分，同时列出 Core 只读扩展的最小接口提案；**不得将缺失采集以零值充数，也不得宣告完全验收。**

## 6. 执行流程与审批门

1. **先完成 M2-A 审计清单。** 以真实工程路径与代码事实为准；若现有架构与本文示例字段不同，优先复用实际实现。
2. **实现 tests 范围内的 M2-B/C/D/E 最小补齐。** 不改变正式规则与占位数值。
3. **如必须改 Core：停在审批门。** 提交 `调用点 → 只读字段/事件 → 用途 → 性能/存档影响 → 回归`，未经批准不动正式 Core。
4. 完成定向测试、全量回归、A/B/C/D/E 模拟和报告。
5. 对未通过的项写出真实原因；不在本任务中开始正式数值设计。
