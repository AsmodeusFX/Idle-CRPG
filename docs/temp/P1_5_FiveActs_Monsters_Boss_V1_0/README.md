# Steam D2｜07 五章节怪物与 Boss 内容配置执行包 V1.0

**本包定位**：在五章世界配置、P0-2怪物行为原型、P1-4玩家自动技能AI、P0-3职业BD和既有 Encounter/Floor/Skill/Effect/Buff 的上方，增加**候选怪物身份、区域投放池、POI绑定、Boss锚点和特殊阶段事件规则**。**不是一份覆盖已有地图、怪物或Boss代码的全量配置。**

## 最重要的状态区分

- `*_REFERENCE.*`：直接从已挂载的五章原始开发包读取后规范化的**源事实快照**。它们可供审计比较，但不能声称用户当前 Godot 项目仍逐字一致。
- `*_PROPOSAL.*`：本次建议的配置语义、怪物身份、区域投放权重、精英词缀与 Boss 技能候选；**不是已批准的生产数值或运行时ID**。禁止直接覆盖生产 CSV/JSON。
- 上游第一章 POI/拓扑 V0.5 有明确已确认部分；Act2–5 的老交付包中多处仍标为 `PROPOSAL_UNBALANCED`，本包不把这些标记擅自升级为正式批准。
- 用户的现有 Godot 源码是实施时的权威。第一轮只审计，不写代码；发生冲突先报告并取得用户批准。

## 核心源数据校验

- 5章：8×8、9×9、10×10、7×7、11×11世界地图；世界地图不刷怪。
- 42区域、231个 POI = 189 Dungeon + 42 Castle，跨三难度合计 1515 份楼层记录 = 505份单难度。
- 每一个 Castle 仍须按既有逻辑等待玩家授权；可选支线仍需单独授权；自动路由不变。
- `poi_id` 在不同章节**可能重复**。本包所有联结采用 `ACT##:<原PoiId>` 复合键，例如 `ACT01:A01-C01` ≠ `ACT02:A01-C01`。
- 五章原数据较大，**不重导入**，本包仅输出必要字段快照与来源 SHA256。工程实施时按项目现有源文件比对。

## 立即使用方法

1. 将本包置于工程外独立需求目录，不要先复制 `*_PROPOSAL.csv` 到生产 data 目录。
2. 让 Claude Code 阅读 `CLAUDE_CODE_FIRST_PROMPT.md` 并只读检索现有工程。
3. Claude 提交 **现有数据/行为映射、冲突列表、方案差异、迁移与清理清单**；存在冲突必须先向用户询问。
4. 用户批准具体切片后，按 `07_开发切片与完成定义.md` 编码、`dotnet build`、Core.Tests与 Godot 实机测试；提供代码 diff 与配置变更摘要。
5. 运行离线参考校验：`python data/validate_examples.py`。通过仅证明交接数据自洽，**不等于工程通过**。

**范围外**：不新建地面战斗、不改地图拓扑/关卡数量、不重做伤害与护甲公式、不增加第六种伤害类型、不实现全量任务/专属掉落、不改已存在 T01–T08 / 玩家自动技能 AI。
