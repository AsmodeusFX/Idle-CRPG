# R-A1｜WP4 固定四技能＋职业核心特性／旧技能槽体系退役

**设计Owner功能合同｜P0**。此项是原WP4授权内的遗漏补齐，**不能只关闭旧按钮而保留旧生效权威**。确切文件/API名以工程仓库调查为准。

## 一、概念与数据权威

| 名称 | 唯一职责 | 禁止复活的旧含义 |
|---|---|---|
| `ClassId` / `SpecId` | 定义该职业固定S1、S2、S3、S4技能集合＋T特性树，及本轮职业资格共享键 | 不可用作两个同职英雄个人学习状态的键 |
| `HeroInstanceId` | 个人Lv、天赋点、已学技能、互斥分支、CD、Buff/召唤来源 | 不能用`Heroes[0]`或同职第一个成员代替 |
| S1～S4（内部可仍叫`skill_slot.csv`） | **静态技能定义顺位**，每个职业恰好四个固定定义/允许标记尚未投放的原型数据空位 | 不是装配格数、不是玩家可以替换技能的槽 |
| T | 第5块独立职业特性天赋树，非第5个主动技能装备格 | 不参与主动技能数量上限或装配编辑 |
| 星图`class_trait_unlock` | Run金币按职业购买一次资格，同职业所有上阵英雄可分别投入T | 不自动学习、不分发免费额外点、不解锁全职业 |
| `TalentNode` | 独立英雄天赋点投资；前置、Rank、互斥及区域洗点 | 不由旧`CastTalent`在另一条权威施法路径直接触发 |

**内容与机制分离**：本次要保证合法定义与真实学习、AI施放、资格和UI行为。原WP4允许未全量投放职业技能；已有16条历史主动不意味着S06 V0.8的16条设计已实现。未实现的S2～S4必须显示为明确的未投放/不可学习状态，不得被空槽伪装为可购买槽，也不可令未学技能战斗自动施放。至少1名代表职业与第二名职业/4同职完成真实关键场景。

## 二、英雄页｜具体页面与交互

用户选中`HeroInstanceId`后：

1. **头部**：英雄名+实例序号、职业、等级、可用天赋点。顶部主四页签（游戏/英雄/星图/地图）不变，英雄页原有**装备子页签F-01**保留。
2. **技能子页**：按职业固定S1～S4四块显示，分别展示技能图标/占位、名称、类型、已学/可学/未达前置/未投放状态、当前CD或自动施放状态、关键效果描述、已投入Rank与互斥分支。S1固定为“开局已学”，普通区域洗点不可移除其基础攻击；S2～S4在合法消费天赋点后立即加入对应英雄AI调度，无“再装配”流程。
3. **T特性区**：在S1～S4之外独立显示该职业的特性树。未买星图资格→只读锁定，显示“需要在星图购买××职业特性资格”；已买→按该HeroInstanceId显示独立可投资状态。T没有装配开关。
4. **投资与局部洗点**：节点点击显示花费/前置/互斥冲突原因；同小树A/B不得双学；仅对当前技能区域免费清空该区域投入并返还正确点数，不影响其他区域或其他英雄，不退星图金币。失效Buff、召唤、动作、CD的清理由工程确保原子一致；读档或重选英雄后不应重复返还。
5. **废弃入口处理**：移除“编辑/装配/卸下技能”“技能槽数量”“技能装配上限购买”等玩家行为入口；若仍需编辑器工具，应只在隔离QA工具可用且不得改变生产存档/玩家配置。原来的“编辑技能”位置可变成只读技能说明或“天赋”页入口，不应出现可点击但无效的幽灵按钮。
6. **左下队伍HUD**：每位英雄有可见的已学技能及CD/自动施放反馈，固定S1不因洗点消失。未学S2～S4不显示为能施放，若显示灰位只表示学习进度且提供说明。同职业四实例技能CD不能同步错误。
7. **星图页**：不得销售`skill_slots`/`party_slots`；职业资格节点按ClassId显示“购买后本轮同职X人可分别学习”，扣Run金币一次，效果可观察；任何旧节点前置不能绕回槽位购买。

### 可复制给执行AI的状态矩阵

| 状态 | 四技能区 | T区 | 行为 |
|---|---|---|---|
| 初入Run Lv1 | S1已学；其余依内容标可学/锁定 | 资格未购、T锁定 | 能基础输出，不接受编辑技能装配 |
| 有天赋点、S2前置已达 | S2可学、消费成功即已学 | 不改变 | 下一次合法AI机会能触发S2 |
| 点数不足或互斥 | 禁止学习，显示确切原因 | 同左 | 不扣点、不产生Buff/CD |
| 同职两英雄、资格未买 | S状态各实例独立 | 两人都锁 | 互不改变 |
| 买该职业资格一次 | S状态不变 | 两人都可投资 | 不自动扣各自天赋点 |
| 仅一人投资T | 另一实例不变 | 仅一人已学 | 效果/来源只对投资实例生效（若设计为团体Aura则效果范围按定义） |
| 洗点某技能区域 | S1基础输出不丢 | T仅该区时才变化 | 收回该区点数、旧特效撤销，无双发 |
| 存读档和重生 | 同Run恢复；正式重生重置 | 同Run资格恢复；重生清空 | Account原有历史事实保留 |

## 三、旧功能与旧档价值迁移合同 LEG-01

执行前必须对下面**每一类**生成“代码位置→数据字段→玩家价值→迁移/隔离/退休方案→证据”清单：

- 旧`CastTalent` **23个**未绑定节点及其施法调用、UI点击、战斗AI选技、测试保留断言；新系统必须唯一决定“是否学会/能否自动施放”。
- 旧`SkillIds`、`EquipSkills`、`active_skill_max_slots`和编辑/解锁槽位入口；保留合法的技能定义ID、实例学习状态与必要历史存档读取，但取消生产运行时装配资格与数量控制。
- 星图旧`skill_slots`、`party_slots`节点的购买、消费、效果聚合、保存字段与前置引用。四个基础队员席位开局拥有；第五席是未来Account内容，不可由旧星图重启。
- 旧`talent.csv`已投资节点、旧星图已花金币和超四席角色迁移隔离区；**老五人冻结迁移已有[C]实现，不能因此次功能退役而破坏**。

**资金与价值规则**：不指定未经批准的统一退款金额或跨货币折算。可确定性映射的才迁；不可确定则保留原数据与额外隔离信息，记录方案/用户裁决项；新Run旧路径无可用购买或施法权威。迁移必须幂等：反复读取、重存、重生/放弃本轮不能重复补偿。不得为绿测试删除旧档或使不可解析时静默清档。

必须更新历史`SkillMigrationChecks`：从“23个旧节点继续存在”改为“已分类、已合理迁移/保存、生产路径已退休”的证据；旧测试历史基线留存但不再算新版正式通过。

## 四、技能实际有效的证明

`SK-02/SK-03`至少展示一名代表职业：未学习S2的固定Seed战斗没有S2动作→学习后AI自动选择S2并命中/产生真实Effect→战斗HUD图标/CD变化→局部洗点后不再施放（S1仍可用）→读档不复活旧Buff或重复特效。强制区分“UI已学”与“Core真的施放”。

`SK-06`四同职业：两人对同一合法目标施加同一BuffId，记录Buff的`SourceHeroInstanceId`/叠层或覆盖、失效及读档恢复，**按已有效的Buff同来源/跨来源规则结算**；如果现有解析无法正确选择目标，应先修正再验收，不用只提交“已选择技能并进入CD”代替Buff实际存在。

## 五、红线检查

- Core对外不能再次暴露玩家可用的`EquipSkills`或旧技能栏增购入口；若为了兼容保留同名方法，也必须对生产命令拒绝并有可追溯迁移处理。
- `class_trait_unlock`资格没买不得偷偷解锁T；没有部署对应资格节点时，原型测试的“缺节点不设死门槛”规则必须有明确配置环境边界，不能在生产内容启用后绕开资格。
- 旧配置不允许静默落入新的自动攻击队列；单纯移除 UI 不等于WP4完成。
- 不能为完成本次返修自行把S06 V0.8的候选技能、98节点或31星图全量强行上生产。
