## B1｜原型能力已存在的节点真实消费闭环

- 先接基础进攻/HP/AR/DR/公共XP、职业T资格、F01合法金币等，所有消费者复用现有唯一来源，固定种子QA中应有实际变化。
- 每Rank使用明确正数的**仅QA**参数；用A/B同种子对照证明差异，不得以UI文字变动代替真实行为。导出节点-原始/新值/Rank增量/来源Key及购买账本CSV。

## B2｜新增效果消费者/边界

按依赖顺序分切片，每片完成真实消费+回归再继续：

1. **目标与伤害/治疗**：O04元素合法分量、O05精英身份与额外伤害、D02真实格挡、D04治疗事件增强；无对应机制则强制BLOCKED，不允许把所有项替换为ATK%、DR或旧Armor。
2. **成长与收益**：G02精英合法击杀额外XP与一次性收据（可同模板重进领取）、F02安全出售金币、S01合法伤害卷轴实际增益，注意卷轴击杀掉同卷轴时库存守恒；公共XP/GOLD乘算顺序须唯一确定并出逐行账。
3. **药剂与旅行**：P01合法Tick延长、P02按真实药剂Effect提升、A01非战斗效率。A02/A03在C0无明确消费证据，保持`BLOCKED`直到提供有效原始延迟事件及有值对照；**不能为了开售额外增设等待**。
4. **F03**：仅在合法离线结算渠道有效，可作为离线玩家可选节点；纯在线十小时有效购买量不计入F03。
5. **G03**：保留`STAR_G03_QA_ENABLED=false`类似的隔离门禁接口（实际开关名称由工程决定），仅测试+1/+2/英雄实例、局部洗点、死亡复活、存读档、放弃Run；生产不可售。S02/S03/P03/C-NEC同样不可售。

## B3｜31节点交互、账本、两阵容可达性

- 验收矩阵每个可售节点至少包含：合法Rank1购买、Rank上限、每条OR前置合法路径和反例、差1金币、重复命令、存档重读二次、重开Run、无角色/重复同职、从禁售配置注入购买的失败案例。
- 每个属性类有无购/购买后/洗点或读档三方同种子对照。条件收益需提供正例和无效上下文的诚实提示；没有真实正例一律不计有效购买。
- 两条候选QA路线57次（四职）、55次（双游侠双圣骑）通过了**设计层Rank与前置**。实施阶段须用真实游戏购买事务跑通同样顺序，并提供`star_purchase_ledger.csv`、`star_effect_proof.csv`、`node_coverage.csv`，展示每一笔效果可观测。条件不满足时必须准确报告可买笔数，不得用禁售节点补足。
- 核心账本：`Run.GoldBefore - PurchaseCost == GoldAfter`、购买层级只+1、跨Run清零、旧已购隔离不补偿、同一节点重复尝试不扣款、另一同职实例不重复收费。经济购买能否在10小时赚到属于C3，不以QA作弊金币冒充。[P/H]价格保留受控测试，不能声称C3已批准。
- UI证据：至少四职业队、重复同职队、初始缺金币、上限、前置未满足、锁定/延期/G03测试门禁、职业特性购买后英雄页状态变化；真实Godot窗口+真实控件操作证据，截图/日志索引。
