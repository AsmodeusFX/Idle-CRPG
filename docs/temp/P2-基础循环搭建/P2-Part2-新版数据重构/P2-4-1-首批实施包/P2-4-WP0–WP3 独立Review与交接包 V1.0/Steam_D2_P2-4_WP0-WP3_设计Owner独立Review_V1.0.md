## 三、关键问题与处理建议

### R-01｜P1｜旧档迁移的“拒绝并保留”必须再细分

执行报告将925份互斥分为 `251 + 488 + 3 + 183 = 925`。488份拒绝中包含287份故意损坏、106份“旧地图版本”、95份“旧结构/字段”。后两类合计**201份**，其是否包含**曾经有效的玩家存档**尚未证明。不可因为“备份保留”便认定旧档迁移全通过，也不能认定这201份全部为真实故障。

**设计验收要求**：执行AI在现有WP1的Review下追加201份分类和至少代表性样例的旧版可加载性说明，区分①故意构造/测试遗物②已不再受支持但此前确实可玩③按批准兼容范围应能迁移却失败。对③给出不破坏存档的修复与回归。无需重跑无关内容。

**3份5人/候补旧档**须用户裁决，见§四A。裁决前保持原件/备份与可理解的迁移阻断提示是安全的临时行为，不能自动裁员。

### R-02｜P1｜WP1实例隔离的剩余链路要有定向证据

已有 `HeroInstanceId` 和召唤属主 `SummonOwnerInstanceId` 的报告。WP4要使用独立技能/CD/Buff/召唤，所以建议补测：**四个同职业英雄同时给同一目标附加同ID Buff时，来源键、叠层、失效与召唤名额正确**。只在旧Buff语义可支持的范围内验证，不提前批准新叠加规则。

### R-03｜P1｜技能/天赋点升级来源需闭环

WP2描述升级修改了Attack/MaxHp、AR/DR，但报告未明确显示“升级带来天赋点余额、保存重载后一致”的测试。WP4依赖此来源。要求给出升级前后天赋点/已分配点的定向测试；若实际尚未实现，归入WP4前置缺口，而不是记WP2全功能通过。

### R-04｜P1｜KP收据既要防重领，也不能误杀新遭遇的正常收益

当前收据结构含 `RunId:进场地序:难度:章节:种子:层:房:怪序`。先报告为已实装，但仅凭字段列表不能确认重复游玩同一地牢/同一房间坐标的新合法怪物会否与旧收据冲突，导致KP不再获取。

要求两个对照：
1. **同一已击杀怪物**反复触发领取事件→KP不得重复入账；
2. **新的一次合法遭遇**（即使重用模板/场地/Seed）→其新怪应正常获得KP。

如需要新增遭遇唯一实例号，技术方案可由执行AI自主实现；不得以限制正常重复刷怪代替去重。

### R-05｜P1｜真实UI图像证据未回传

执行报告列出 `artifacts/preview-combat.png` 及 `setup-1/3/4.png`、`specified-hero-upgraded.png`、`lmax-purchased.png`、`settings-abandon-and-clear.png`。当前附件只有Markdown，并无这些图片原件。下次对账请仅回传**1张整屏+关键交互前后对照的代表图**（不要求上传全部日志），至少能核对：顶部旧功能没删、卷轴横栏独立、右栏货币与成长卡、左下队伍与技能CD、右下药剂4槽、文字不溢出；以及升级/KP购买变化。

脚本 `FIRST_BATCH_UI_PASS` 是有效的自动化证据，但不能替代人工视觉/UE Review。卷轴、药剂当前PLACEHOLDER符合首批边界。

### R-06｜P2｜旧行为清理与测试策略更新

- 旧Armor不参与伤害已达首批关键要求；`ArmorK`/配置残留标技术债，WP4或相关回归包清理，避免旧数据字典再次成为权威。
- `SimulationRunner`仍不会手动升级，长周期数值曲线不可使用，必须在**P2-5模拟验收前**补玩家升级策略；当前XP/KP守恒测试仍有价值。

## 四、提交产品负责人裁决的2件事（不拖住其他包）

### A｜旧档含5人/候补时的迁移体验 [P]

- **推荐**：只针对旧版存档启用一次性的“超额英雄只读保留/冻结候补”迁移状态。新Run继续按4席创建；任何多余旧英雄及装备/天赋数据**原样保存在迁移隔离数据区**，不得被当作当前轮候补，也不开放重新编队；显示说明及以后放弃/重生时该隔离数据的去向。具体选择前不自动删失、自动挑选谁离队。此路径需可回滚和样本回归。
- 优点：不产生第五席可玩的新机制，也不直接阻塞可兼容的四人部分。代价：UI需清晰说明冻结者不可上场，且用户要决定是否保留供手动恢复/导出。这仍是产品取舍，**未批准不得实现**。
- 备选：仅拒绝并保护原档（最安全但用户无法继续）；或者允许老档临时5人继续旧Run（体验保值较强但对当前4席和第五席奖励体系形成特殊例外）。

### B｜KP提升Lmax后已生成房间 [P]

**推荐**：已经揭晓/实例化的怪物和房间内容保留既有快照，不因点击KP按钮瞬间刷新；**尚未生成具体怪物的房间首次生成时**采用当下最新 `[Lmin,Lmax]`，即使地图结构早已存在。再次进入已完成/已揭晓房间不得借此重开奖励。

此处理保留房间事件和战斗连续性，也让玩家能在进入下一间房时感受到KP升级；需要执行AI根据现有“地牢结构先生成、房间内容跨门快照”的事实证明“已生成”的判定范围，避免把整座早已生成的地图结构等同于“所有怪物已生成”。

**两项均为产品建议，不是设计AI替用户确认。**
