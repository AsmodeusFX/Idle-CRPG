# Steam D2｜S15首轮配置生产方案（准备阶段）V0.1

> 范围仅**首次Run的前四章、标准四人队约10小时**。S14跳过。此文是配置内容和工程消费接口的**生产方案**，不是已经可直接复制到正式游戏的生产配置，更不是工程实现授权。

## 1. 权威、环境与上线门槛

- **地图权威[C]**：P0原配置，前四章31城堡（25主线/6可选）、136普通地牢、226层Normal楼层。地图门禁/AND汇合/OR选择先按P0与有效设计补丁对账，不能拿候选表直接覆盖真实路由。
- **玩法权威[C]**：每Hero S1–S4固定技能定义，T职业特性树；公共XP手动分配；KP提高Lmax、AR/DR全员达标；唯一怪级区间；星图Run购买按职业解锁T资格；单主属性装备；卷轴/药剂操作规则。
- **内容建议[P]**：四职业16技能+四T、98天赋、31星图节点(78Rank)、31城堡战斗内容、136地牢投放、28装备模板、5卷轴/4药剂。
- **临时数值[H]**：H-B1/H-S08/H-EQ1/H-C1以及章节90/165/195/150分钟、Lv6/14/21/25。原型仅用于能否行得通的测试。
- **生产门槛**：任何 Effect/Trigger/Modifier无实现消费者、前置不合法、状态非法、跨Run双重领取、数值无法追溯源表时，**拒绝加载而非默默忽略**。

## 3. 从设计表到工程配置的标准工序

1. **ID和schema核对（执行AI只读调查）**。输出每列目标配置字段、枚举、效果消费者、类型/范围、是否已有实现、`ClassId`/`SkillId`映射；确保P0原地图ID和新版设计ID可追溯，不基于中文显示名关联。
2. **差异矩阵归类**。将每个设计效果分为`REUSE`,`CONFIG_ONLY`,`NEEDS_RUNTIME_SUPPORT`,`DESIGN_DECISION`,`DEFERRED`；不能靠写入CSV数据掩盖缺乏机制支持。
3. **建立隔离测试集**。从[P/H]源表变换生成候选CSV/JSON，只进`artifacts/qa/content-candidate/<version>`，不写旧归档、生产配置或正式玩家档。
4. **数据与逻辑双校验**。检查引用存在、前置无环、互斥合法、Rank价格覆盖、效应有消费端、给定同职组队不串来源、31城堡正确映射可选角色身份。
5. **沙盘→真实Core逐步替换**。用固定Seed记录每章节实际击杀等级直方图、XP/KP/金币、装备候选、卷轴/药剂使用、Castle尝试、TTK、死亡与重新挑战次数；先比较数学模型误差，再改数值，不靠更改已确认机制拼目标。
6. **正式参数审批关口**。设计Owner提出最终[H]→[P]→[C]的数值表变化和风险解释，用户批准后由执行AI导入并验证。当前没有自动授权这一步。

## 4. P2-5A正式体验验收情景

- 1人、4人、4同职业、四职业混编；四章25主线城堡及6可选城堡隔离测试；合法路线AND/OR前置不被破坏。
- 至少100%、80%两种有效击杀压力；主章90/165/195/150分作为观察目标而不是预置脚本的必然结果。
- 检查第二章XP阶段性缺614和金币阶段欠账（当前H-E1情景），不允许偷偷自动升级/免门槛/从未达到的后章领取资源。
- 角色最低自然AR/DR能够达到31档Lmax；Lmin保持1直至安全设计批准。
- 星图57/56的每一笔购买对应实际效果；有不支持的节点就调整有效容量统计，不声称60笔体验已存在。
- 必须区分前台、后台运行、完全关闭离线；不能把离线固定配额[H]当正式游戏收益。卷轴/药剂不作为Boss唯一必需解法。

## 5. 阶段交付格式

- `S15_config_provenance.json`：每个来源文件SHA256、行数、状态标签及转换目的（本包提供）。
- `schema_diff.md`：各内容表当前工程字段对比、缺失消费者与实现建议（需执行AI读取当前源码后输出）。
- `candidate_config/`：**未来**待审测试配置，由执行AI按授权转换；目前本包只有设计参考副本，不伪装成可执行配置。
- `load_validation.log`／`runtime_events.csv`／`experience_10h_report.md`：未来测试与数值验收结果；本轮不预填PASS。

## 6. 本次文件用途

`reference_only/`下的CSV仍带[P]/[H]，目的为**保持现有S06–S13成果可直接追溯和逐项迁移**，不是正式配置；修改它们必须先回源表确认，禁止执行AI盲目复制到`config/`。
