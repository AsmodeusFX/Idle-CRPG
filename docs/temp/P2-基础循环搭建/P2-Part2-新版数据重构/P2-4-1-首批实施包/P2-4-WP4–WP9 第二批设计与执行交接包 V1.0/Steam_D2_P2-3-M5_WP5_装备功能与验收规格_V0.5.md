## 0. 体验目标与边界

- [C] 玩家在自动战斗中看到装备掉落，右侧获得“可以变强”的换装机会；**穿戴必须经玩家点击**。不自动强化、不自动装备。
- [C] 仅本轮实际上阵的英雄实例获得个人绑定装备；允许四名同职业仍完全分开背包归属与穿戴状态。
- [C] 首轮**六部位**，每件有装备等级、四品质（普通/稀有/罕见/传奇）结构；装备主要改善ATK/HP及TTK/生存，不得变成KP自然AR/DR评级资格的唯一可靠来源。
- [C] 回城自动出售前保护每个“英雄实例×装备部位”的更优候选；旧件/杂物按已批准售卖规则出售。
- [C] 同时存在**至少5个不同的（HeroInstanceId, Slot）**可替换项时，右侧出现一次主动“批量换装”动作，展示“谁、哪个部位、原值、目标值”；仍允许逐件点击。
- [P] 六部位暂命名为`武器／头盔／胸甲／手套／靴子／饰品`，仅为UI/配置原型命名，未锁正式世界观名称。
- [C] 首轮每件先只有一种主属性（ATK或HP），便于单调比较；装备等级与品质值均由配置承载，**不在M5预设掉率、价格或强度倍率**。

## 1. 最小可实现数据合同（工程具体结构由执行AI自主适配）

| 数据域 | 要求与归属 | 状态 |
|---|---|---|
| EquipmentDefinition | 物品定义ID、可装备Slot、itemLevel、quality、主属性类型/可配置数值，合法取值校验 | [P]最小结构 |
| EquipmentInstance | 唯一实例标识、Definition/生成结果、`OwnerHeroInstanceId`、所处状态（掉落/候选/已穿/可售） | [C]实例独立，[P]字段形式 |
| HeroEquipment | Run内按`HeroInstanceId × Slot`持有当前穿戴物；同职业不可互串 | [C] |
| LootCandidate | Run内待处理更优候选及必要的来源，跨房间、回城、保存后不会因为未点击而消失 | [C]保优候选，[P]容器形式 |
| GoldLedger | 装备旧件/杂物出售获得金币，回城交易事件可追溯 | [C]金币价值链，[P]事件格式 |

建议一次只保留**每个英雄实例／部位的最佳可客观比较候选**；如玩家看到不同属性取舍而无法确定优劣，则进入人工查看区，**不得误判并自动出售为垃圾**。[P] 该建议减少仓储爆炸，并非用户已批准“只保留一件”的通用背包上限。

## 2. 状态机与主链路

`怪物被击杀 → 按规则生成掉落 → 绑定上阵英雄实例 → 掉落/拾取 → 进入待处理装备 → 比较当前穿戴 → (更优候选→保护并触发右侧换装提醒；其他→按回城售卖规则处理) → 玩家点击单换/批换 → 穿戴状态与属性快照刷新 → 被替下的旧件进入可售集合 → 回村售卖 → 金币入账`

### 2.1 掉落与拾取

1. [C] 掉落对象的身份必须是**实际已选择进入本轮的英雄实例**，非`SpecId`；相同职业每个实例均可成为归属目标。
2. [P] 引擎先确定物品定义/等级/品质，再分配合法Owner；任何非法或已不在本轮的归属一律拒绝，留失败事实。
3. [P] 掉落尚在地面时不进入已穿/候选资产；拾取成功恰好转移一次所有权，避免重复拾取。

### 2.2 “更好”的判定与不自动穿戴

- [C] 当候选与当前穿戴部位的**主属性同类**时，主属性数值严格更高定义为“客观更好”；数值相等不自动触发替换。无穿戴时合法候选可换。
- [C] 不同主属性（例如ATK对HP）与未来多属性装备属于玩家权衡，**本包不使用隐藏综合战力评分自作决定**。显示“可比较/需手动判断”而非偷偷纳入批量。
- [C] 评级附加AR/DR即使存在，也不使随机装备成为正常KP升档的唯一途径。
- [C] 玩家在右侧点选前，任何拾取、回城、自动售卖都不改变穿戴属性。

### 2.3 回城候选保护与出售

- [C] 自动售卖必须在计算并保存受保护候选之后执行。不能把“未装备”当成“应出售”。
- [P] 每个英雄每个部位至少保护当前最好候选与现穿装备；多属性不可比较件保留给人工查看或另设安全白名单，不能静默错卖。
- [P] 非保护物品与已批准杂物可在回城出售，金币入账必须有物品集合、数量、总价、事务ID对账。
- [P] 背包/仓位溢出处理在工程调查中给出实现候选；不能默认丢弃保护候选。

### 2.4 单件与批量换装

- [C] 单件替换由用户直接点击具体角色部位，实时检查物品还存在、属于对应实例、未被消耗/出售，成功后原子交换与属性刷新。
- [C] 批量门槛为“**5个或以上不同`(HeroInstanceId,Slot)`**”，不是5件同槽掉落、不是5个英雄，也不是库存中5件总量。
- [P] 批量只包含客观更优项，展示清单可展开到全部明细。若点击瞬间已有一项失效，**拒绝整个批量并刷新清单**，避免部分执行却表现为“全部成功”；是否允许用户取消单项可后续UX验证。
- [C] 不与英雄升级、KP消费、城堡按钮合并。

## 3. UI位置与状态

- 主界面固定七分区（M5主界面V0.5）；装备**通知/快捷操作在右侧成长队列**，英雄装备详情可在顶部“英雄”页查看。不得删除左下小队状态栏和技能CD区。
- `0候选`：无换装提醒；`1–4不同键`：独立换装项；`≥5`：批量按钮，清单显示`英雄身份+部位+当前主属性→目标主属性`。
- `同槽多件`：只计一项，打开明细可查看备选；`跨属性不可判优`：标“需比较”，**不误入批量**。
- 更换完成：右侧待办数量更新、左下英雄相关属性/战斗快照刷新；金币变化只在回城真实售卖时更新。
- 截图/录屏至少覆盖：同职业四英雄、0/1/4/5不同键、不同品质、跨属性、回城卖出前后、保存重载。

## 5. 需在WP5实现前裁决/定案的最少项目

- [O-装备1] **六部位名称与槽位编码**：建议沿用`武器/头盔/胸甲/手套/靴子/饰品`。编码细节可执行AI自定，玩家看到的名称由设计Owner确认。
- [O-装备2] **不可客观比较装备的回城保留方式**：已明确原型每件仅一种主属性，但不同装备仍可能是ATK与HP之间的取舍；**不得自动售卖跨属性待判断候选**，建议保留并提示人工查看。候选保留数量/容量是[P]实现方案，不在此擅定。
- [O-装备3] 卸下/手动保留多件旧装备的玩家自主权：首轮原型可以限缩操作，但**不可无说明把所有旧件都当应出售**。
