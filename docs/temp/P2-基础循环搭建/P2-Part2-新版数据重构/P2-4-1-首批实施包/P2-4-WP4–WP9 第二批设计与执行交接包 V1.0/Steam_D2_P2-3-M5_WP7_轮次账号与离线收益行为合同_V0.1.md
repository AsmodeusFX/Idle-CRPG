## 0. 目标与本轮边界

仅把三类行为说明白并能测试：**关闭/重启游戏后的有限离线收益**、**一轮完成与主动正式重生**、**账号永久数据和本轮数据严格隔离**。

不在M5设计AP完整商品、最终数值比例、第五席价格、新职业全部技能、正式首轮总时长。P2-4应做能观察、能保存、能模拟的最小真实机制；P2-5A再专项确认收益和消费规模。

## 2. 四种玩家操作应明确分离

| 操作 | 玩家可见条件 | 允许改变 | 不允许发生 |
|---|---|---|---|
| 普通继续游戏/读档 | 已有有效存档 | 恢复Account、Run及待结算离线窗口 | 重复发离线收益；自动升级、自动买星图/KP |
| 放弃本轮并重选队 | 玩家明确提出且确认 | Run清空，开启新轮；Account保留 | 领取“已通关重生”奖励；误清账号永久权益 |
| **正式重生** | [C]首轮完成第4章；后续轮次按正式章节终点；玩家明确点击 | 结算**已获批**的永久价值、记录有效轮次；Run清空后新轮重新选队 | 自动重生、重复领取通关奖励、提前开放未获资格的第五席 |
| 清除全部进度 | 设置/调试中的专门操作 + 强确认 | 全部账号和本轮进度清除（另保留独立客户端设置） | 与普通重生共用含糊按钮、静默清档 |

[P] 完成首轮第四章时，右侧交互区显示“可正式重生”的**独立待处理事件**。玩家可以暂不点击而继续查看本轮状态；是否允许继续反复刷该章属于内容/时间轴细节，不影响“不得自动重生”的底线。

[P] 在最小功能原型中，可配置**测试专用的永久奖励或账号事实标记**来验证重生事务；必须显式标记`QA/H`，不冒充正式AP经济或上架奖励承诺。

## 3. 离线收益最低合同

### 3.1 在线、后台和完全关闭的区分

- [C] **前台/切后台但进程持续运行**：继续进行正常自动战斗与挂机；收益仍进入Run；不自行把后台运行改成离线结算。
- [C] **完全关闭游戏**：再打开时对一个有限时长窗口结算离线收益；起步约2小时仅是当前方向值，不是已批准精确秒数或效率系数。
- [C] 离线不得替玩家执行任何需要选择的操作：英雄升级、天赋学习、穿装备、星图或KP消费、卷轴手动施放、药剂使用、城堡发起、重生/换队。
- [C] [WP6]药剂Buff按**有效游戏运行时间**消耗，完全关闭期间暂停剩余时间；拾取瓶或使用中的瓶仍占槽，读档时同种灰态和禁并发保持。

### 3.2 离线结算的工程机制边界

- [P] 使用**单次结算事务**：记录离开时刻/已结算截止点；再次打开按上限、合法收益类型和离线期间的有效状态计算；提交资产与结算标识必须具备原子性，保证崩溃重开不重复领取。
- [P] 离线进账先进入Run公共XP/金币/KP等合法余额；无英雄等级自动变化，也不改变当前怪物`[Lmin,Lmax]`、城堡与章节进度。奖励的精确取值和算法先由可配置接口控制，不写死M3代理数值。
- [P] 离线结算面板显示“离线经过时间／有效结算时间／资源分类／上限说明”；结果能在资源账本、客户端快照中核对；不得只弹一个无法查证的总战力值。
- [O] 装备、卷轴、药剂是否进入首版离线掉落以及其背包容量、最佳候选保留和满槽规则如何执行，仍需结合WP5/6内容与用户裁决；**未批准时不得偷偷授予或丢弃**。
- [O] 成就点在离线有效挂机时是否与在线同规则产出，以及具体额度/章节加成尚属账号经济设计；工程预留可追溯事实和计量接口，不擅自记正式可消费AP。
- [O] 离线XP/KP/金币采用固定收益折算、离开前有效击杀率快照还是受限真实遭遇重放，其机制影响“离线时能不能刷过更高档敌人”；首轮建议以可审计的可复现实测函数为目标，实际算法由工程提出并在P2-5A收益定标前验证。

### 3.3 不变量与异常

1. 同一时间窗口，**最多一次**离线收益结算；双启动/崩溃恢复/关闭并重开不得重复入账。
2. 离线结算发生于**当前合法Run**，不能跨越“放弃本轮/正式重生”边界将旧轮收益追加进新轮。
3. 离线结算不会推进需要玩家主动确认的核心成长和章节进度；绝不自动提升英雄等级或赋予星图、装备战力。
4. 真实有效挂机失败/收益为零的状态不应被结算器凭空变成最高档收益；对离线收益率的推断必须可记录输入和说明。[P]
5. 时间戳异常、系统时间回拨、极长间隔或存档损坏时，优先**防重复发奖与保护原档**，不可静默重置全账号；实现防护由执行AI据证据自主决定。
6. 药剂余时与离线经过时长**分属不同计时逻辑**，完全关闭游戏不会减药剂余时；在线与后台有效Tick会递减。

## 5. 与WP1、WP3、WP5/6的边界

- WP1交付Account/Run结构、稳定英雄实例ID、合法迁移和事务存档接口；**WP7不另造第二份账号权威**。
- WP3提供城堡与章节完成事实，并且城堡准入仍按`Lmax ≥ RequiredMonsterLevel`；WP7读取事实，不能添加新的“已击杀同档怪”前置。
- WP5/6提供装备、卷轴、药剂的Run库存与增益生命周期；WP7负责离线与重生时的状态归属，不自动把离线物品写入未批准的背包规则。
- 完整成就商品及第五席价格仍待后续设计；除非用户另行授权，否则不能以WP7原型权限擅自公开新永久商品。
- 各UI任务需遵循用户确认主界面七区结构，并保留原有效入口；真实截图证据用于设计Owner异步Review。
