# C3首轮600分钟实验的关键真值核验

## 需要先区分三件事
A. 当前生产确实在何时不能进入下一城堡；B. 模拟器是什么操作策略；C. 即使模拟操作正确，原型怪物密度/伤害/收益是否符合设计。当前报告只支持“10场全未到第四章”，不支持“应该立即提高全部XP/KP价格”。

## 重要的操作数算术（供核实而非臆造规则）
- 四名英雄**从Lv1→Lv5**：每人4笔升级，共**16笔英雄升级**，并非20笔单独英雄升级；若Run的Lmax从1→5且每次只+1，则再有**4笔KP升档**，两种命令合计**20次购买/升级动作**。还没包含其它星图、天赋、装备点击。
- 四名英雄Lv1→Lv25共96笔英雄逐级升级；当前“10分钟一次会话且每周期只升一个人一级”的600分钟脚本最多约60次，根本不能完成96笔；45分钟最多约13笔。这是*脚本操作预算*，不是玩家实际上不允许每次回流连续点多次。
- C3报告P4 seed3301 10min剩公共XP103448但平均只Lv15–16；45min剩40294但平均Lv4–5。这是策略限制强迹象。**注意：有XP余额不代表下一升级必定付得起，也不能忽略KP、评级与城堡准入。**
- P4(10min)在第480min首次进入第二章，600min末有11605次击杀；历史“11189四章必经静态击杀”是计划工作量，并非实跑击杀上限。应分解重复地牢/重试/可选/房间来源，不能据此判收据错误。

## 工程本次只读需出哪些证据
1. 真实第一章第一座被挡城堡的`chapter + poi + 配置门槛 + UI文案 + CanChallengeCastle`路径；区分仅Lmax门槛与章节/统治区其它前置。按真实需求分列AR/DR最弱者、不足哪一级、当前XP、KP和可达升级笔数。
2. 每次“玩家回流”：模拟策略允许几次UpgradeHero、BuyStar、BuyKpUpgrade、LearnTalent、EquipCandidate、UseScroll/UsePotion、ChallengeCastle。没有模拟的命令标`NOT_MODELED`，禁止从缺失策略推断最终经济表现。
3. 战斗密度：`spawn_rule`名额、`floor_rhythm`偏置、实际每房怪数分布、清房秒数TTK、S1-S4在清房期间启动次数；至少给首章代表性房间与第一城堡附近房间、固定Seed与配置指纹。
4. 事件流分解：按章节 `entered_at/cleared_at`，在POI、楼层、房间层级区分`combat`、`move`、`wait_for_upgrade_or_kp`、`castle_blocked`、`death_retry`、`repeat`、`optional`；既有事件不足则明确不可用和将来补采的最小字段。
5. 资源流：公共XP余额和逐笔消费、KP入账与购买、金币及星图入口根与真实价、装备手动穿戴/出售、ConsumableUse、同Seed资产账本；每个抽样点标实际运行还是静态。
6. 边界：`herolevel.csv`与`monsterlevel.csv` 10000行 ≠ 已确认长期设计硬上限；H-B1 Lv25/31先作为首轮里程碑候选进行审计，不改生产。
