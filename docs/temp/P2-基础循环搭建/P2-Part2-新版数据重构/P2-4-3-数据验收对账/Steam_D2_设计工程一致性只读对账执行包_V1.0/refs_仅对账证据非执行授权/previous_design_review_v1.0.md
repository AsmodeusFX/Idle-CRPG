## 核心发现 1：操作策略在数学上限制了成长
报告：P4 10min 600min最终 `16/16/16/15`，余额103448；P4 45min为`5/4/4/4`，余额40294；单人10min Lv60。旧WP9的`ExecUpgrade`规定每次策略动作仅一名英雄+1级；C3仅加Lmax动作，未见多升级动作。
- 10min/600min约60机会，四人起始Lv1总等级4，每次仅+1级，理论上总等级最多64；报告总等级63，表示实际59笔升级（时间取样/启动偏移容许1次差异）。四人全到候选Lv25需96笔，脚本绝不可能做到。
- 45min/600min约13机会，初始总等级4，报告总等级17，恰好13次。
- 因此报告“玩家每10/45分钟回流”与“每次会话只能购买一个升级”错误绑定。该限制不属于[C]产品操作规定。正常玩家一次回流可选择连续多次单名升级（每笔依然是一次真实点击），而不是在后台自动升级。
- 大量XP余额使“XP短缺导致600分钟卡关”当前缺乏证据。要先重跑可消费全部合法XP的玩家动作策略，再诊断真实资源不足。

## 核心发现 2：章节结果与静态预算不能直接比较
P4/10min两个Seed在第480分钟首到第2章；P4/45min十小时仍处第1章；P1/10min第210min首到第2章、第360min首到第3章。**章节列记录进入该章，而非通关；采样30min一格，时刻只是采样精度。**
P4/10min在仅进入第2章的600分钟场景累计击杀11605，已经超过旧静态四章必经计划量11189；这两者不是同一统计口径。必须拆分总击杀为首次必经、合法复刷、Boss重试、可选内容与其它，并按章/POI逐项核实是否存在导航循环、地图卡死或内容膨胀。不能简单得出“必经四章需要11605击杀”。

## 核心发现 3：尚未充分消费C1/C2有效内容
报告明示升级、星图**根节点**、城堡、Lmax定时检查；未提供57/55星图路线、8套天赋合法构筑、装备/卷轴/药剂手动QA点击作为600min连续策略的结果。报告把可选内容、装备策略与耗材策略列为ACTION_NOT_MODELED。此乃模拟器缺失显式点击代理，不意味着可以/应该在正式游戏开放自动使用。C3设计原规格要求“自动战斗 + 显式模拟玩家操作”，并不禁止QA模拟脚本在既定周期内连续发出真实玩家命令。

## 核心发现 4：不要把候选目标变为未经批准的硬封顶
工程提议：`lmax_cost`10固定→14/28/42…，`herolevel.exp`18×等级→候选1→25累计54120，生产10000级英雄/怪物表→硬上限25/31。它们全属于[H/P]候选且对资源与后续轮次价值有重大影响。`Lv25/Lmax31`至少应先区分“第一轮设计目标范围”与“绝对等级硬上限”，不能从目标数字推导永久封顶。更高XP成本可能使本来脚本操作限制造成的停滞更严重，不宜三项一起批准。
