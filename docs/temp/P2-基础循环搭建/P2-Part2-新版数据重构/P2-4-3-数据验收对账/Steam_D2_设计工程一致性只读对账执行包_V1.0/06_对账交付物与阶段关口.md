# 交付物、双Owner对账闭环与聊天迁移门槛

## 工程执行AI交付（必须来自真实工程、机器可读）
- `recon_master_matrix.csv`：按种子清单逐项写设计/实际/证据/差异/责任主体，不留空白PASS。
- `recon_design_id_crosswalk.csv`：逐S06 16技能+4T、S07 98节点、C1B 31星图及相应Rank、C2A P0/城堡/Boss源、C2B 24实投+4废止、5卷轴+4药剂、31怪级、C3参数源；每行DesignID→ProductionId→Config→CodeConsumer→ObservableTest。
- `recon_runtime_chain.csv`：公共XP、等级、AR/DR、KP、城堡准入、刷怪/TTK、装备/消耗品/星图、存档与四章Boss的运行消费者及读写归属。
- `recon_user_observations.csv`：对应`05`的每项用户观察，有复现/截图/反证说明/未证实状态；不得把用户意见改写为工程PASS。
- `recon_c3_assumptions.csv`：600min每次动作策略、允许动作、未建模维度、样本数、Seed、元数据哈希、时间与产出字段。
- `recon_evidence_index.csv`：证据绝对/项目相对路径、命令/退出码、输入配置指纹、产出hash、截图或帧锚点、是否仓库可复现。
- `recon_conflicts_decisions.md`：已确认设计与生产冲突清单，以及哪些尚无足够设计文本或用户裁决。
- `recon_summary_for_design_owner.md`：一页结论：MATCHED、IMPLEMENTED_DIFFERENT、NO_CONSUMER、PENDING_USER等数量；Top P0/P1；需要用户确认的最小问题；下一轮建议整改/实验切片（仅建议）。

真实结果仅写入`artifacts/qa/s15-c1-c3-recon-<stamp>/`；工程唯一Review追加§32对账小节，附复跑命令、环境与数据文件指针。此时**仅标[E]工程审计完成，不能代写设计AI或用户通过**。

## 设计Owner接到工程回传后承担（本聊天继续）
1. 核对工程新证据与每项最新[C]/[P]/[H]、S06–S13设计、用户观察的对应关系，至少逐项检查P0/P1，覆盖所有关键DesignId。
2. 发出“统一有效设计与生产差异映射”版本，包括旧设计已覆盖项、双方认定一致项、实际功能尚缺项、设计自身需补规项及实机体验延期项。**一致不是让设计盲从现网，也不是要求先改所有代码。**
3. 对真正妨碍基本推进/经济合法性/读取存档的问题提出最小整改包，先请用户决定是否实施；对于UI美术与全面调优另排，不给本次只读包扩权。
4. 若用户要求“达到无严重全局卡关的可观察首轮形态”，再由设计Owner输出限定范围的数值/交互修正需求、工程执行/模拟/真实窗口验证；在该阶段门槛完成前不能宣称体验达标。

## 迁移聊天至少需要的双边材料
**工程执行AI的独立冻结包**：当前工作区版本/提交/非提交差异、源码与生产配置SHA、最新模块唯一Review、逐ID交叉表、运行命令/复现数据/截图索引、已知问题/回滚及存档迁移边界、当前授权与禁止范围、给设计Owner的对账摘要。

**设计Owner的独立冻结包**：有效产品纲要及最新用户裁决、按DesignId统一的C/P/H/E/V权威表、C1–C3的终版设计—工程差异判定、可延期用户反馈清单、数值验证状态、开放决策及下一阶段范围、源文件索引与优先级、跨聊天开场指令。

**用户最终确认**：①至少P0关键设计—工程偏差已辨清并做出“修正/保留/暂缓”的显式决定；②不会把全局卡关当体验已通过；③双边材料能够复现；④新聊天首项任务、禁止内容、待批准事项明确。**这四项共同构成“可以迁移”的关口**，不是设计AI自行宣称迁移完成。

> 对账完成 ≠ 必须先修完UI ≠ 10小时验收通过。若用户希望在迁移前达到“首轮基本可推进、没有完全卡死”的体验目标，必须另设一次最小体验验收关口；这是一项明确、可选的用户阶段决定。
