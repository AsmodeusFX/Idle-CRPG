# 03｜配置接口、运行时状态与示例数据约束

> 该文件属于**接口建议 R / 当前真实 schema 待审计 T**。**严禁**仅按本文创造新的生产 CSV/JSON 数据结构和公共 DTO。先检查实际配置、加载器、资源引用、战斗事件/命中属性，再产生最小差异方案。

## 1. 复用优先顺序

1. `SkillDefinition` / `EffectiveSkillSpec` / `SkillRuntime` 的现有定义（如存在）。
2. `Effect` 标准类型与注册/读取入口（伤害、治疗、应用 Buff、投射物、召唤等）。
3. `BuffRuntime` + `AttributeModifier` + Dirty 快照机制。
4. 已有 `TriggerRule` + 确定性 `EffectQueue`；原有 DMG1/DMG2/DMG3（4+1）不可替代。
5. `EntityRuntime` / 角色团队/召唤物、`PlayerPolicy` / `MonsterPolicy`、`ActionRequest`、Encounter/Room 生命周期。
6. 原有 `CSV / JSON / Godot Resource` 混合数据规范与强类型校验；游戏显示资源始终和 Core 决策隔离。

若当前源码不含某项，不得自行把“假想模型”当成需要直接创建的新模块。先提交能力缺口及几种方案的修改文件/测试成本。

## 2. 技能数据最小信息的**语义**（并非必设字段）

| 语义 | 应能表达什么 | 权威归属建议 |
|---|---|---|
| 稳定技能 ID / 学习资格 | 职业、系别、主动/被动、学习层级、前置 | 现有技能/天赋配置 |
| 装备到技能槽 | 普通主动、召唤、主动光环需占槽 | 角色配置与星图解锁验证 |
| Cast/AI 意图 | 条件、当前主目标或技能独立 TargetPolicy、合法射程 | `PlayerPolicy` + `SkillRuntime` |
| 动作时序 | Windup/Commit/Recovery、CD从Commit起 | `SkillRuntime` |
| 离散效果 | 直接伤害、区域、投射物、ApplyBuff、Heal、Summon、ConsumeCorpse等 | 既有 Effect 执行器/合法扩展点 |
| 技能变化 | 技能等级调整系数；独立天赋追加已有标准 Effect | `SkillModifier` |
| Buff 生存/来源 | 生效主体、目标、来源技能/实体、作用域、刷新/叠层策略 | 既有 `BuffRuntime` |
| 召唤物属性 | 类型、主人、合法继承、数量与跨房间持续状态 | 现有 Entity/Summon/Encounter |
| 事件链来源 | 原 Cast/Hit/Kill、来源实体/技能、派生深度、目标去重 | `TriggerRule / EffectQueue` |
| 尸体消费 | 来源怪物、房间、唯一消费资格、消费时原子状态 | 现有死亡事实/Encounter 可复用处 |
| 调试与表现 | 来源、拒绝原因、技能行为标签、Godot 表现标识 | 事实映射/只读诊断 |

## 3. Buff / Modifier / Damage 类型映射

统一伤害仍为 **4+1**：

| 提供者示例 | 语义作用 | 预期归属（需审计） | 禁止 |
|---|---|---|---|
| 狂热光环：攻速+% | 普攻频率 | AttackSpeed / 调度 | 视为直接乘一次所有伤害 |
| 力量光环：物理伤害+% | 条件泛增伤 | `M_general` | 自动独立建 AuraDamageMultiplier |
| 伤害加深：受物理伤害+% | 物理易伤 | `M_vulnerable` | 同时进入通用增伤和易伤 |
| 信念、降低抵抗 | 元素抗性减值 | 目标有效 Resist、按上下限截断 | 又额外乘独立“减抗增伤” |
| 火球的基础技能系数改变 | 技能自身系数增量 | `M_skill` | 当成通用技能伤害再算一次 |
| 装备数值型“威能” | 合法条件的数值型威能增伤 | `M_power` | 只因为来源是装备就将+火伤误归威能 |
| 格挡、物理护甲、元素抗性 | 防御与事件结果 | DMG3 各对应防御 | 把格挡当第六增伤乘区 |
| 骷髅接受狂热 | 自己合法 Buff 增益 | 自身对应 Modifier | 在主人继承快照里再重复接受 |

## 4. 示例数据目录与禁令

### `data/skill_catalog_PROPOSAL.csv`

记录的是**建议首批技能的身份、优先实施阶段、需复用的能力、审批障碍**。没有产品伤害/CD/特效数值。实际项目的技能 ID、技能名、层级与字段请按已有数据规则比对映射，不可覆盖已有 ID。

### `data/bd_semantic_examples_TEST_ONLY.json`

是表达语义的**非生产示意**。文件内顶层包含 `not_runtime_schema:true` 与 `test_only:true`；没有任何可直接用于平衡的倍率/CD等字段。不得直接交给正式配置加载器。需要先经人审核转成实际 schema，并对所有参数进行强类型校验。

### `data/encounter_validation_PROPOSAL.csv`

是设计验收条目，不是世界配置或刷怪池。随机种子、怪物属性、测试技能等级/数量在真正实现测试时应使用 `TEST_ONLY` 隔离注入，不能修改正式章节难度与怪物奖励表。

## 6. 初步错误与边界校验建议

- 技能引用缺失、重复 ID、未学技能占槽、超出已解锁槽数量。
- 主动光环/主动召唤的槽位占用正确；被动不占槽；游侠配置不含标枪/长矛主武器技能。
- Buff 叠加策略不存在、同名来源实例误删除、Modifier 无效归属；减抗越界/非法值。
- Trigger 引用不存在的 Effect、派生链无限自引用、非法负数次数/计时，未标识来源。
- 召唤定义不存在或递归主人关系、召唤物奖励/尸体来源资格不合法。
- 尸体重复消费、跨房间消费、不合法怪物反复刷奖励。
- 元素与护甲遵守已确认公式；不得接受独立Magic/True/Absolute无批准输入。
- 测试标志/测试配置数据不允许通过正式资源加载验证并混进生产存档。

## 7. 当前开发范围不包含

暂不变更五章地图、城镇、装备掉落池、角色经验公式、队员回城换人规则、星图节点可见性、窗口模式、完整装备威能库、离线挂机结算。若新技能依赖其中任何一项变更，须拆出独立审批任务。
