# Steam D2｜P1-5 装备属性、词缀与技能 BD 接口｜Claude Code 执行包 V1.0

**交付性质：设计合同 + 已确认既有系统的扩展计划 + TEST_ONLY 演示配置。不是实机已实现。**

## 执行顺序

1. 先读 `00_主Todo与项目状态.md`、`01_现有S3S4继承与工程只读审计.md`。
2. 按 `CLAUDE_CODE_FIRST_PROMPT.md` 在用户本地实际工程执行**只读审计**；发现分歧列为 BLOCKED / 待用户批准，**不得先写代码**。
3. 使用 `02_装备与词缀领域模型.md`、`03_属性技能威能与Proc接口.md`、`04_掉落随机开箱装备及存档.md`、`05_五职业装备BD边界.md` 讨论可实现范围。
4. 以 `06_分阶段开发与验收.md`、`07_测试矩阵.md` 执行切片。`data/` 仅为隔离验证，不是正式词缀表。
5. `08_待审批事项与回退清理.md` 记录每次审批；未获批不得扩大范围。之后交付最后一份 `08_综合战斗测试与调平` 开发执行包。

## 硬性约束

- **S3 已批准**：唯一击杀事实→独立宝箱实例→箱仓；仓满仍战斗，多余宝箱丢失且不补发；**手动成功开箱时**才生成 ItemInstance 与随机实例词缀，一次原子提交，不得开箱前生成装备。
- **S4 已批准**：单一权威 ItemInstance 池；角色装备槽仅引用实例 ID；装备/卸下/换装合法原子提交；战斗中换装仅在确定性安全边界生效；掉属性经统一 AttributeModifier/Dirty/EffectiveFightAttr；保存实例的已定型数值和槽位引用，加载重建 Modifier，不重复掷词缀；真实跨进程保存/加载。
- S4 **仅批准 TEST_ONLY 的武器槽和防具槽**，不等于正式全部槽位、品质层级、随机词缀池已批准。本 P1-5 不会擅自把正式装备槽数量和词缀概率升级为确认状态。
- 战斗伤害严格维护已确认的 **4 常规增伤池 + 独立暴击因子（4+1）**：`M_skill`、`M_general`、`M_power`、`M_vulnerable`，另有 `M_critical`。装备来源不自动意味着装备威能乘区。
- 当前物理护甲采用 `DR = Armor/(Armor+K(攻击者等级))` 的已确认设计，**生产 K(L) 曲线仍待定**；未审批不能把 TEST_ONLY 值写入正式配置。
- `Skill + Effect + Buff + SkillModifier + TriggerRule`、固定 Tick / Windup→Commit→Recovery / CD Commit 起算 / 现有 AI / 单一伤害管线必须复用，**禁止并行代码和新隐性伤害乘区**。
- 纯弓游侠；圣骑士**多主动光环共存并逐个占槽**；死灵**多主要诅咒共存**；召唤跨房间；首发至多4人；旧单人设计不应覆盖当前多人战斗。
