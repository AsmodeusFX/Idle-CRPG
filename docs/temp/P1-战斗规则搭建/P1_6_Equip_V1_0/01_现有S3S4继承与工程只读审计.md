# 01｜既有 S3/S4 合同与 G0 工程审计门禁

## 1. 读旧合同的优先级

1. 用户正式批准的 S3 V1.0（2026-10-15）和 S4 V1.0 七项 P0 决议：**不可静默推翻**。
2. 已确认的 `DAMAGE_FORMULA.md`（4+1）、`FIGHT_ATTRIBUTES.md`、`ATTRIBUTE_MODIFIERS.md`、`SKILL_EFFECT_BUFF.md`、Battle Runtime/AI 及后续 G01–G06。
3. 本轮用户要求 P1-5 扩展：若旧 S4 标为 *Out of Scope*，只意味着**当时不实施**，并不意味着本次自动获得了完整正式装备规则。每一新增语义必须标记 PROPOSAL/TBD/TEST_ONLY。
4. **当前代码优先用于确认已实现什么，不自动凌驾于新获批准的规则；若两者冲突，必须交用户决定迁移。**

## 2. G0 必读核对矩阵

| 审计项 | 在真实工程中检查 | 要求输出 |
|---|---|---|
| S3 Chest / Loot | Kill Fact 唯一化、Ledger、仓满丢弃、手动 OpenChest、原子随机奖励 | 文件路径/关键入口/真实测试状态 |
| S4 物品 | ItemDefinition、ItemInstance 已固化属性、装备位 Slot→ItemId、跨角色唯一实例池 | 权威数据地图；实例 ID 是否稳定 |
| 装备命令 | Equip/Unequip/Replace、安全生效边界、在途攻击属性取样 | 既有定义；精确 TBD 分支 |
| 属性 | `fightattr.csv` ID、合法 operation、Modifier Source 身份、Dirty Snapshot | 可支持词缀类型、未知属性拒绝证据 |
| 公式 | 4+1、护甲当前实际上是否减法、K(L)、元素抗性上下限 | 新旧版本差异，不能据新包覆盖 DMG |
| 技能 | SkillModifier 已实现类型、TriggerRule、EffectQueue、Proc 限额 | 哪些玩法只需配置、哪些需要扩展 |
| 召唤 | 属性继承快照、owner/instance ID、跨房间、死亡后释放 | Buff 双计算风险、换装时点 |
| 装备资格 | 是否已有职业门槛、武器类型、游侠弓约束、槽位互斥 | 当前事实，不自行补正式槽 |
| 生成/存档 | OpenChest RNG 固化、实例词缀序列化、版本兼容与恢复校验 | 固化前后、Replay、真实新进程验证 |
| 表现 | 现有 UI 物品详情、Mini/Management 显示、特效触发可观察性 | 最小复用方案，不重写 UI |

## 3. 必须报告的典型冲突

- **C-01**：现有 S4 仅 TEST_ONLY 武器/防具槽，本包需要新增正式多部位？不得自行创建完整纸娃娃。
- **C-02**：现有 ItemInstance 只有 FlatAttr，词缀来源是否能容纳 SkillModifier/TriggerRule 的固化引用？禁止建立第二个装备权威实例池。
- **C-03**：现有配置质量等级/词缀前后缀/随机权重与设计例子不一致？使用原规范，差异请审批。
- **C-04**：现有 DMG 有额外乘区或仍为减法 Armor？报告来源，不得把装备威能当修公式的理由。
- **C-05**：战斗中换装/在途 Projectile/持续 Buff 的快照语义不明？阻塞对应测试，不擅自选时点。
- **C-06**：召唤物继承主人有效属性导致同一 Aura 双计？先报告既有快照语义，再修改。
- **C-07**：已存在 `SkillModifier`/Trigger 实现，交接包例子却需要新类型？先复用、再最小扩展，拒绝影子 `EquipmentSkillSystem`。
- **C-08**：游侠只用弓、职业限制/跨职业装备规则不一致；历史纯标枪节点已废弃。
- **C-09**：读取旧存档词缀/定义不兼容；不得自动删除物品或暗中洗词缀。
- **C-10**：P0-1 护甲迁移专项尚未完成，S4装备 Armor 测试不可报告为正式通过。
