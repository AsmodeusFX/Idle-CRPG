# 06｜P1-5 开发切片、依赖和交付标准

## G0：只读审计（强制首关）

**目标**：核对已实现 S3/S4、4+1、装备 Modifier、技能 Effect、TriggerRule 和存档；用户未批准前不动代码。

**必交**：类图/关键路径、现有可复用能力及证据、C01–C10 冲突报告、建议改动文件清单、旧代码/重复系统清理方案、分段测试命令。未完成的上游 S3/S4 应局部标为 `BLOCKED`，不能伪装已完成。

## E1：普通装备词缀与 AttributeModifier 闭环

**依赖**：S3 手动开箱的原子 ItemInstance、S4 装备槽引用/来源撤销/存档链路可用。

**范围**：在已有生成入口，按 TEST_ONLY AffixDefinition 实例化普通 `atk`、`armor` 和合法四抗/暴击等**已有属性**；实例固化、装备贡献与卸装移除、保存恢复。武器/防具槽只用 S4 已批准测试位；正式多部位暂停。

**准出**：实例持有唯一；同输入 RNG 受控复现；失败不重抽；装备/卸装/换装后 EffectiveFightAttr 正确且无残余来源；跨进程存档一致；伤害真实使用已批准公式（Armor K 未确定则仅在隔离测试 Profile 验证）。

## E2：技能专属词缀 / SkillModifier

**依赖**：现有技能系统 SkillModifier 及有效技能规格缓存；不强制所有五职业技能已完成。

**范围**：优先 2–3 条行为明确、已实装技能可验的词缀（如多重箭合法额外弹道、火球技能系数或额外弹道、召唤类属性之一），从装备实例注册有限 SkillModifier；卸装撤销；技能未学会、未装备时的可用性由原技能规则决定。

**准出**：Core EffectiveSkillSpec 与表现一致，合法条件下改变技能行为；战斗中换装不破坏已受理动作；存档后重新注册一次；不产生新的伤害乘区；未实现的技能标 `BLOCKED` 或 `NOT_RUN`。

## E3：条件威能与 Proc

**依赖**：G01–G06 的实际 TriggerRule / EffectQueue 与事件因果链已被审计。

**范围**：至少一个直接合法命中触发（有 ICD/限次）和一个有界击杀效果（如合法爆炸）；支撑单目标重复击中、跨多人击杀、延迟投射物等回归。不得新增无限事件递归与重复 Loot。

**准出**：基础伤害与 Proc 伤害分别归档，Trigger eligible 与 damage hit 区分，M_power/M_general 等归属测试，来源卸装后没有悬空监听；旧已入队效果卸装并发的精准处理如果旧合同无定论，应阻塞并审批。

## E4：召唤装备继承与团队协同

**依赖**：召唤物、主动光环、多诅咒已真正完成或隔离测试夹具可用。

**范围**：合法主人基础/装备来源继承、外部 Aura 单次作用、合法召唤数量上限、跨房间存续与死亡；同步记录 TBD-03/04（存活召唤物在装备变化后的行为）。未批准前只做不触及这两个争议的快照测试。

**准出**：装备/召唤属性没有重复继承，怪物接敌容量统计正确，无无限召唤战损恢复和无限奖励/尸体；主人/召唤单位杀怪不重复发经验。

## E5：整体验收与清理

- `dotnet build`、`dotnet test Game.Core.Tests`（以工程实际命令为准），记录版本、日志和测试列表。
- Godot 真实管理 UI 开箱→看固化词缀→装备→属性变化→真实战斗→卸装→再战斗。
- Save→退出原进程→新进程 Load→检查词缀、槽引用、Modifier、SkillModifier、Trigger 监听、再次战斗。
- 战斗在 Mini/Management 切换时无逻辑重复；入场散开、敌 AI 激活延迟、远程受击退让和无碰撞索敌不倒退。
- 清点已删除的冗余旧实现/无效配置/重复事件来源，不删除仍有合法存档引用的兼容代码；用户批准迁移后才执行清理。

## 禁止以“假验收”准出

示例 CSV/JSON 静态检查 PASS **不等于**工程编译 PASS；Godot 单次点选成功 **不等于**存档或固定 Tick 回归 PASS；设计 V1.0 **不等于**S3/S4 上游实际代码已实现。
