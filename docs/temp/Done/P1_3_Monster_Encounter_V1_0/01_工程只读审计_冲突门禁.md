# 01｜Claude Code 工程审计与冲突审批门禁（强制）

## G0 — 首轮只读，不改工程

从实际工程根目录开始：读取当前 `CLAUDE.md`、文档索引、相关已确认规范和实际 `.csproj`、`Game.Core`、`Game.Godot`、`Game.Core.Tests`、CSV/JSON/Resource、`git status`。优先关注下列入口，**名称不是强制存在的接口要求**：

1. Room/Area/Encounter：当前房间怪物选择、刷怪预算、刷怪波次、房间完成、失败重试、房间重进位置、同一关重复挂机；是否支持隔离测试房间。
2. AI：`MonsterPolicy`或等价决策器、普通近战容量优先/Overflow/Forced、普通射手最近目标、`ActionRequest`、决策时刻、当前射程与追击范围。
3. **最新真实入场流程**：敌人 AI 启动延迟是按房间还是每只怪设置？小队入场散开何时完成？怪物何时取得候选目标？此前“立即激活”旧规范是否仍存在于注释/代码？不得靠取消AI启动延迟来满足旧测试。
4. **远程受击退让 V0.1**：用户已将需求交给Claude，必须核实是否已合并、当前开关与CD；未实现不得谎称实现，也不得在本包重复做新一套RetreatController。
5. 无单位真实碰撞与视觉散开：核实1D X逻辑/2D视觉、合法房间区域/门口保护区、投射物扫掠命中、墙体、场景Node与Core权威数据。
6. 技能：Skill/Effect/Buff/TriggerRule是否支持冲刺/点名、召唤/复活、范围攻击、增益、怪物施法条件；技能伤害使用统一既有DMG合同。
7. 奖励：召唤或复活怪的`reward eligibility`、死亡事实唯一性、重复奖励/掉落/尸体的现行规则；不能自行编造一个生产收益方案。
8. Debug与测试：既有AI日志、战斗观测、固定种子、Core模拟测试、场景资源、Godot可执行命令与实机流程。
9. 用户其它正在进行的 Claude Code 工作：可能涉及技能、护甲、入场与受击退让，报告文件/改动冲突，避免并发覆盖。

### G0 报告格式（四份）

**A. 现有能力对照表**：要求ID → 源文件:类/方法/配置 → 当前实现证据 → 完整/部分/不存在 → 复用方案。

**B. 冲突清单**：冲突编号 → 设计目标 → 实际工程/现行已确认规则 → 不兼容点 → 受影响的存档/资源/测试 → 最小方案A/B与成本 → **是否需要用户审批**。

**C. 分切片修改预案**：拟新增/修改/不碰的实际文件路径 → 现有入口复用 → 最小增量 → 回归测试 → 是否需要迁移 → 原有冗余代码如何经过批准清理。

**D. 待用户决定**：只问真正阻断的事项；不能重新询问已确认的近战接敌、召唤跨房间、多光环/多诅咒、普通远程不风筝等原则。

> **在G0报告提交后停止。** 不写C#、不改CSV/JSON、场景、资源、存档或既有文档，不自动运行会生成/改写产物的工具；如只读操作出现副作用，报告副作用。

## G1 — 获得明确批准再写码

用户批准的对象必须是**具体切片 + 改动范围 + 已列冲突解决方案**，不是泛化成重构授权。

任何新增公共API、改变旧配置语义、升级存档、更新回城/换人/奖励规则、改变战斗公式、删除旧类，都必须记录审批依据；超出已批范围再次暂停问用户。

## G2 — 实施原则

- 现有系统为唯一事实源：不另造 `MonsterBrain2` / `EncounterDirector2` / `TargetManager2` / `DamagePipeline2`。
- 不为8种原型写8套AI类，优先在现有Policy + Skill行为与配置组合。
- 规范中的字段名、枚举、ID仅作配置语义，须以仓库真实Schema强类型验证后映射。
- 试验数据全部放在开发/测试命名空间或 fixture 路径；**用户确认前不得注入五章正式怪物池**。
- 不随意调整掉率、EXP、金币、怪物难度、护甲K(L)、队伍上限、回城和房间重进规则。

## G3 — 真实构建与验收

1. 使用仓库真实 solution 运行 `dotnet build` 与 `dotnet test`；保存命令、框架版本、失败信息。
2. Core验证确定性AI、召唤/奖励、目标分配、房间完结与异常路径。
3. Godot/Mini实机验证堵门、视觉散开、技能打击、远程退让、无碰撞穿行、房间入口合法性；无运行环境记为NOT RUN。
4. 对每个场景报告`PASS / FAIL / BLOCKED / NOT RUN`，不能把测试编写完成当成通过。

## G4 — 零垃圾代码交付检查

- 不存在两套AI、两套房间完成判定、两套收益、两套召唤生命周期、两套TargetLock真值。
- 检查测试配置未流入生产、Debug窗口默认禁用、日志有界且不开启高频全量转储。
- 删除只限于本次批准范围、引用确认为零、测试通过的废弃实现；其他已有功能不得“顺手清理”。
- 不得重置/清理用户未提交改动；不允许未授权`git reset --hard`、`git clean`、覆盖文档索引。
- 提交变更文件表、测试日志和未完成问题。
