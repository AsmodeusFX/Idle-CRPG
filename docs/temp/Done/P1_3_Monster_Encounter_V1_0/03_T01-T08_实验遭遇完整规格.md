# 03｜八间标准实验房 T01–T08（独立测试场景规格）

## 0. 共同前提

- 这些房间为**专用开发测试内容**，不自动加入现有五章正式地图、怪物池、Castle、地牢收益表。
- 各房间遵守现有房间入口、玩家入场散开、敌AI激活延迟、房间界限与完成规则，不绕开现有Encounter/Area流程。
- 同一局测试的角色、怪物等级、属性、技能、装备、随机种子和测试配置冻结；**比较不同机制只改一项变量**（如Capacity=3→4）。
- 角色单人/双人/四人阵容必须适配**首发最多四人**的现行限制；技能未完成时可以在隔离测试用fixture注入模拟效果，不能宣称正式技能已实现。
- 真实战斗逻辑为Core权威，视觉Y散开不改变逻辑射程。这里“前后、左侧、入口”均需映射现有战场位置数据，**本包没有擅自制定可用坐标**。
- 怪物在合法激活时刻之前应表现出已有非主动/延迟行为，不因测试要求“积极战斗”而取消AI启动延迟。
- 标准测试流程：载入隔离场景 → 锁定参数/seed → 入场与展开 → 激活 → 至少一个完整决策与攻击周期 → 清理/死亡/重试 → 重跑比对日志与画面。

## 1. 测试用推荐队伍与变量

| 代号 | 建议队伍 | 验证目的 |
|---|---|---|
| P-SOLO-FRONT | 单前排（容量为测试值3） | 测Overflow合法追击，别等后排才激活 |
| P-SOLO-RANGED | 单法师/纯弓游侠（容量0） | 0容量仍可被多个敌人攻击；受击退让见真实版本 |
| P-PAIR | 前排(容量3)+后排(容量0) | 容量溢出迁移、后排退让 |
| P-FOUR | 两个可承接单位+两个后排（按已解锁名单组队） | 多承接容量与多目标锁定 |
| P-SUMMON | 死灵法师+已允许的其他角色+召唤物 | 召唤物死亡/新出现改变合法候选和接敌 |

数字“3”是**TEST_ONLY**：不修改正式职业Capacity平衡。

## 2. T01｜8只普通近战：容量与队员入场

**配置：** 8×M01，房间合法分布，不将8只堆在入口接触点。**角色：** P-SOLO-FRONT、P-SOLO-RANGED、P-PAIR、P-FOUR；对照容量2/3/4。

**步骤与预期：**

1. 小队开始入场，检查已部署的AI延迟与入场散开；延迟期不得突然在门口全体夹住队伍。
2. 当敌AI激活且只有容量3前排可被合法索敌，允许3个正常容量预约、其他为合法临时溢出（实际分配受可达/发现/动作边界影响）。所有能合法行动的怪不应无故待机。
3. 后排成为合法候选后，仅在既有安全行动边界促使需重评的Overflow怪重新选择；既有Normal稳定，不把所有怪强制洗牌。
4. 后排基础容量0，**可以有多只怪同时锁定**；不按“后排至多1只”或平均人数分摊。
5. 增加前排容量、保持其它因素一致，正常容量预约的潜在可承载量提高；不能把容量成长做成触发反常的大规模抖动。
6. 结束、队员死亡或重进房间，预约全部释放，不存在幽灵TargetId。

**核心断言：** `normalReservations(target) <= actualCapacity(target)`（容量临时下降期间按合法安全修正规则）；每只近战普通预约至多1份；容量0单位可被锁定；固定seed一致输出相同。另测仅剩容量0角色时不死锁。

## 3. T02｜12只快速怪：散开、堵门与退让回归

**配置：** 12×M02，分布式入场/分布，不用人为指定可引发拥堵的同坐标出生。**角色：** P-PAIR、P-FOUR、P-SOLO-RANGED。

**步骤与预期：**

1. 小队完成其现行入场展开，敌人按现行激活延迟开始索敌；视觉上入口不会形成持续卡死的“堵门块”。
2. M02 **与M01共用接敌规则**，只有速度/基础属性不同。容量超额后漏怪可逼近后排。
3. 远程角色被近战实际命中后，若已有V0.1退让且满足条件，短距离后撤；若未实现，记录为依赖`BLOCKED`，**不能在本包新增第二套退让AI**。
4. 保证退让目标不越过房间边界/入口保护区；怪物原目标锁定不能因为退让自动换人；CD内不持续后退。
5. 固定seed与FPS变化不得引起Core数值/索敌结果改变，画面仍可允许视觉插值差异。

**核心断言：** 不靠RigidBody推开队员；无永久相互卡住/逃出房间/无穷重新索敌；怪物不因高速跳过容限与攻击判定。

## 4. T03｜3只重型近战：物理承伤

**配置：** 3×M03。**角色：** P-SOLO-FRONT、P-PAIR、P-FOUR。

**步骤与预期：**

1. 重型怪使用M01索敌，普通攻击节奏慢但完整执行。
2. 比较有无被动护甲/格挡/团队恢复时的承伤与房间剩余HP，记录击中、暴击、格挡。
3. 如果现行工程仍是减法护甲，按P0-1单独标记`FORMULA_MIGRATION_PENDING`，不在本包纠正公式；调平结论必须注明用的实际版本。

**核心断言：** 伤害只由已有唯一伤害管线结算，不因不同怪物行为写第二套护甲规则。

## 5. T04｜4近战＋4普通射手：远程AI和范围施法变体

**标准：** 4×M01+4×M04。**变体T04-C（同一房间切换配置，不新增第9房）：** 4×M01+2×M04+2×M05。**角色：** P-PAIR、P-FOUR。

**步骤与预期：**

1. 所有M04选择最近合法目标；当前普通射程内站定射击，不不断后撤风筝。
2. 远程攻击不预占近战Capacity；M01仍遵循容量。
3. 投射物保留已有墙体、合法攻击线和1D连续命中；视觉Y错位不得制造合法性的假象。
4. T04-C验证M05基本远程索敌+合法AOE，不因一次技能特别选择就永久覆盖其普通TargetLock。

**核心断言：** `rangedEngagementReservations == 0`；射手原目标失效后正常改选；投射物无穿墙和失控重定向。

## 6. T05｜6近战＋2后排猎手：显式特殊TargetPolicy

**配置：** 6×M01+2×M06。**角色：** P-PAIR、P-FOUR。

**步骤与预期：**

1. M01正常被前排承接或溢出；M06在合法候选中按`BacklinePriority`显式策略优先后排。
2. M06只能通过现有合法移动/技能路径接近，不可穿墙或无限距离突进。
3. 玩家嘲讽/拦截（如果已经实现）能让指定数量M06短时进入Forced，过期在安全边界恢复选敌。
4. 远程目标退让不隐式改变M06锁定；无退让实现时不假装验收通过。

**核心断言：** M06和M02逻辑可从诊断中明确区分，受控后目标释放不泄漏；普通M01不会一起突然点名后排。

## 7. T06｜4近战＋1召唤巫师：召唤、防刷、完成条件

**配置：** 4×M01+1×M07；M07技能测试生成M01或M02，单召唤者存活上限为**TEST_ONLY可配置小值**。**角色：** P-FOUR、P-SUMMON。

**步骤与预期：**

1. M07召唤成功前检查活动区域、上限、Skill CD和合法位置。
2. 召唤物出现后持有来源身份、可攻击/死亡/正常AI；不会引入第二套MonsterRuntime。
3. 召唤物死亡释放对应接敌与目标引用；奖励按现行规则审计，缺少资格合同时必须审批（不能自动设置正式收益）。
4. 连续召唤、召唤者死亡、残留召唤单位与房间完成状态要产生**有限终止结果**，不允许无穷Spawn阻止通关。
5. 如果使用“复活”变体，必须用已批准尸体来源/唯一消费规则；否则标记复活变体BLOCKED，不创建专用第二尸体库。

**核心断言：** 同一召唤实体只死亡/奖励一次；满上限不产生额外单位；不存在无限刷金币/EXP/掉落路径；房间完成规则结果与已有Encounter合同相符。

## 8. T07｜4近战＋1支援巫师：Buff来源与清理

**配置：** 4×M01+1×M08；提供一个隔离测试用合法`Modifier` Buff（不锁正式数值）。**角色：** P-PAIR、P-FOUR。

**步骤与预期：**

1. M08对合法友军施加有视觉标记的强化；目标没有资格时不得不断空放技能。
2. 标记强化来源、Buff生效时间、目标属性快照Dirty更新。
3. M08死亡或出范围时，区分持续源光环和独立施放的定时Buff，按照现有Buff合同清除/到期；不无条件即时删掉所有Buff。
4. 相同来源重复施加遵循G01/G02，不重复永久叠加。

**核心断言：** 没有永久悬空Buff来源；伤害只结算一次；玩家没有手动集火支援者也能够完成或明确表现压力差异。

## 9. T08｜Boss＋近战小怪：特殊技能与基础索敌分离

**配置：** 1个当前真实工程现成Boss或显式`TEST_ONLY`代理＋若干M01（测试值建议4）；**不在此专项创建完整Boss系统**。**角色：** P-FOUR。

**步骤与预期：**

1. Boss普通近战或远程攻击使用对应基础TargetPolicy；如果近战普通攻击，应遵循近战容量资格。
2. Boss特殊技能使用独立Skill TargetPolicy（如合法区域范围攻击），不能顺带永久改写Boss普通锁定。
3. 测试控制/嘲讽对Boss的行为以已有Boss合法性/免疫配置为准，未确认时提交审批。
4. 完成条件、阶段和奖励遵守当前已有Boss/Encounter合同，不能借测试增加全新Boss奖励。

**核心断言：** 普通与特殊目标分离；技能CD/动作生命周期完整；如果没有可复用Boss实现则T08标记BLOCKED，**不声称已覆盖真正Boss行为**。

## 10. 每间房统一输出的最小测试事实

`Seed / TestConfigHash / PlayerComposition / AIActivationTimestamp / PartySpreadCompleteTimestamp / EntitySpawn / TargetAcquired(TargetPolicy,Reason) / ReservationChange / SkillCommit / Damage / DeathUnique / RewardEligibility / SpawnLimit / EncounterCompletion / RoomExit / UnexpectedException`。

无需新建第二总线；使用现有事件/日志/测试夹具记录等价事实。所有逻辑事件必须能映射到稳定实体ID和固定Tick。

## 11. 不得“用测试成功掩盖不存在的功能”

- 若无M06突进技能，可只验后排优先索敌，突进记`BLOCKED`，不能做假瞬移。
- 若无怪物复活规则，可先验M07召唤，复活单列`BLOCKED`并提交用户审批。
- 若无Boss技能机制，可使用无头代理验证基础接口，但T08真正Boss表现仍是`BLOCKED`。
- 若没有远程退让实施反馈，可验Monster行为但退让回归记`NOT RUN/BLOCKED`。
- 若未完成P0-1护甲迁移，T03的百分比护甲平衡结果必须标`NOT VALIDATED`，不能为了过关临时覆盖旧公式。
