图例：`T`=安全城镇，`1`=郊外大草原，`2`=绝望平原，`3`=神罚之城，`4`=火焰之河与混沌避难所，`5`=地狱熔炉支线，`x`=熔岩/深渊/不可通行断崖。坐标 `(row,col)` 从 1 开始，横向列 col，纵向行 row。

## 4. Floor 活跃格子、怪物密度与杀怪预算

### 4.1 三种格子单位及建模定义

- `WorldTile`：大地图7×7的一个格。只承载 POI、连接与地形，不自动生成战斗怪物。
- `Floor Layout BoundingBox`：每层随机布局的行列边界 (`LayoutRows`×`LayoutCols`)，含障碍、深渊，不等于可战斗格。
- `ActiveCell`：该 Floor 实际有效的逻辑格，拆成入口/走廊/战斗/精英/事件/出口/Boss 场；不是渲染像素，也不是角色寻路用的最小单位。
- `BossArenaCell`：一处大 Boss 空间可能占 11 或 14 个有效格，但只配置 1 个 Boss 演员，不按格数生成 Boss。
- `DungeonFloor` 或 `CastlePhase`：二者共享房间/遭遇预算基础数据，Castle 表现为连续阶段 `PHASE_SEQUENCE`；不强制意味着上下楼梯。

### 4.2 精确预算公式

```text
ActiveCellTarget = EntryCellCount + CorridorCellCount + CombatCellCount
                 + EliteCellCount + EventCellCount + ExitCellCount + BossArenaCellCount
PlannedKillTarget = CombatCellCount * CombatMonstersPerCellTarget
                  + EliteCellCount * EliteGroupMonsterTarget
                  + FixedUniqueActorCount + BossActorCount + BossEscortTarget
DungeonPlannedKills = Σ Floor.PlannedKillTarget
ChapterFirstClearKills = Σ DungeonPlannedKills + Σ CastlePlannedKills
```

其中 `SealActivationCount` 是**封印事件次数**，不等同击杀数。混沌避难所 5 处封印合计 5 次，3 位封印守卫计入 `FixedUniqueActorCount`。避免将一个封印事件同时作为精英格和额外独特演员重复计数，未来实机需使 SpawnProfile 的规则与预算匹配。

| 3 | 封印西翼 | 激活 2 个封印，击杀首位封印守卫 | 封印2/5 |
| 4 | 封印东翼 | 激活 2 个封印，击杀第二位封印守卫 | 封印4/5 |
| 5 | 封印中央 | 激活第 5 个封印，击杀第三位封印守卫 | 封印5/5、三个守卫已击败 |
| 6 | 迪亚波罗王座 | 固定宽阔 BossArena，迪亚波罗出场 | 击败迪亚波罗，征服 Castle，结束第四章 |

- 原典是同一片混沌避难所内的封印事件，而不是六层地下城。`StageMode=PHASE_SEQUENCE`，由自动小队按顺序推进。
- Seal 激活与守卫击杀必须由 Runtime 真实事件满足才能进入最终 Boss 阶段。不能只凭“进入第6阶段”直接假设完成。
- Boss 场地独立放大：终局阶段有效格数/长宽可扩大，多格形成空阔战场；对 3–5 角色小队应保留横向/纵向移动空间与火焰/闪电预警。
- 固定怪物与动态击杀统计要分开：三个封印守卫为固定角色，不要再通过普通敌人池重复刷出。

### 5.2 地狱熔炉支线事件

`REGION_05` 在 Region3 Castle 被征服后变为可见状态，但不能自动加入候选。**仅玩家批准后才开放 Gate** `G-04-05` 与区域5。支线 Castle 地牢全部完成后也要获得新的玩家批准。

最终事件顺序：击败海法斯特 → 获得/使用符文锤的任务事实 → 摧毁墨菲斯托的灵魂石 → 结算支线奖励（奖励种类、发放方式、次数待定）。此奖励不得参与 `ACT04_DIABLO_KILLED` 的必需前置。

若从第三章延续灵魂石任务物件，需要显式建模跨章节任务事实，例如 `ACT03_SOULSTONE_OBTAINED`；若未实现剧情资源，也可以把需要的道具抽象为自动剧情事件，不能因物品栏缺少道具而使已授权支线死锁。

## 6. 全自动目标选择与人工批准——优先级顺序

```text
候选 POI：
  1) 本难度属于已解锁 Region；
  2) WorldMap 按 Gate 有真实可达路径；
  3) POI 在本难度尚未首次通关；
  4) 若 Region.IsOptional，SideRegionApproval=true；
  5) 若 POI.Type=Castle，必须 all RequiredForCastle Dungeon 已完成，且 CastleApproval=true。
排序：ChallengeLevel ASC → IsOptional ASC（主线优先）→ AutoOrder ASC → PoiId ASC
选中后：大地图寻路 → 进入该 Dungeon/Castle → 自动移动/索敌/战斗 → 按 Floor/Phase 顺序推进。
无合法候选：停止自动首次攻略，显示待批准要塞 / 支线；可由后续挂机策略选择重刷，不擅自批准。
```

**手动批准的语义：** 许可是本难度该支线/该 Castle 的持续授权，不代表立即插队；每座 Castle 需要单独的授权，不得一次授权全章；授权状态存档并跨重启恢复；跨难度互不影响。

**与 Act IV 地形的特殊关系：** 区域5是从已解锁的区域4入口分出，虽然它的 `UnlockParentCastleIds` 指向区域3 Castle，但并不要求区域4 Castle 完成。`Gate` 是移动边；`Region.ParentCastleIds` 是解锁条件，这两个概念不能混合。

**任务事件与区域推进分离：** `衣卒尔` Boss / `封印5` / `迪亚波罗` 等事实由明确的战斗完成事件发放；不因为 UI 手动批准而直接产生成功事实。支线独立于主线，进下一章后仍可回到本章批准并完成地狱熔炉。
