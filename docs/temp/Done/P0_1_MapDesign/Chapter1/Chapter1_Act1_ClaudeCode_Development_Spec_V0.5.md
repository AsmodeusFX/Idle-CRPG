## 5. 地牢逻辑格、楼层规模和刷怪预算（本次新增）

### 5.1 三类格子不允许混淆

1. `WorldTile`：本章大地图 8×8 的格子，只有自动移动/解锁作用。
2. `DungeonCell`：随机地牢内部的**抽象房间或走廊模块格**，每个格的几何尺寸待实际生成器审计；不是 Godot 贴图 Tile。
3. `NavGridTile`：具体房间内部路径与碰撞格，服务 3–5 人小队移动/索敌/障碍，不能直接乘怪物数量。

每层 `LayoutRows×LayoutCols` 是用于程序生成的包围盒；`ActiveCellTarget` 才是实际可走格；`CombatCellCount` 只统计普通遭遇格；`EliteCellCount` 为精英组所在格；`BossArenaCellCount` 多格只代表**一处单独的 Boss 遭遇**。

### 5.2 格数档位与表演约束

| 档位 | 每层有效格数 | 适用场景 |
|---|---:|---|
| XS | 8–12 | 邪恶洞窟/短新手地牢 |
| S | 12–18 | 一般洞穴、前期支线 |
| M | 18–28 | 一般地牢与中程要塞 |
| L | 28–42 | Castle 主体、后期深层 |
| XL | 42–60 | 少数大型终局（第一章尚未强制使用） |

**本版示例值可与随机生成器的布局范围对齐，不是强制固定生成结果。** 不能只用“格子数”判断世界尺寸；小房间、长走廊和大礼堂的几何尺寸需采用模板/房间资源另外配置。Boss 场地：普通 3–5 连通模块，安达利尔示例 8 模块，**全场只有 1 个 Boss Actor**。

## 7. Core 自动选择目标与解锁流程（已确认规则）

### 7.1 选择候选

```text
Eligible = 目标未首通 ∧ 所属区域已解锁 ∧ Gate 可达 ∧ 特别前置合法
Castle 特别前置 = 本区域 RequiredForCastle 的所有独立地牢已首通
StableSort = (ChallengeLevel ASC, BranchPriority ASC, AutoOrder ASC, PoiId ASC)
Choose First → 大地图自动行走（无战斗）→ 进入 Dungeon/Castle →逐层完成→提交真实首通→重新挑选
```

支线的 BranchPriority=1，主线=0，**只有挑战等级相同时才参与决胜**；低等级埋骨之地允许自动先于高等级主线攻略。支线完成不是大教堂解锁的前置。

### 7.2 与上一个版本的接口变化

- 过去地图 UI 可手选 Dungeon 的演示流程，不再代表产品的默认攻略方式；默认由 AutoExpeditionPolicy 自行前往。
- `PoiFirstCleared`、`CastleConquered`、`ChapterMainCleared` 只能由真实 Dungeon/Floor/Boss 结算产生，不允许点击地图格直接成功。
- 区域解锁依赖、可通行 Gate 和 POI 位置全部在 Core 强类型配置，视图不重复判定。
- `DungeonChallengeLevel` 显式存配置，与当前队伍等级**解耦**；玩家等级只用于策划推荐与对比验证。
- `WorldTile`/`DungeonCell`/战场 `NavTile` 互不复用坐标系。

### 7.3 自动攻略模拟与防死锁

已附 `data/ACT01_AUTO_ROUTE_SIMULATION_V0.5.csv`，在**所有挑战一次成功、不主动回刷**的假设下，用 Core 等价的稳定排序策略推演三个难度各 41 个 POI 的自动完成顺序。

| 验证点 | 预期 |
|---|---|
| 初始只开放区域 1 | 通过 |
| 区域 2 Castle 通关后同时解锁 3/4 | 通过 |
| 地牢未全清时 Castle 不进入候选 | 通过 |
| 区域 3 未完成也能完整清除主线 37 个 POI | 通过（支线不会阻断安达利尔） |
| 相同 ChallengeLevel 先主线，后支线 | 通过（稳定排序） |
| 所有配置目标均可完成且无循环前置 | 通过（静态模拟） |

**注意：** 自动完成顺序仅供检测逻辑，不等于用户将实际体验到一场连胜。失败回刷阈值、切换目标成本、自动回复/营地补给、阶段性收益与重刷 Boss 等策略仍需单独批准。

## 9. 未批准的重要决策清单（供后续独立确认）

1. **格子实际尺度**：DungeonCell 对应多大房间/走廊段，场景碰撞与镜头单位，尤其俯瞰 3–5 人小队的宽度、转角与队形。
2. **Floor 清关条件**：除邪恶洞窟全清、Boss 层击杀 Boss 的样例外，普通 Floor 是抵达 Exit 还是击杀守卫，是否要清扫支路余怪。
3. **随机规模是否允许波动**：本版 `ActiveCellTarget` 为预算目标，实际 `ActiveCellMin/Max` 容差及生成失败回退未批准。
4. **怪物密度与精英/ Boss 配比**：三难度 Spawn 数值为设计样本，还未按用户实际怪物类型、队伍人数与 Godot 表演负载实测。
5. **失败与挂机回刷**：无可攻略目标时如何刷 Boss、失败后如何选已清地牢、什么时候再次挑战、卡关收益归属。
6. **Boss 实际配置**：原创 Castle 守将、角色属性、攻击动作、BOSS 房间模板与关卡胜败事件。
7. **多人小队人数**：3–5 只是方向，最终队伍数量、角色 AI 和怪物碰撞预算未批准。
8. **任务回访流程**：D2 崔斯特姆的卷轴/石阵前置暂不移植，不自动让黑暗森林构成石块旷野必清前置。
9. **统计口径**：击杀事实与奖励有效性、召唤物/复活怪的 `CountsTowardLoot`、刷 Boss 特殊收益和宝箱容量溢出。
10. **商业发行的 IP 处理**：本文件使用 D2 原典地名/Boss 作为**内部设计映射**，公开发行版本不能直接视为已获得专有内容使用授权。
