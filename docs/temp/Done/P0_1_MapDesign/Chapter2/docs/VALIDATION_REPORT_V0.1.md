# Chapter 2 V0.1 — 静态 / HTML 原型校验报告

日期：2026-10-18。**这是离线规划数据与浏览器模拟校验，不是游戏工程 L1/L2/L3 的测试通过记录。**

## 静态校验

- 9×9 共 81 格，55 区域地块＋2 格鲁·高因＋24 x，不越界。
- 9 个 Region 均在 3–8 格之间；各 Region 内所有格子按上下左右连续可达。
- 40 普通 Dungeon、9 Castle，共 49 个 POI；全 POI 唯一坐标且坐标与区域对应；每个 Region 恰好 1 Castle。
- 术士峡谷严格 6 假墓 Dungeon + 1 真墓 Castle = 7 墓，不额外复制都瑞尔真墓入口。
- 9 条显式 Gate 均连接正确的相邻格；魔法传送和皇宫门由 TravelKind 区分。
- 77 个独立 POI Floor 内容，231 条三难度 Floor 预算；逐层分区格数求和恰好等于 ActiveCellTarget。
- 每个 POI 的三个难度 `DungeonChallengeLevel`、推荐玩家等级、预计首通杀怪目标均存在且在本章总区间内。

## 自动攻略离线模拟

- 普通、噩梦、地狱三难度模拟均通过。
- 初始不批准任何 Castle：碎石荒地 5 座 Dungeon 完成后停止，没有自动攻击 Castle。
- 玩家逐个批准主线 Castle 后：7 条主线区域全部完成，无须批准任何支线。
- 术士峡谷必须在 `群蛇峡谷 Castle && 神秘庇护所 Castle` 两项同时成立后才解锁。
- 主线完成后，再批准下水道与古代通道支线，仍可以将 49 个 POI 全部完成。
- 同一级别的候选目标按主线优先、AutoOrder 和 PoiId 稳定排序，不由地图邻近程度覆盖。

## 浏览器 HTML 冒烟测试

- Chromium 实际渲染：81 个格子、9 条 Gate 连线、标题与区域 / POI 详情正确显示；无 JavaScript pageerror。
- 通过真实按钮 `连续推进` → `批准 Castle` → 继续推进，验证第一个要塞等待点。
- 模拟完整七主线 Castle、两支线 Castle 的人工批准及清理；三难度模拟进度互相独立。
- 预览截图见 `preview/` 目录。

- Godot 场景内每层随机布局是否满足活动格目标、是否具备足够的 3–5 人队伍战斗空间。
- 实际每秒击杀、刷新与回刷产生的总击杀差异、前进时间、奖励和真实章节时长。
- 原创地牢名称及原典命名的最终制作授权，以及 Boss 美术和机制。
