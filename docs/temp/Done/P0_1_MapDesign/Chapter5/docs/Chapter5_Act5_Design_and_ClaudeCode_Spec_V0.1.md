- `T`=哈洛加斯（9,2，仅1格）; `1..9`=九个主线区；`A`=支线10冰河；`B`=支线11尼拉塞克神殿；`x`=不可通行（雪山断崖/峡谷/地图边缘）。
- **格子贴边不等于跨区可通行**：只有 `ACT05_GATES_V0.1.csv` 里存在显式 Gate 的边才可跨区域，其余贴边处需要使用雪壁、封闭门或地形断面阻挡。
- 地图外形强调海拔与山路走势：哈洛加斯在西南低处，主线向东北翻越高原后转向东南、最终绕入世界之石大殿；冰河在水晶通道北侧，尼拉塞克神殿经哈洛加斯传送。
- 所有 `x` 都是不允许寻路穿越的物理阻挡，不应该因为视觉遮罩不同而产生穿模捷径。

**主线** `T → 1 → 2 → 3 → 4 → 5 → 6 → 7 → 8 → 9`。此为解锁依赖，不表示玩家要连续手动导航；小队自动选合法最低挑战目标。每一区结束时必须等待该 Castle 的手动攻坚许可，才允许继续解锁下一片区域。

**支线**：`4 → 10（冰河）` 玩家第一份区域许可 → 10 Castle 获准并击败 Frozenstein / 营救安雅 → `11（尼拉塞克神殿）` 显示为待批准 → 玩家第二份区域许可并经哈洛加斯传送进入 → 11 Castle 再次获准 → 击败尼拉塞克。以上都不在 8/9 区 Castle 的前置条件里。

## 4. Floor / Cell / Spawn 的面积与怪物预算

### 4.1 数据单位与格式定义

```text
WorldTile                 大地图通行格：仅承载一处POI或安全空地，绝不直接刷怪
Dungeon / Castle          大地图唯一入口，进入后触发一至多层真实随机DungeonFloor
LayoutRows / LayoutCols   楼层逻辑包围盒（不等于实际有效房间/格数）
ActiveCellTarget          实际有效格数量；由Entry+Corridor+Combat+Elite+Event+Exit+BossArena组成
CombatCellCount           允许生成普通战斗编队的格子数
EliteCellCount            精英编队格数；并非每格只出现1名敌人
BossArenaCellCount        Boss场占用有效格总数；Boss演员数量需独立指定
ScriptedWaveCount         只用于固定剧情波次，不能计为额外随机精英格
ScriptedWaveMonsterTarget 固定波次产生的额外怪物总数，计入计划击杀
FixedUniqueActorCount     固定独特角色，远古三人组以3人计，不再计入BossActorCount
DungeonChallengeLevel     整座地牢参与自动冒险排序的挑战等级，不用第1层替代
```

**面板的物理格尺寸、房间边长、走廊宽度、路线曲折度**仍由 Godot 地牢生成器配置实现；表中格数是房间/遭遇层面的抽象逻辑单元，不是贴图像素或NavMesh网格。

### 4.2 首次全清预算公式（防重计）

```text
ActiveCellTarget = EntryCellCount + CorridorCellCount + CombatCellCount
                 + EliteCellCount + EventCellCount + ExitCellCount + BossArenaCellCount
PlannedKillTarget = CombatCellCount × CombatMonstersPerCellTarget
                  + EliteCellCount × EliteGroupMonsterTarget
                  + FixedUniqueActorCount + BossActorCount + BossEscortTarget
                  + ScriptedWaveMonsterTarget
PoiPlannedKills = Σ (its Floor.PlannedKillTarget)
MainFirstClearKills = Σ (all mandatory Dungeon and Castle of R1..R9)
SideFirstClearKills = Σ (R10 and R11)
```

`ScriptedWaveMonsterTarget` 已包含五波仆从实际生成的演员，不能再次从CombatCell中抽取同一组；三远古者用固定UniqueActor计，不再额外计BossActor。`BossArenaCellCount=17` 仍然代表**一个场地空间**，不会生成17个巴尔。

## 5. 关键任务事件与终局阶段（不新增手动移动操作）

### 5.1 远古三守护者（W08-C01）

- Castle 第4阶段固定空旷山顶竞技场（本版 BossArena 16有效格），同时出现科力克、马道克、塔力克；三者全部被击败后产生 `ACT05_ANCIENTS_DEFEATED`，作为该 Castle 攻克事实。
- 不为三人再额外刷普通 BossActor；不做“一个死了就自动通关”或“只剩两个时房间结束”的错误逻辑。
- 原版 D2 的远古者存在离场重置等规则；本游戏改造成连续自动挑战，失败处理复用后续统一的 `AutoExpeditionFailurePolicy`，**不会假定已经批准的 Castle 需要二次批准**。

## 6. 自动攻略选择器、许可与失败策略接口

```text
For each candidate POI in current Difficulty/Chapter:
  Region parents have been conquered in this Difficulty
  AND WorldMap explicit Gate path is physically reachable
  AND POI first-clear not yet completed
  AND (Region.IsOptional == false OR SideApproval[Difficulty,Region] == true)
  AND (POI.Type == Dungeon OR
       (All RequiredForCastle dungeons in same Region done
        AND CastleApproval[Difficulty,Poi] == true))
Sort by (PoiChallengeLevel ASC, IsOptional ASC, AutoOrder ASC, PoiId ASC).
Execute: walk world tile -> enter Dungeon/Castle -> auto path-find, acquire targets, fight and progress floors.
If zero candidates: wait for authorization or hand over to separately designed farming policy.
```

**特别注意**：等待Castle批准是刻意的玩家决策点。批准只获得挑战资格，绝不代替实际通关，也不直接授权下一座Castle或其他支线。持久授权在保存/读取之后仍生效；失败后如何自动回刷、多久重试为后续待定规则，本章不能自行定义数值。
