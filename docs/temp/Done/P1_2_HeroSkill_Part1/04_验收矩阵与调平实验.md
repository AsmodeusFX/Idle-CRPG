# 04｜功能测试、回归测试与平衡实验矩阵 V0.1

> 测试用例是**设计验收目标**；尚未在真实工程执行。G0先梳理哪些可直接以 `Game.Core.Tests` 现有 Fixture 实现。测试数字仅测试夹具，不进入生产配置。

## A. 核心规则验证（应优先为无头确定性测试）

| ID | 场景/操作 | 通过条件 |
|---|---|---|
| BD-01 | 圣骑士装备祈祷＋狂热，测试环境开放足够槽位 | 两种效果同时存在，各占一个合法槽位；未擅自限制为一光环 |
| BD-02 | 两个圣骑士同名光环不同强度同时作用 | 根据审定的同名Buff策略取强/刷新/限层，不出现每Tick增长；离开来源可正确恢复 |
| BD-03 | 圣骑士光环覆盖骷髅；骷髅进出范围 | 正确附加/撤销，无双重继承、无残留 Modifier |
| BD-04 | 死灵同一敌人附加伤害加深＋降低抵抗 | 两种主要诅咒共存，各影响自己属性；不可互相自动清除 |
| BD-05 | 反复施加同一种诅咒 | 按该技能经批准的刷新/择强规则处理，不无限堆层 |
| BD-06 | 信念＋降低抵抗同时作用高抗怪 | 减抗进入唯一有效抗性计算；同一效果未重复落入独立乘区 |
| BD-07 | 物理伤害带 Buff/诅咒/暴击、可格挡 | DMG1/2/3和既有4+1一致；Crit和Block可合法共存 |
| BD-08 | 五种伤害与负元素抗性 | 各分量独立护甲或元素抗性；攻击者等级驱动 K(L)；没有魔法/真实旁路 |
| BD-09 | 多重箭一次技能命中多目标 | 每个合法目标实际伤害结算；次数控制不误删真实伤害 |
| BD-10 | 旋风/炮轰/多弹同时触发某个有界装备威能 | 按该 Trigger 资格/ICD/每次释放上限触发；不同帧率结果一致 |
| BD-11 | 由 Proc 引发的额外伤害试图再触发同源 Proc | 未获显式链授权时不能自我无限派生 |
| BD-12 | 一个 DOT Tick 与武器直接命中分别触发装备 | 根据经批准来源资格区分，未审定前不把所有 Tick 当直接命中 |
| BD-13 | 单人死灵在无尸体房间装备召唤骷髅 | 能在合法时机召唤，受到数量上限约束，骷髅加入接敌体系 |
| BD-14 | 骷髅、石魔/女武神加普通队员面对8只近战 | 召唤物独立容量；不取消后排可被攻击规则；死亡释放槽位 |
| BD-15 | 骷髅跨多个房间 | 存活骷髅数量/HP保持，显示位置重新建立，不因切房补满HP |
| BD-16 | 主人外部光环变化后召唤物的属性 | 不通过主人继承一次+召唤物直接Buff一次造成重复增益 |
| BD-17 | 召唤物死亡后连续重召唤 | 不发放额外怪物收益，不生成无限可消费尸体 |
| BD-18 | 怪物在同一 Tick 同时受两个致命 DamageInstance | 一次正式 DeathConfirmed/KillConfirmed，一次奖励，至多一个尸体消费资格 |
| BD-19 | 死灵尸爆与复活争用同一具尸体 | 只有一次合法消费；失败分支按审定的施法语义处理，无双 Effect 成功 |
| BD-20 | 火球二次爆炸/尸爆连锁达到已批准预算 | 有界确定性执行，完整保留已经提交的HP/收益/死亡清理事实 |
| BD-21 | 连锁对已注销目标/已消费尸体重新申请 Effect | 安全拒绝或跳过，无崩溃、悬挂锁定、重复奖励 |
| BD-22 | 不同随机种子和相同随机种子重跑 | 同输入同种子结果确定；不同种子可产生允许范围内不同结果 |

## D. 调平观测指标与决策方法

不要只比较人物面板 DPS；推荐至少记录：

- **输出**：房间通关时间、按伤害来源拆分的有效伤害、单体/多目标效率、过量击杀伤害。
- **生存**：队伍成员剩余 HP、死亡、复活/重试率、连房持续作战长度、召唤战损和补充时间。
- **协同**：光环/诅咒贡献的团队额外有效输出（通过有/无相同效果的可控配对实验估计），控制有效时间、召唤物承受的有效伤害。
- **行为**：技能实际施放次数、因目标无效放空比例、AI动作饥饿、后排退让次数及有效脱险比例。
- **风险**：每Tick触发/伤害事件峰值、最大链深、Buff实例数、尸体消费失败计数、Mini窗口特效对象峰值和FPS。
- **经济**：每小时合法经验/金币/宝箱等，召唤死亡/复活来源的奖励是否异常。

**调平步骤**：先验证规则/重复结算正确 → 固定角色等级、装备价值与技能点预算 → 控制随机种子对比不同BD → 观察不同怪物组合的优势和弱点 → 才调整具体技能系数、CD、目标数、召唤强度。所有正式参数调整应以独立实验记录为证据。

| Gate | 必须完成 |

| G0 审计 | 源码证据、旧规范冲突表、TBD清单与最小改动方案；**不改代码** |
