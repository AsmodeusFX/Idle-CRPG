# Steam D2｜五职业技能 BD 交互与首批技能交接包

**版本：** 设计合同 V1.0 / 首批技能切片 V0.1  
**日期：** 2026-10-22  
**范围：** 规则文档、技能设计草案、工程只读审计与验收规范；**没有修改 Godot 工程，没有执行 dotnet build / test / Godot 实机测试**。

## 阅读顺序

1. `00_决策状态与历史冲突清单.md`——核实用户最新已确认规则，避免旧设计覆盖新结果。
2. `01_技能BD交互与平衡规则_V1.0.md`——G01–G06 正式规则合同，避免平行状态机。
3. `02_五职业首批技能垂直切片_V0.1.md`——17个候选技能的设计规格及自动释放策略。
4. `03_配置接口与示例数据说明.md`——建议字段、资源边界与示例数据的使用禁令。
5. `04_验收矩阵与调平实验.md`——规则、队伍、怪物、性能和回归测试。
6. `05_ClaudeCode只读审计与分阶段执行.md`——**首次只读 G0；审批之后才进入开发**。
7. `CLAUDE_CODE_FIRST_PROMPT.md`——可直接复制进 Claude Code 的首轮指令。

## 辅助示例数据（全部非生产配置）

- `data/skill_catalog_PROPOSAL.csv`：17个首批技能候选清单。
- `data/bd_semantic_examples_TEST_ONLY.json`：字段概念和三个跨职业事件示意；并非工程已有 schema。
- `data/encounter_validation_PROPOSAL.csv`：验收用遭遇矩阵。

## 状态区分（必须遵守）

- **C / Confirmed：** 用户在当前对话明确通过的玩法合同；可作为产品基线，仍需得到任务/代码实施授权。
- **R / Recommended：** 本包新增的技能行为细节、字段、调平试验建议；尚未获得最终批准，不得直接当生产数值或公共 API。
- **T / TBD：** 数值、公式参数、接口、存档变更及有冲突的旧规则；没有明确决策时先报告。

## 不允许的行为

- 解压即覆盖现有 `CLAUDE.md` / `DOCUMENT_INDEX.md` / 已签署战斗文档。
- 未审计就实现新的 DamageCalculator、BuffManager、TriggerBus、SummonManager、CorpseManager 或第二套技能 AI。
- 将 `TEST_ONLY` 示例当成正式职业/技能数值。
- 发现历史规则冲突仍擅自选择一种方案；清除、重写用户未提交改动或删除旧实现。

**建议使用方式：先将本包放到工程外或独立临时目录，执行只读审计，得到审批后再将已通过的文档差异和代码修改同步进入仓库。**
