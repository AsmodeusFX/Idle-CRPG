## 1. 必过的功能测试

| ID | 场景 | 应满足的结果 |
|---|---|---|
| TG-01 | 单野蛮人容量3，8近战怪同场激活，其他角色未入场 | 正常预约最多3个，余下 Overflow 继续追击/攻击野蛮人，没有等待/循环死锁 |
| TG-02 | 在TG-01后法师(容量0)入场 | 安排 Overflow 重评；允许多只怪锁定法师；原 Normal 3只保持原目标，不“只转1只” |
| TG-03 | TG-02后游侠(容量0)入场 | Overflow 按最近合法非满坦克目标分流，不保证均匀分配法师/游侠 |
| TG-04 | 只有法师(容量0)，遭遇8近战怪 | 8只怪仍有合法目标并正常战斗；不存在“0容量不可攻击” |
| TG-05 | 野蛮人容量3调至5（相同入场时序、敌人与位置） | 允许更多近战正常预占前排；数值差有可观察因果；不应出现提升容量反而因压力均摊让所有人同样受击的隐藏算法 |
| TG-06 | 双坦各有剩余正常容量 | 分别可预占自己的槽位，单个怪不会重复占2个角色槽；无全队强制均分 |
| TG-07 | 所有前排槽已满、后排尚未出现 | 后续近战目标可临时超额攻击已满前排，不会空等 |
| TG-08 | 两名容量0的后排都在场，10只敌人 | 溢出可同时锁同一后排，不存在伪造“后排接敌1”的单怪限制 |
| TG-09 | 普通远程弓箭手与近战敌人混合 | 普通远程按最近有效目标，**不占近战容量**；不会把坦克容量“远程先占满” |
| TG-10 | 远程怪切换近战攻击 | 安全边界重新进入近战容量分配；切回远程释放普通预占，不泄漏 |
| TG-11 | 特殊狙击怪配置后排优先 | 技能/特殊策略能合法攻击后排且不改变普通远程怪默认行为 |
| TG-12 | 嘲讽使怪临时转向坦克、普通槽已满 | 技能强制锁定仍生效；超量可攻击；到期后安全重评，不永久追着坦克 |
| TG-13 | 救场技能目标不在有限范围内 | 不允许无距离强制转移；动作与 CD 依已有 SkillRuntime 约束 |
| TG-14 | 骷髅1、石魔3等可受攻击召唤物入场 | 各自可配置独立容量；新候选触发Overflow重评；召唤物退场预约释放 |
| TG-15 | Normal怪/目标被杀、注销、离房 | 清理对应目标锁定/预约恰好一次，不留下占满假象 |
| TG-16 | 目标容量骤降（如从3降到1） | 不超过现容量的常驻Normal预约；多出的改成可正常战斗的Overflow，在合法时机处理 |
| TG-17 | 远程/近战技能行动中有新后排进场 | 不在Windup/Commit强制取消；同原技能合同合法完成或合法打断后重新索敌 |
| TG-18 | 同一Tick生成10只怪，容量3 | 固定顺序预占，Normal不会因竞态超过3；重复运行结果完全一致 |
| TG-19 | 只有坦克且所有敌人超额、坦克死亡 | 战斗按既有失败/死亡处理，不能继续攻击不存在的目标 |
| TG-20 | Boss普通近战与范围点名技能交替 | 普攻遵守接敌逻辑；AOE/点名目标独立策略，不强制改主锁定 |
| TG-21 | 近战普通攻击碰到0容量后排 | 不受当前后排被锁定数量阻止，允许多只围攻；攻击合法性/距离仍有效 |
| TG-22 | 小队打开房门，坦克先进，法师迟到 | 怪立即激活，无长时间等队友的停机；后排出现会稳定触发Overflow重评 |
| TG-23 | 重复进房或换人回城→原房续行 | 没有旧房间悬空目标/槽位；恢复准确性遵循已有房间/存档合同 |
| TG-24 | 有效配置缺失、容量负值、未定义策略 | C#强类型校验明确失败；不使用隐藏fallback悄悄改成最近目标 |

## 2. 既有功能回归（不能以实现新索敌为由降低）

| ID | 关联原合同 | 验收重点 |

## 3. 神经质AI/视觉测试：必须用视频或实机检查

| ID | 场景 | 可观察验收 |
|---|---|---|
| VIS-01 | 野蛮人先进门，法师迟到 | 无“全部怪原地等3秒”；坦克第一眼确实接敌；后排出现后有部分敌人绕过去 |
| VIS-02 | 6~12近战围攻同一角色 | 使用稳定虚拟攻击点/视觉Y偏移，避免完全叠成一团；不出现无限交叉换位 |
| VIS-03 | 20怪大量超额 | 能围攻/穿行而不被单位刚体/门口阻塞卡死；不会悬空攻击异常远目标 |
| VIS-04 | 多名召唤物产生/死亡 | 目标自然转移，视觉站位适时更新，避免突然瞬移到反方向 |
| VIS-05 | 高速投射物经过多单位视觉重叠 | 逻辑命中仍按Game.Core独立规则，不受视觉Y散开影响 |
| VIS-06 | 目标频繁改变导致AI重评 | 不出现反复横跳/原地旋转；日志能解释每次换目标的触发原因 |
| VIS-07 | 野蛮人容量从3提高到5的对比录像 | 在同构房间里前排正常承接数量明显改变，但不意味着输出/承伤自动提升 |
| VIS-08 | 远程怪、后排刺客、Boss混编 | 普通远程射近目标、特殊策略可威胁后排，各行为易辨认 |

**要点**：VIS 视觉效果属于 Godot 运行实测，不能因 `dotnet test PASS` 就写成视觉验收 PASS。具体录像观察方法和量化阈值由负责人在实测后审批；不得自行设置“必须3秒无抖动”等正式指标。

## 4. 质量与性能边界

- 默认使用已有诊断事件/有界日志，开发模式可开目标线、接敌占用、重评原因，正式运行下不得持续无限积累。
- 不新增每 Tick 所有怪物扫描所有单位的无界双层重评；只有新目标/失效/Force变化等触发，正常锁定稳定。
- 性能场景数量建议采用测试档而非正式敌人刷新预算；沿用已有 Benchmark/Performance 测试项目。
- 单房间无人机体、单人、满队、满召唤、战败清理等都需要覆盖。

## 5. 验收门槛

**交付完成必须有**：

1. G0只读审计报告与用户对C/D冲突的明确处理决定；已确认的新设计合同已与旧 Confirmed 文档同步对齐或留下获准的迁移记录。
2. 在用户批准的变更范围里，**单一权威 AI/锁敌路径**生效；不存在新旧目标系统并行竞争与幽灵引用。
3. TG-01~TG-24、RG-01~RG-08中属于实际代码已具备的可测项通过；未具备的召唤/特殊技能/旧存档场景标明`BLOCKED`并说明依赖，而不是伪造PASS。
4. 提供至少坦克先入、后排迟到、多人近战围攻、远程混编四种 Godot 演示观察结论；若环境不可运行，标 `NOT RUN`，给出本地复测步骤。
5. 实际运行`dotnet build`与`dotnet test`（用户工程路径为准），附命令和真实结果；不可仅说“理论可编译”。
6. 变更清单、Git状态、潜在风险、未实现项、建议调参项、需用户下一轮确认项完整。
