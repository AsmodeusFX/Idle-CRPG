# C3｜31怪级数值参数与真实消费链合同

## 一、参数优先权威

1. [C] 玩家本轮唯一怪级区间`Run.MonsterLevelMin/Max`；Room首次Reveal采样形成快照；升级Lmax不改变已生成内容；Lmin继续恒等1且购买关闭。
2. [C] 公共XP按合法击杀及真实修饰入池，升级是按`HeroInstanceId`的一次玩家点击；AR/DR为自然角色评级和有限修饰，不允许装备成为唯一级别准入门槛。
3. [C] KP合法击杀去重、逐级买Lmax并独立核对所有上阵英雄AR和DR；金币单独按星图购买消耗；三账必须闭合。
4. [P/H] S04的31档英雄等级、XP/怪级、购买Lmax费用、章末Lmax只是初始离线数值建议。现工程WP3 `lmax_cost=10`等参数属于旧[H]原型，**不能静默混用**。要求C3通过参数注册表绑定真实消费者并作同种子前后对照，不擅自宣布哪个正式值胜出。
5. [C] G03仅QA验证，S02/S03/P03和死灵首轮不出售。生命HP/装备品质遵守现存保护规则，不在C3改变机制。

## 二、31级表投放方式

见`C3_31怪级联合参数待校准_H-B1.csv`：以`MonsterLevel=1..31`作为完整候选表，逐行记录XP奖励、评级要求、KP价格和累积KP。这份是设计源，不能直接替换`monsterlevel.csv`目前1..10000的HP/ATK倍率，不能把章节地牢隐式变成怪级权威。可采用扩表、独立数值表或聚合编译配置，由执行AI在后续授权中调查并自主选实现。

**必要可观察对照：**同一Seed、同一实际怪级、同一怪物类型，对比加载前后`RewardXp`、实际伤害评级倍率、英雄资格拒绝原因及购买KP成本；读取保存前后结果一致，源码或生产表意外更改应触发哈希门禁。

## 三、星图和装备跨系统因果

- 真实星图消费者不得以UI数值改变作为唯一PASS；需要`StarPurchase`→`ModifierApplied`→随后合法击杀、治疗、Buff、攻击间隔或出售的**同源事件链**。出场前已获得的奖励不允许被事后补加倍率。
- G01 XP、F01/02金币、O05精英伤害及D04治疗效果各使用自身合法的触发/覆盖条件；无治疗技能的阵容D04不可凭“购买了”算有效体验。
- 订单包括候选比当前更好才能自动推荐；玩家亲自点击单角色“穿戴更好”或全队≥5合批；所有装备售卖净额按真实Owner、品质、ItemLevel、Slot记录，不重复卖出。
- SC01..SC05、PO01..PO04需C2-B实际实现及Review后才能进入正式增长计算；四药剂槽和冻结逻辑不变。

## 四、参数状态和签出

任何参数行均有`ApprovalStatus [C/P/H]`、`EffectiveScope QA_ONLY | PRODUCTION_READY`、`ConsumerPath`、`Unit`、`Evidence`、`LastTestSeed`、`EditorSourceHash`。切到生产需要用户对数值范围及体验作最终裁决；单个测试PASS只令其从`H_UNTESTED`转为`H_ENGINE_VERIFIED`，不升格[C]。

S04的英雄升级费用和职业自然评级也逐行附在`C3_英雄1到25级XP升级费用与累计_H-B1.csv`（四人全到Lv25共54120 XP）以及`C3_四职业自然ARDR示范基线_H-B1.csv`。这两表的ClassId仅作候选，必须与C1-A的生产ClassId交叉核对。
