## 2. 设计Owner需要修正的审计口径

### R-01：六个B项不等于“全部P2-4编码前阻断”

应按**具体工作包的产品决策门槛**分层：

| 开放项 | 我的分层 | M5/P2-4处理建议 |
|---|---|---|
| B-01 Lmin安全性 | **Lmin永久购买启用前阻断（P0）**，不阻断其他开发 | M5允许设计可禁用购买的通用区间接口；直至防断供规则和场景测试通过，Lmin升级不开放给玩家。不得用“保留一级差”直接宣称安全。 |
| B-02 城堡需要实杀同档怪的证明吗 | **城堡准入规格定稿前阻断** | 我推荐先按`Lmax≥N`，不额外要求实杀证明，以避免新增隐性门槛；待产品负责人按规格确认。 |
| B-03 AR/DR函数与等级曲线 | **正式数值定标后置P2-5A**；参数接口/临时验收条件需M5定义 | 用户已同意临时试用**40%–150%**；`(AR/DR)^1.5`仍是探索假设，不能在正式配置里默认为最终曲线。P2-4可实现可配置倍率与确定性成长接口，通过可复现示例测试。 |
| B-04 公共XP成本曲线 | **正式成本后置P2-5A** | 公共XP无等级差衰减、无当前库存上限已确认，不需重新裁决；M5仅需定义升级费用读取、手动升级事务与测试用临时表。 |
| B-05 装备/卷轴/药剂内容参数 | **本轮交互雏形范围须M5确定；全量内容后置** | 6–8部位可先选一组代表部位做首版，卷轴可先至少1种基础攻击，药剂至少1种有效持续Buff，但5槽机制、库存/掉落/保留/到期必须真实生效。装备合并以“可换部位件数≥5”为规则，不是“≥5名英雄”。 |
| B-06 成就点经济与第5席售价 | **详细商店经济后置** | P2-4必须有Account/Run分层、有效重生/放弃接口与持久化；完整成就商店及第五席昂贵价格在正式经济设计阶段再定，不能阻止基础WP。 |

**说明**：建议不等于用户审批。用户可直接批准M5规划范围，工程执行AI在该授权目标内自主选技术实现，但不能自行决定重大产品体验。

### R-02：工作包粗估算存在算术不一致

《M4_DEPENDENCY_AND_MIGRATION.md》WP1–WP12逐项相加实际为**71–108人日**，但末尾写作**65–100人日**。两者均属粗估，不应据此承诺工期；M5应按拆包、并行依赖与真实改造范围重新校准。尤其完整成就商店、全部五职业技能树、最终数值、实机验收不能隐含在“功能雏形”中。

### R-03：工程状态报告对“阻断项”数量表述不一致

状态报告结论处强调3项产品裁决（Lmin/城堡准入/AR-DR），而开放问题报告列B-01～B-06共6项。正确解释是：**6个待决主题，但并非6个同优先级的编码阻断**。M5主表按WP门禁管理，避免“一项未定，全部停工”。

### R-04：存档迁移属重大风险，不宜直接照搬审计提案

推荐复用`progress_v1.json`的单文件Account/Run双区段及既有备份原子写盘，但仍为待授权技术方案。旧角色等级不能因XP折算被错误降低；`Σ个人未花XP`与新公共XP的初始余额关系需以真实旧档做测试。旧档迁移/开发期清档的产品价值取舍必须明确；没有授权不能静默删除玩家进度。`SaveStore.Reset()`全清要与“放弃本轮”“正式重生”不同名、不同确认反馈。

### R-05：实际引擎/UI验收环境未就绪

D23只能认定**代码结构已是单窗口**，不能认定UI/UE达到新版要求。进入P2-4 UI工作包前，工程端需查找Godot实际安装路径或建立明确的视觉取证替代设备，跑真实截图/操作路径/状态切换；只用`dotnet build`不能通过UI门禁。版本控制工具不可用也应在M5前明确可用的变更取证方式。

### R-06：旧双权威清理必须是“替代”，不能叠加

- AR/DR必须取代Armor，不能物理伤害先吃Armor再吃评级。
- 公共XP手动升级后不得残留`while`自动升级、经验等级差衰减或个人XP消费。
- 怪物等级应仅从Run的`[Lmin,Lmax]`决定；POI、floor_plan、spawn_rule现有的覆盖/偏移权限需统一迁移。
- 重复职业首先要有稳定英雄实例ID；Buff来源、召唤归属、装备、天赋和存档必须以实例定位。
- 技能树下架`skill_slots`，保留4固定技能+1特性；旧`CastTalent`路径不可默默双活。
