**坐标从 `(row=1,col=1)` 开始**：`x`=不可通行的河流/密林/断崖；`T`=库拉斯海港，位于 (9,1)、(9,2)；`1–9`=区域 ID。地图外围留出密林断崖勾形，而不是必须填满100格。

**核心地形组织**：海港在左下角；蜘蛛森林与剥皮丛林呈蛇形向东北延伸；下层库拉斯是雨林与石城的衔接；库拉斯商场、上层库拉斯的地块布局趋向规整；库拉斯堤道沿右缘的窄桥折回东南；崔凡克位于下缘终点。

**Gate 是跨区域移动的唯一权威**：即使区域格子彼此视觉接壤，只要没有 Gate 记录，小队不可跨越该边，必须由地图美术表现为河谷、城墙或山崖。区内采用四方向可行走连通格。禁止按全图纯四邻接自动穿透区域锁。

## 4. 地牢 Floor 布局预算、密度和首通击杀建模

### 4.1 数量口径（不与世界地块混淆）

- `WorldTile`：10×10 大地图中的一个格子，承载最多 1 POI，**不生成战斗怪物**。
- `DungeonFloor`：同一个 POI 可包含多个楼层，采用独立随机种子和场景布局。
- `LayoutRows × LayoutCols`：随机生成器布局包围盒，包含不可走障碍，不是遭遇格数量。
- `ActiveCellTarget`：该 Floor 中实际活跃逻辑格，拆分 Entry/Corridor/Combat/Elite/Event/Exit/BossArena。
- `CombatCell`：普通怪物编队目标数；`EliteCell`：精英及随从合计；`BossArenaCell`：占据多个有效格，但只按单个 BossActor 加其固定随从预算，绝不能“每格刷一个 Boss”。
- 这些是**完整清完所有规划遭遇**的预算，不等于游戏机制要求玩家必须杀死每只怪；实际路线中的可选遭遇比例仍要在生成器/实机中验证。

### 4.2 Floor 格子及怪物数量公式

```text
ActiveCellTarget = EntryCellCount + CorridorCellCount + CombatCellCount +
                   EliteCellCount + EventCellCount + ExitCellCount + BossArenaCellCount
PlannedKillTarget = CombatCellCount * CombatMonstersPerCellTarget
                  + EliteCellCount * EliteGroupMonsterTarget
                  + BossActorCount + BossEscortTarget
DungeonKillBudget = Σ Floor.PlannedKillTarget
ChapterFirstClearBudget = Σ DungeonKillBudget + Σ CastleKillBudget
```

## 5. 主线克林姆意志任务如何自动化（防死锁）

**D2 原典关系**：蜘蛛洞窟获得克林姆之眼、剥皮地牢获得克林姆之脑、库拉斯下水道获得克林姆之心；议会成员掉落连枷，合成为克林姆意志后破坏强制球体进入墨菲斯托的憎恨囚牢。资料：https://classic.battle.net/diablo2exp/quests/act3.shtml 。

**本项目候选实现**：三件任务部件关联 **必清 Dungeon 深层完成事实**；它们作为 `QuestFacts` 随 POI 通关写入，而不是稀有概率掉落、背包随机物品、玩家手工合成。

```text
B01-D02 蜘蛛洞窟  → KHALIMS_EYE
B02-D01 剥皮地牢  → KHALIMS_BRAIN
B04-D01 库拉斯下水道 → KHALIMS_HEART
     三者随地牢必清自然获得（不手动申请）
B07-C01 玩家批准并进入 Castle
     → Council encounter 获得 KHALIMS_FLAIL
     → 自动触发 KHALIMS_WILL 事件（条件已满足）
     → 破坏强制球体 → 开放 Castle 内憎恨囚牢 1–3 层
     → 击败墨菲斯托 → B07-C01 CastleConquered / Act3MainCleared
```

**禁止**：将克林姆意志合成作为“进入崔凡克 Castle 的外部前置”，因为连枷在 Castle 内才会获得；也禁止要求完成古神庙群/庞大湿地支线才能进入终局。部分任务事件先做模拟通关事实即可，实际剧情系统留待后续。

## 6. 自动小队、人工批准与跨章返回

**自动候选集强制过滤**：已解锁 Region ∧ 可达 Gate 路径 ∧ （主线 OR 支线已批准）∧ 未首次通关 ∧ Dungeon 可攻略 OR Castle 前置全清且该 Castle 已批准。

排序键：`(ChallengeLevel, BranchPriority(main=0/side=1), AutoOrder, ChapterOrder, RegionOrder, PoiId)`。绝对不得用距离替代挑战等级优先。进入已批准支线后，其地牢同样参与全球等级升序，不强制连续清完整支线。

两组授权按 `DifficultyId + ChapterId` 单独存档：

- `SideRegionApproved(RegionId)`：支线解锁时不等于已批准；批准后可自动访问，但不代表其 Castle 已批准。
- `CastleApproved(CastlePoiId)`：本区域必清地牢通关后玩家再主动确认；批准状态跨战斗失败保留至征服或主动撤销；不会批准下一个 Castle。
- `DungeonFirstCleared(PoiId)` 与 `CastleConquered(PoiId)` 为权威事实；可达性与区域解锁由 Gate 和 Castle facts 派生。
- `ActiveChapterSelection` / `ReturnToChapter` 决定玩家何时返回旧章节支线；跨章全局候选范围仍按用户后续批准的策略实现，不可擅自让新章探索遭到旧支线低等级牵制。
- 失败后的回刷地牢、重试条件和收益策略 **TBD**；首轮模拟视作一次挑战必定完成，不代表真实战斗。
