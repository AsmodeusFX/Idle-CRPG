## 0. 本轮总体交付目标与限制

**从WP0–WP3新版骨架出发，打通真实可玩的横向资源闭环：** 1–4名英雄自动冒险 → XP/KP/金币/装备/卷轴/药剂产出 → 玩家主动升级/学技能/买星图/换装/消费卷轴药剂/买KP/攻城 → 存档恢复、合法重生/弃轮、有限离线收益 → 工程账本及真实UI可验收。

**首轮必须真实能用：** 装备6部位功能链、1种单体攻击卷轴、1种主动Buff药剂、4+1技能机制与职业特性星图解锁、星图购买、重生事务与有限离线、七分区UI与观测。可以采用有明确标记的[H]功能测试数值，不能用纯占位代替上述系统。

**首轮不做：** 五职业完整技能大树、最终星图布局和全部节点价格、装备复杂词缀、卷轴全集/自动使用、药剂8槽全部内容、正式成就/AP商店与第五席售价、完整四章内容制作、首轮10小时正式平衡、正式Steam发行流程。

**硬边界：** 旧技能槽/旧CastTalent/旧星图加席位/旧Armor伤害消费不与新版双活；Lmin永久购买对玩家持续关闭；已确认七分区UI不可删；HeroInstanceId管理重复职业；手动决策（英雄升级、KP、城堡）不能批量自动化。

## 2. WP4｜技能、天赋与星图机制重构

**覆盖设计：** D08/D09/D15/D24/D25；详细规格WP4 V0.6。

### 必须实现
1. 每职业固定**4技能＋1特性树**的机制容量。普攻默认具备；其他技能用英雄实例天赋点学习，学会后由战斗AI自动施放；不恢复技能装配槽购买。原型至少一个职业跑通招牌技能与特性完整链，其余已开放职业至少可正常普攻。
2. `HeroInstanceId` 为技能已学、天赋点、互斥分支、Buff/召唤来源的独立归属键。同职业四实例互不串CD/等级/天赋；处理WP2升级后天赋点来源的欠证接口。
3. 小树分支互斥、按技能区域**免费局部洗点**，已返还点数和已撤销效果在存档重载后不重复。
4. 星图属于Run，用金币购买并真实提供至少：一类队伍数值增益、一类成长增益、一种**按职业解锁特性树学习资格**。一职业节点买一次，对本轮同职业所有上阵实例共享资格，但各实例分别花自己的天赋点，不能自动代选。
5. 退役`CastTalent`旧施法权威、旧`skill_slots/party_slots`和装配购买；旧档权益采用可追溯映射/退款/保留方案，不静默剥夺。

### 不做与保留空间
- 不一次性填齐五职业每招每节点；不锁正式天赋点总量、星图总节点/价格与金币经济。原型节点全标[H]，保留数据驱动配置。
- 不自行把星图职业资格迁移到账户永久商品。

### 验收与UI
`SK-01~06、ST-01~04、LEG-01、UI-01`：重复职业多实例、学习后真施放、互斥、局部重置、星图购买扣金与战斗快照、同职共享资格、读档、旧技能双权威退役。Godot英雄页/星图页与左下技能图标和CD真实截图/点击流程。

**前置门槛**：升级后天赋点入账与同职业Buff来源可靠。若现有WP2未实现，不准默默伪造天赋来源，先依首批Review补证或在授权范围内修复并备案。

## 3. WP5｜装备与回村换装

**覆盖设计：** D13/D14；详细规格WP5 V0.5。

### 必须实现
1. 六部位、每件**一个主属性**（ATK或HP）、装备等级和四品质结构。所有实际装备绑定唯一英雄实例，同职业可穿不同装备。
2. 打怪掉落、拾取、候选保留、回村售出次优/杂物换金币构成合法账本；保护尚未被玩家点击更换的优候选。装备穿戴必须用户点击。
3. 同槽**同属性数值更高**可判为明确更优；跨ATK/HP属人工选择，不用隐藏战力评分代替取舍，也不能被自动出售。
4. **至少5个不同`HeroInstanceId×Slot`**可明确变好时，可一键批量穿戴。显示每名英雄、部位、旧/新属性；4项及以下仅单换。批量是一笔可验证的明确玩家操作，不与XP、KP、城堡合并。
5. 本轮存档与正式重生归属正确、装备Bonus通过WP2战斗属性快照真实生效。若有本轮装备容量风险，优先保证受保护候选不被误删。

### 不做
- 不完整复杂词缀、不做二级洗练、不提前定掉落概率、终版品质数值、套装和复杂装备养成。

### 验收与UI
`EQ-01~08`：四同职业绑定，0/1/4/5不同键候选，同属性/跨属性、回村保留及卖出账本、失效候选批量拒绝、装备读档。Godot右栏批量卡及英雄页实机前后图。

## 4. WP6｜卷轴与药剂的真实使用链

**覆盖设计：** D18/D19；详细规格WP6 V0.5。

### 卷轴必须实现
- 至少1类从怪物掉落→拾取→Run库存→玩家点击→当前合法目标→真实战斗伤害结算→库存恰好-1；目标失效/无目标/缺件拒绝不扣。主战斗区下缘**横向快捷栏**，不放入右栏成长队列。
- 不得默认开启自动卷轴，不靠特效假装真伤害；后续星图自动化仅留可配置接口。

### 药剂必须实现
- 右下4槽（预留8槽布局），拾取占槽、手动点击Buff生效、**生效期间仍占槽**、到期解除Buff并清空原槽；满槽不得自动覆盖；玩家能主动丢弃待用药剂以腾槽。
- **允许多个槽拾取同一个PotionDefinitionId，但仅一瓶可处于生效中**；一瓶使用时其他同类型待用瓶灰显且使用禁用，丢弃仍可用；原Buff结束后解除灰态。
- Buff时钟按有效前台/后台运行Tick，暂停/完全关闭期间不流逝；离线结算不自动消耗药剂，也不自动激活下一瓶。
- **[O] 生效中药剂是否可主动丢弃**：产品尚未单独裁决。不得允许“腾槽保Buff”；在裁决前优先使“生效中丢弃”不可点并显示原因，**待用瓶丢弃始终可用**；是否允许提前结束效果，在WP6公开该操作前取得用户裁决。此局部项不阻断其它卷轴/药剂实现。

### 不做
- 不做全五类卷轴、卷轴自动化、复杂药剂搭配规则、离线装备/消耗品掉落与正式时间系数。

### 验收与UI
`SC-01~05、PO-01~07、UI-01`：消费/真实伤害、失败不扣、双击去重、同种灰态、满槽、丢弃待用、运行/暂停/关闭时钟、存档复原及用户截图七分区不变。

## 5. WP7｜重生、账号永久结构及有限离线

**覆盖设计：** D01/D16/D17/D20；详细规格WP7 V0.1。

### 必须实现
1. 第一次完成第4章后（未来轮次再到下一章）由玩家主动发起**正式重生**；未达条件拒绝。Account记录可靠资格与测试可观察的结算事实；Run英雄/装备/XP/KP/金币/星图/卷轴/药剂/地图等本轮资产清零后开启新队伍选择。
2. **放弃本轮**仅清Run、不发通关奖励；**正式重生**只结算已批准的永久权益；**清除全部进度**额外强确认、与上述命令完全不同。迁移隔离历史英雄不受普通重生默默销毁。
3. 真实关闭到重开时，按**有限时长**做一次可审计的XP/KP/金币离线结算，防同一时间段重复领取，不自动升级/换装/天赋/KP/星图/城堡/卷轴药剂/重生。后台运行仍走正常自动战斗。
4. 完全关闭期间**药剂剩余有效Tick冻结**，Run的活跃药剂和灰态库存随读档恢复。
5. 测试阶段账号奖励可使用明确`QA/H`的事实标记验证事务，**不得发放未经批准的正式AP经济或开放第五席/完整商店**。

### 仍需设计/技术定案的边界
- **离线收益具体算法**：[P]优先使用可配置、可审计、与离线前合法收益能力相关的限额结算；具体XP/KP/金币倍率、基础2小时量级、结算历史窗口按QA配置临时验证，不视为正式经济。若算法会让不可击杀高档怪产生收益，要在工程Review提交差异由设计Owner复核，不擅自把玩家收益规则改掉。
- 首版离线**装备/卷轴/药剂实际掉落**：保持不开放，除非另获授权（以免绕过候选保护和满槽行为）；接口可预留。
- 账号AP产出、正式职业解锁、永久第五席资格与价格留P2-5/后续商品设计。

### 验收与UI
`RUN-01~05、OFF-01~05、UI-01`：四章准入/未达拒绝/通关结算唯一性、Run清空Account保留、双启动或重开幂等、后台挂机、关闭后药剂停表、跨Run不能把旧轮收益打进新轮。Godot重生确认/离线汇总实际截图。

**重大门槛：** WP7不得以“只做存档结构”为由跳过最小真实重生和有限离线链；反之也不得把完整成就商店顺带做进去。

## 6. WP8｜UI/UE总整合与多状态回归

**覆盖设计：** D21/D23与前述各WP。**本包是最终跨模块UI整合，不免除WP4–7各自UI交付义务。**

### 强制七分区
A顶栏（四页签、标题、GM/设置/暂停；旧入口不得无说明删除）；B中左战斗视区；C战斗下沿独立卷轴横栏；D右上金币/KP；E右侧成长交互卡；F左下小队状态及技能图标/CD（公共XP、Lv、HP、AR/DR；不是每人私有XP）；G右下药剂4槽预留8。

### 必须完成
- 跟随各系统接入真实操作状态、允许1/3/4人、4同职业，稀疏/密集待办适应，不遮挡战斗；保持页签与必要旧功能，旧入口迁移/退役明列审计。
- 右栏英雄升级**每次逐人选择**；KP、城堡各是独立购买/挑战；装备≥5不同键时用户一次明确点击换装；卷轴/药剂不混入统一自动消费。
- 对缩放、长文案、无货币、满槽、连续点击、存档重载等状态做实机回归。覆盖当前窗口基础配置，不要求新Mini/Management双窗口。

### 验收与UI证据
全屏原尺寸截图＋按场景独立步骤图/短录屏，明确用户提供的布局截图对照（实际Godot，不是伪图）。分开判断：功能正确、信息清晰/误触、布局完整；任何截图缺失不声称视觉验收PASS。
