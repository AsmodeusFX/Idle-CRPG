首轮至少**1种攻击卷轴＋1种主动增益药剂**。这里的1类是真效果/真消费、非贴图和占位按钮。

## 1. 卷轴状态机

`怪物击杀→卷轴掉落→成功拾取→Run卷轴库存增加→玩家选择卷轴→目标合法性/库存验证→提交施放→库存恰好消耗一次→真实伤害/效果与战斗事件→战斗/库存/UI刷新`

### 1.1 目标与使用

- [C] 卷轴需要玩家早期主动介入；不能默认拥有自动施放。
- [C] 最小原型为**单体攻击卷轴**。界面点击卷轴时优先作用于当前队伍已锁定的合法敌对目标；如果没有合法敌人，则不可释放并且**不消耗库存**。
- [C-卷轴目标] 首版用户已确认“点击后一键打当前合法目标”，**不增加二次点击选择怪物**。未来精确选择作为新功能单独评审。
- [P] 命令提交、扣件、生成伤害事件为同一个确定性事务；目标合法且命令被接受后，即使发生**正常命中失败/闪避**也不返还卷轴；不能发生重复点击造成负库存。
- [P] 若目标消失于命令提交前，拒绝施放且不扣件；如果进入结算队列后目标死亡，按现有战斗事件语义确定且可重放，不必为单卷轴重写整个DMG链。
- [C] 卷轴伤害必须真实走战斗结算入口而不是只播放特效；保留AR/DR对抗链的一致性，不能创设绕过公式的影子伤害。
- [P] 主界面图标显示类型、剩余件数、可用态/禁用态。是否需要额外卷轴CD并未批准，不把原型CD当硬规则。

### 1.2 库存与掉落

- [C] 库存属于本轮Run，重生/弃轮清空；客户端后台不自动消费或自动补给。
- [P] 第一阶段按卷轴种类计数并随存档保存，0件时灰态；消耗时产生一条库存事务与对应战斗事件。
- [P] 有效拾取才增加库存；掉落尚未拾取、读档重复加载同一奖励不能多发；无效拾取不生成重复库存。
- [P] 原型不额外引入强制容量上限，未来星图“卷轴容量”效果与携带库存逻辑在正式设计前定案；但不得误把这点当成用户确认“永远无上限”。

## 2. 药剂状态机

`怪物击杀→药剂掉落→拾取时寻找空槽→占用Run药剂Slot→右下显示待用药剂→玩家点击→Buff激活(仍占原Slot)→Buff计时/状态可见→Buff到期→原Slot释放→可再拾取新药剂`

### 2.1 槽位与生效

- [C] **初始4槽**；游戏主界面右下区域预留8槽扩展，但本轮不必开放。
- [C] 每个拾取成功的药剂占一个槽；一瓶药剂只占一个槽，同一槽使用中不得被后续掉落覆盖。
- [C] 药剂使用**不是立刻清空槽位**；在Buff结束时同一生命周期解除效果并腾空槽。
- [C] 禁止自动使用、自动替换、无限叠加；只有玩家点击才开启新Buff。
- [P] 最小药剂采用可观测的`ATK增益`或类似战斗效率增益，具体幅度与时长是[H]测试数值（产品前期提到约十余分钟，但未锁定本包时间）。
- [P] 生效中点击同一槽不能再次使用；使用中槽位显示Buff图标与剩余持续时间；到期时只移除该药剂贡献，不误删除同名其他效果。
- [C] **同一种药剂可以重复拾取、占据不同待用槽位，但同一种药剂同时只能生效一瓶**：一瓶生效时，其他同种待用槽位**使用按钮灰显、不可点击使用，但丢弃按钮仍可用**；其余药剂仍留在原槽，不销毁、不自动替换、不自动补充。当该药剂Buff结束或被合法提前终止，其他同种待用槽位恢复可用。跨不同种药剂的相互作用和同效果不同定义的冲突规则保留[P]扩展。

### 2.2 满槽与未拾取药剂

- [C] 槽满不能自动覆盖仍待用或正在生效的药剂；没有无限库存绕过槽数。
- [P] 初版满槽时拒绝拾取，并显示“药剂槽已满”，可保留在当前地面拾取窗口；随正常地牢离场是否失去掉落，按现有Loot生命周期处理并记日志，不为此另建无限候补背包。
- [C] **药剂槽有丢弃按钮**，由玩家主动丢弃指定药剂、立即清空该槽；不得隐藏为自动覆盖。待用药剂丢弃后不返还库存。**使用中药剂能否丢弃**的建议见下文：若允许，须同时终止该来源Buff且不退回药剂，不可只释放槽而保留增益。[O] 满槽未拾取的地面药剂，仍按已有掉落生命周期处理，是否引入额外出口留待体验。

### 2.3 时间、暂停与离线（用户已确认）

- [C] 药剂持续时间按**有效游戏运行时间**计算；前台、后台正常自动战斗计时，暂停时停表，**完全关闭游戏时停表**，重开保留Buff剩余时长与占用槽位。
- [C] 后台挂机不因失焦被强行转换为离线；真实关闭后另行有限离线收益结算，**不会替玩家使用药剂、不会消耗药剂剩余时间**。离线奖励是否受已激活药剂的增益影响：本轮推荐**不生效**[P]，保持纯有效运行时间定义一致，避免奖励重复计算。
- [P] 执行时以Core有效Tick/受控游戏时钟推进，不以UI动画或系统墙钟自行扣时；存档记录剩余时长，加载时不执行过期补偿或奖励重领。
- [O-主动丢弃生效中药剂] 推荐允许玩家提前终止：同一操作中停止其Buff、释放槽位、不返还瓶子；使用中应有区别于待用瓶的醒目二次确认，防误点。此体验建议在WP6真正开放前需用户确认。

## 3. UI交互与反馈

- **卷轴横条**：主战斗画面内下沿，横排，默认能显示最小卷轴和0库存禁用态；约5种卷轴≠必须硬锁5快捷槽。显示“库存剩余数量、合法/非法目标、使用结果”。
- **药剂栏**：右下独立容器，4槽依截图布局；每槽空/待用/使用中/同种禁用/到期状态可辨；**每槽有玩家可发现的丢弃操作**（避免与主使用按钮误触）；支持未来8槽布局不改主界面大结构。
- 右侧交互列**不作为卷轴/药剂的主要施放入口**；可以做资源/槽位满提醒，但不能把它们与英雄升级/KP/城堡合并成一键消费。
- 旧功能不可因位置冲突直接删除；迁移必须在Review声明路径。

## 4. WP6最低验收矩阵

| 编号 | 场景 | 通过条件 |
|---|---|---|
| SC-01 | 有库存，有合法战斗目标，点击卷轴 | 真伤害进入战斗事件、库存-1且恰好一次；UI更新 |
| SC-02 | 0库存、0目标、目标在提交前失效 | 不消耗、不给予伤害；错误态明确 |
| SC-03 | 同一时刻双击/多事件竞争 | 库存永不负数，不重复释放同一卷轴 |
| SC-04 | 战斗中卷轴闪避或未命中 | 消耗与事件逻辑一致，可固定Seed重放 |
| SC-05 | 拾到药剂，四槽从0到4 | 只在空槽分配；同一拾取不会重发 |
| PO-01 | 待用药剂点击激活 | 原槽持续占位，有可追溯Buff、状态和倒计时 |
| PO-02 | Buff到期 | 移除正确来源Buff，仅对应槽释放；新掉落可拾取 |
| PO-03 | 满4槽又掉一瓶 | 不覆盖、不自动使用，提示与掉落处理一致 |
| PO-04 | 两瓶同PotionDefinitionId，占两个槽，先后点击 | 第一瓶生效；第二瓶灰态禁用但不消失，第一瓶结束后恢复可用；不能同时叠加/刷新 |
| PO-05 | 前台/后台/暂停/完整关闭后重进 | 按有效运行时间计时；停表后Buff与占位保留；不重复扣时/额外结算 |
| PO-06 | 待用槽丢弃 | 点击丢弃、确认后只清该槽；满槽时可再次拾取，不自动覆盖其他槽 |
| PO-07 | 同种多瓶跨保存/重载 | 原先同种禁用关系恢复正确，Buff只归属激活的那一瓶 |
| PO-08 | 使用中主动丢弃（待裁决） | 若批准，则先移除该Buff并释放槽位，不返还药剂，其他同种瓶恢复可用 |
| UI-01 | 默认与缩小窗口 | 截图展示战斗区卷轴横条、右下4药剂槽，不遮挡左下队伍/技能CD |

## 5. 仍需产品裁决的最少事项

1. **[O-药剂生效中丢弃／WP6开放前]**：推荐可提前结束效果并腾槽；不允许保留Buff又释放占位。
2. **[O-不同药剂冲突／可后置]**：目前明确“同PotionDefinitionId不可同时使用”。不同品类即使效果同属ATK，默认可以同时用吗？建议第一版只有一种药剂，不成为当前开发门槛；新种类加入时再定。
3. **[O-满槽未拾取掉落／可后置]**：按现有掉落生命周期保存/消失，不新建无限药剂仓。

**已关闭的旧问题**：卷轴首版目标二次选择、药剂关闭后计时、同种药剂并发使用、丢弃入口、满槽自动覆盖，均以2026-10-25用户裁决为准。
