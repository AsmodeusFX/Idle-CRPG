# Steam D2｜M5 主界面结构与UI/UE验收合同 V0.5

> 2026-10-25；基线：用户提供的红框截图 `UI_主界面参考_20261025.png`。  
> **本文件替代V0.4中与用户截图及新版公共XP语义有冲突的UI细则**，保留V0.3中无冲突的操作状态规格。不是新的窗口形态提案。

## 1. 固定信息分区（已确认[C]）

```text
┌────────────────────────────── 顶部全局栏 ──────────────────────────────┐
│ 游戏 / 英雄 / 星图 / 地图       标题                 GM / 设置 / 暂停 │
├───────────────────────────────┬─────────────────────────────────────┤
│ 中左：战斗、房间、移动、掉落   │ 中右上：金币、KP等资源              │
│                                │ 中右下：成长/远征交互队列           │
│ 战斗区下缘：横向卷轴快捷栏     │                                     │
├──────────────────────────┬────┴─────────────────────────────────────┤
│ 左下：小队状态＋技能图标/CD │ 右下：药剂槽（默认4，预留8）           │
└──────────────────────────┴──────────────────────────────────────────┘
```

**注意**：示意图仅表达用户确定的拓扑与功能位置，不锁死像素坐标或所有容器比例。照片中旧“五人小队”是既有工程内容；新版首轮上阵1–4人，未来第五席为跨轮永久解锁，不可为保持旧截图内容而恢复开局五席。

| 分区 | 必须保留 | 本轮新增或调整 | 禁止 |
|---|---|---|---|
| A 顶栏 | 四页签、标题、GM、设置、暂停及旧有必要功能 | 合法迁移已有入口，不丢功能 | 把原GM/设置等因信息不对称直接删除 |
| B 战斗主视区 | 大面积战斗、门/场景/房间、必要状态与速度 | 维持核心观看主导权 | 右侧交互侵入战斗主区域；取消战斗视区 |
| C 卷轴横栏 | 主战斗区**下缘独立横条** | WP0–3可灰态/占位，WP6交付至少一类真实卷轴点击、库存/释放反馈 | 混入右侧交互或右下药剂；占位当功能验收通过 |
| D 右上货币 | 金币、KP和必要资源 | KP有真实余额/变动 | 把金币与KP混成单一种货币 |
| E 右侧交互 | 城堡卡等旧有入口 | 英雄升级置顶；KP购买、城堡为独立事件；装备≥5项可批量 | 自动代选英雄、自动买KP、自动攻城；不明原因删旧入口 |
| F 左下队伍 | 每名上阵英雄身份、Lv、HP、关键状态、右侧技能图标与CD | 增加AR/DR；**把旧个人XP条语义改为公共XP余额+各英雄的升级成本/可升级态** | 整块移除或保留“每人私有XP账户”造成规则冲突 |
| G 右下药剂 | 默认4个药剂槽，视觉预留扩至8 | WP0–3保留空槽结构；WP6完成拾取/使用/持续占槽/到期释放 | 删除/并入卷轴/变为自动补瓶 |

**技能区特别约束**：五项固定技能+特性属于新角色的最终机制，工程可以优化图标大小/显示密度，且上阵1–4人时能观察CD；不能为适配空间直接删除技能、重新开放技能槽购物或隐藏所有技能状态。旧“编辑”入口若因技能槽废止被退役，要在Review中说明新对应入口（如英雄天赋页），不许无登记删除。

## 2. 分包阶段的界面交付梯度

| 工程包 | 必须真实能点/能观察的内容 | 允许尚未启用 |
|---|---|---|
| WP0 | 旧页签/GM/设置/暂停仍有效；真实整屏截图；分区存在与版本/窗口记录 | 卷轴、药剂新功能仅占位 |
| WP1 | 1–4人创队、同职重复、轮内锁队；存档/重选队状态反馈 | 卷轴和药剂真使用 |
| WP2 | 公共XP余额、单英雄升级卡、等级/AR/DR变化；左下保留队伍与技能显示 | KP尚未接线 |
| WP3 | 金币/KP资源条、Lmax升级、城堡准入；卷轴横条+右下药剂布局结构可见 | 卷轴/药剂真功能仍属WP6 |
| WP5 | 装备逐件/≥5批量换装及角色/部位清单 | 成就完整商店 |
| WP6 | 1种卷轴可用、药剂4槽中至少1种可拾取/启用、计时可观察 | 卷轴全集与8槽扩展 |
| WP8 | 所有已交模块完成整体UI/UE修正与回归 | 终版美术可后置 |

## 3. 可观察状态矩阵（用于界面验收）

| 操作 | 必须拍到或录到的状态 | 对应数字/账本检查 |
|---|---|---|
| 创队 | 1/3/4人、四同职业、0人拒绝、确认后不可重选 | HeroInstanceId稳定，Run阵容一致 |
| 升级 | 可升与缺XP、指定英雄前后等级AR/DR | 公共XP仅扣一次，其他人不变 |
| KP升Lmax | KP不足、个人AR不足、个人DR不足、全部达标 | 拒绝不扣钱；批准只+1 Lmax |
| 城堡 | 未达Lmax门槛、达到可点、挑战成功/失败 | 不使用“必须实杀同级怪”条件 |
| 装备（WP5） | 1/4/5个可更换**角色×部位**，显示批量内容 | 一笔批量事务，未出现自动穿戴 |
| 卷轴（WP6） | 有目标/无目标、有库存/无库存、有效释放 | 有目标成功使用才消费，日志同库存一致 |
| 药剂（WP6） | 空槽、拾取占槽、使用仍占槽、倒计时完释放 | BUFF生效与计时、保存重载一致 |
| 旧入口迁移 | 顶栏、地图、GM、设置等迁移前后路径 | 功能可访问、Review有旧→新映射 |

## 4. 证据要求和Review结论

- 每个涉及UI的包至少交**真实Godot运行完整界面截图**与交互序列（短录屏或连续步骤截图），含运行环境、配置/窗口尺寸、构建结果。
- 按“**功能行为 / 信息清晰和交互负担 / 结构符合截图**”三项分开评审。一个截图只证明某个状态存在，不代替完整点击与存档测试。
- 原本存在但本轮暂时未实现的新内容，标成`PLACEHOLDER`并说明下一包；旧有效入口迁移/退役须提供表，不得无说明删除。
- 默认4药剂槽与截图为[C]；未来8槽是扩展能力要求，不代表本轮必须开放8槽。
- 旧截图保留的XP条是历史UI证据，不构成“个人经验可继续存在”的产品授权。

## 5. 待定但不阻塞WP0–3的排版事项

- 卷轴槽位数量：设计纲要约5类卷轴，**不等于已确定UI恰好5个并行槽**。可先以原型布局适配约5格，但不应把该数值写成不可变系统上限；WP6 UI定稿前确认。
- 各英雄五项技能图标的信息密度、CD表现和少人队空席表示：执行AI可做不改变信息语义的排版原型，真实截图供设计Owner验收。
- 右栏成长事件细节排序：英雄升级置顶已确认；其他相对优先级后续按点击频率和截屏验收优化。
