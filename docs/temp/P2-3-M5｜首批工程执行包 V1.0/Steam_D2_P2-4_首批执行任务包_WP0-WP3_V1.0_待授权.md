## 0｜目标、实施边界、交付准则

**本批目标**：把旧自动升级、个人XP、Armor与地图多套怪级权威，转换为新版可扩展的运行时骨架，同时保留现有Godot单窗口战斗和观测能力：`固定1–4英雄队伍→击杀获得公共XP/KP→玩家指定英雄升级→自然AR/DR增长→支付KP提升Lmax→主动挑战符合准入的城堡`；读写存档保持正确，核心UI可见可操作。正式平衡放到P2-5A/B。

**授权范围候选**：WP0→WP1→WP2→WP3，全部属于同一批、可在用户明确批准后依赖顺序持续施工。授权后不要求每个WP都等待设计AI实时批准；必须每包自检与唯一模块Review并能回传设计AI复核。若用户没有明确批准此批，执行AI仍只能阅读本文件，不得据此开始实施。

**实施AI自主权**：自主调查、技术方案、内部字段和类设计、配表接口、测试、Bug修复、归档与模块Review。不能擅自改变玩家决策、账号价值、核心UI分区、资源产消语义、旧档迁移取舍、开放Lmin、跨越WP4以后内容。无须对一般接口/文件名差异重新请示；遇未授权重大产品取舍，以最少问题反馈并先推进不依赖部分。不得将Review当作新增权限。Git提交/推送等另按明确授权。

## WP1｜稳定英雄实例ID、固定队伍与Account/Run单文件存档

**差异覆盖**：D01、D02、D03、D24（实例引用契约）、D26；D16/17仅预留状态接口，不提前制作完整成就经济。  
**前置**：WP0证据入口；M4单文件迁移方案已获用户确认。

**应完成**
1. 给每个英雄实例稳定唯一ID，职业`SpecId`仅描述类；战斗目标、编队、后续装备/技能/天赋/Buff、召唤属主引用实例ID，不得再用职业ID作为实例身份。对同职业多开在当前可触达技能做来源隔离回归。
2. 开局默认四个普通可用席位；玩家可选1–4英雄并确认，不满编合法、重复职业合法，0人不可确认。队伍确认后本轮锁定；旧“城镇换人”和“按星图扩初始席位”不得绕过。
3. 采用**一个存档文件**内`Account`（永久）/`Run`（本轮）两层；设置依旧独立。已有事务式写盘、备份、损坏档保留不回退。账号可保存历史/权限的**结构**，不擅发成就点或永久奖励。
4. 旧档转换：先建立字段映射与可恢复迁移策略；必须保证旧等级不降。个人XP如果不能确认是“未花余额”，不得用个人累计值求和赠送成公共XP；不能在迁移失败时默默另开新档。先用QA影子档/备份回放并记录，再切正常路径。
5. 明确四种不同操作：`普通保存读档`、`放弃本轮`、`正式重生`、`清除所有进度`。此包着重实现状态模型与独立接口；正式重生的章节资格/奖励发放留后续WP，**此时不可把仅有重置动作的接口冒充完整重生玩法**。
6. Run中放置后续XP/KP/装备/星图/章节/城堡所需字段的状态所有权；不得为方便把永久点数存在Run里。

**不做**：完整AP商品价格、第5席开放、四章完整内容、正式重生奖励、英雄装备完整内容。

**最低验收样例**
- QA-1A：四个相同职业可开局并存档、重载，ID与等级等独立；1人、3人、4人均可；0人不可开始。
- QA-1B：回城/死亡/旧编队命令不能替换或增减本轮英雄；放弃本轮后新建队伍可不同，Account不清。
- QA-1C：旧V1/V2/V3/V4档及内部版本、故意损坏档/`.bak`恢复场景回归；源档指纹前后不变或有明确副本；英雄等级不降、旧余额不重领；**M4统计914份文件但汇总只覆盖783份**，测试需完成互斥分类或明确排除剩余131份原因。
- QA-1D：正常保存后重启Account/Run一致；异常中断备份可恢复，错误不静默清档；清除所有进度有与放弃本轮不同的确认路径。
- UI-1：选队、锁队告知、放弃、读档异常提示与结果可在Godot中观察；旧功能迁移/退役位置在Review列出。

**工程重要提示**：未确认的旧档字段语义由执行AI负责源码调查与样本取证；如果存在不能同时保值的旧档特例，需向用户提出具体方案，不得自行吞掉该类存档。

## WP2｜公共XP/指定升级 + 自然评级 + 唯一AR/DR伤害消费

**差异覆盖**：D04、D05、D06、D07；D21升级卡接线（局部UI）。  
**前置**：WP1实例ID、Run所有权、读写迁移入口稳定；WP0测试入口。此包完成后不要求正式平衡曲线。

**应完成**
1. 击杀产XP进入Run公共池，所有怪按自身基础XP入池，不查等级差衰减表；升级消费一次仅让**指定HeroInstanceId升1级**，基础AR/DR、适量自然ATK/HP、天赋点等依当前原型配置变化。XP不足时拒绝且不改状态。
2. 完全退役个人经验自动升级路径、任何读档/战斗循环`while`自动补升级及`Heroes[0]`XP伪投影，客户端与测试读同一权威公共池；不对旧个人经验字段二次消费。
3. 受击伤害按新的攻击/防御等级计算新增倍率；唯一`DamagePipeline.Resolve`结算。旧Armor因子退出真实伤害；DMG2闪避/格挡/暴击判定顺序和随机源消耗顺序与可保留的旧回归对齐。
4. 评级从角色等级自然产生，装备、星图可以额外提供但**不能成为KP门槛必要随机来源**；参数形状均属[H]可配置，切换到正式曲线无需替换战斗执行逻辑。
5. **保留用户截图中左下整块小队状态栏**，但旧个人XP进度展示改为公共余额以及各英雄“下一等级费用/可升级”态；名字、职业、等级、HP、AR/DR和技能/CD区仍要有位置。右侧交互栏英雄升级单角色可点、优先显示，不允许“一键升全队”或自动升多级。

**不做**：XP上限防守机制、经验衰减、正式英雄等级曲线、复杂装备评分、完整职业技能配置。

**最低验收样例**
- QA-2A：1、2、4人组队不同怪级击杀，入池XP=原始怪物XP合计（不衰减）；离线/GM等非授权入口不让英雄自动升级。
- QA-2B：共有两名可升级英雄，仅点击A→A恰升1级、B不变、公共余额只扣对应费用；重复连续点击遵守每次成本和余额，日志可追溯。
- QA-2C：攻/守评级各自在伤害结算按原型倍率生效；Armor修改不再影响新伤害，先前闪避/暴击/格挡RNG回归仍稳定。
- QA-2D：升级前后保存重载，等级、公共余额、评级、能力点一致；UI显示与账本一致，没有个人经验残余造成“重复收益”。
- UI-2：从右侧点击某个指定英雄升级；左下对应英雄Lv与AR/DR变化，公共XP数字减少；技能图标/倒计时栏未被删。

## WP3｜本轮KP、唯一怪物等级区间与城堡准入

**差异覆盖**：D10、D11、D12（禁玩家入口）、D17（城堡准入部分）、D21 KP与城堡卡。  
**前置**：WP1 Run与实例ID；WP2 AR/DR、公共XP与伤害基础。

**应完成**
1. 引入Run内KP入账/消费账本；击杀掉落KP，重复领取/失败重试不能凭空复制。用[H]配置可改KP单次成本与击杀奖励。
2. `Run.MonsterLevelMin / MonsterLevelMax`（名称可自主）是全部新生成怪物的最终等级权威。清理地图、楼层、POI、刷怪脚本把等级强行覆盖的路径，章节仍决定怪物模板、地形与故事资格。
3. 玩家可**逐笔**购买`Lmax+1`；必须KP足够、全部当前上阵英雄AR与DR逐个满足，不满足提示具体哪位英雄何项不达标，交易失败不扣款。不得把所有KP升级合并一次执行。
4. `Lmin`本包可保留只读值、QA内部场景和验证钩子，但任何正式玩家入口/公开可用命令均无法触发永久升档，直到安全策略获批并实机/模拟达标。
5. 城堡挑战由玩家主动点击；最低准入=全局`Lmax ≥ 城堡要求怪物等级`以及已经确认的章节/地图前置，不增加“同级怪实杀”证明；战斗成功失败另按战斗系统判断。
6. 右侧资源条真实显示金币/KP，右栏为英雄升级、KP购买、城堡等独立卡片；卷轴横条、右下药剂四槽**在结构上存在**，本包允许“后续功能包启用”灰态，不得宣称实际消耗品功能已验收。
7. 异常/重载：购买后立即存档再载入，Lmax与KP都不丢；已生成怪物的处理按已获确认的快照规则，未确认不得发生静默跨档刷怪。

**不做**：`Lmin`面向玩家开放、怪物数量/掉率KP的完整树、最终KP资源定标、卷轴药剂真实使用（第二批）。

**最低验收样例**
- QA-3A：怪物实际刷出等级都落在Run区间；跨地图、地牢和城堡无旧权威覆盖，Seed固定可重复。
- QA-3B：一个队友AR不足、另一队友DR不足时拒绝升级；KP不足时拒绝；4人合格时仅扣一笔KP并+1 Lmax；三种失败均无状态变化。
- QA-3C：正好达到城堡要求Lmax但无同档击杀记录也可以发起；差1级拒绝、无主动画面不自动开城堡。
- QA-3D：正常UI/Gm/读档/非法请求均不能使Lmin永久改变；必须用专门QA隔离路径才能测试。
- QA-3E：升级前后再生成怪、重启回读怪级区间与余额不冲突；固定Seed能重放。
- UI-3：右栏货币+KP/城堡卡真实点击，显示门槛和错误原因；左下状态/技能、中部战斗/卷轴、右下药剂位置均保留。
