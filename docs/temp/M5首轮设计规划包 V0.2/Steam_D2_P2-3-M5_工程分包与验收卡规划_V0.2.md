# Steam D2《暗黑放置》｜P2-3-M5 首轮工程分包与验收卡 V0.2

> 2026-10-25 · `[P]`设计Owner建议 · 非编码授权，用户批准工作包范围及阶段门槛后才可进入P2-4。
> 目标是**可交互的完整增量闭环雏形**，非最终数值/完整成就商业化与五章全内容。

## 1. 原则

- 执行AI在已授权包内自主排查、技术选型、实现、测试、修复并更新模块唯一Review；设计Owner不为常规工程差异重复审批。
- 一个包必须有：需求来源与授权、DesignID、明确包含/不包含、玩家可观察目标、旧逻辑退役、状态/存档/UI影响、具体测试、工程证据及回滚条件。
- 工程自检、设计Owner独立Review、用户关键验收分别记录；日常不因等待复核冻结已授权的独立任务；**禁止跨越未授权P2里程碑**。
- **临时数值只能放在明确可识别的原型配置/QA场景**，不可把M3探索值转成正式平衡。
- 每个包回传单个模块review更新摘要；不可仅说“已经做好”。

## 3. P2-4总验收门槛

**功能正确性**：新Run/Account、手动公共XP、唯一AR/DR、KP-Lmax、技能/星图、装备/卷轴/药剂、城堡与重生/离线原型形成一条真实可重复资源循环，不依赖正式数值模型通过。

**玩家交互与UI/UE**：升级指定英雄每次一等级；装备有5个不同可换部位可一次主动换装；KP/城堡为独立决定；实际Godot场景至少有成功、失败、重载、资源不足、满库存等状态证据；功能UE与视觉可读性分别验收。

**测试与状态正确**：固定Seed复跑、XP/KP/金币及装备库存守恒、角色实例与Buff/召唤归属、Armor与旧XP双权威退役、重要命令幂等性、坏档恢复，版本取证完整。

**明确不属于此阶段**：正式10小时、XP/KP最终价格、星图完整购买容量、成就点商店完整经济、新职业完整内容、最终装备属性跨级关系、各职业全套技能数值及高品质美术；进入P2-5A专项设定并配置，P2-5B工程模拟与实机体验定标。

## 4. 异步Review约束（工作流V1.2）

每包回传：`用户/设计要求来源及授权 → 变更文件及旧规则覆盖 → 执行AI的自主判断/替代方案 → 构建/自动测试/实际界面证据 → 遗留问题 → 设计AI与用户验收状态`。如果技术方案只是改变内部结构、不改变玩家体验，由工程执行AI自行推进并备案；涉及核心玩法、经济、UI关键操作、存档价值的未批准变更，须提交最少必要问题。

## 5. 必须在相关包而非整个M5之前定案的关口

- **WP1迁移前**：旧档保留/转换策略以及账号永久价值回填边界；防止静默丢失。
- **WP3城堡行为签核前**：城堡是否仅`Lmax≥N`；Lmin仍封闭。
- **WP5/6各自验收前**：首版代表装备部位、卷轴/药剂示例与特殊时钟语义；具体强度不定正式经济。
- **WP8重大UI确认前**：开局选队及右侧优先级/确认交互由用户裁决主要体验。
- **WP7持久化验收前**：首次通关后的可用账号权益与“暂未开放永久商城”如何呈现，不许默默伪造正式AP。
