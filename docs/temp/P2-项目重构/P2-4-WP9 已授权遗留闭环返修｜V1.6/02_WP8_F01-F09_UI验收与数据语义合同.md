# R-A2｜WP8 ＋ F-01～F-09 UI/UE回归合同

所有验收以**真正运行的Godot控件**为准；UI构图草图和headless定位断言不能单独替代真实窗口证据。此页只补F-01～09的正确语义，不重新批准新的UI模块或玩法。

## 一、最新UI最终布局及冲突覆盖

A 顶栏四页签/设置/暂停不变；B战斗区域不被右栏侵占；C下沿**固定5槽卷轴快捷栏**（F-09覆盖旧文本条）；D右上**金币/KP/公共XP三格等宽**（F-03/F-08覆盖旧两格）；E成长队列顺序：可升级英雄→可替换装备→Lmax解锁→Lmin退休禁用→挑战城堡（F-02/04/07覆盖旧排序）；F左下英雄小队＋已学技能与CD；G右下4药剂槽。

英雄页同时保留：**技能/天赋子页**（R-A1四技能＋T）以及**装备子页**（F-01六装备槽/该英雄背包/穿戴更好装备）。不允许修技能UI时把装备子页或背包按钮删掉。

## 二、关键卡片精确语义

### 1. F-07 怪级Lmax卡

- 标题：“解锁怪物等级 N”（N=当前Lmax+1）；费用仍为KP，原型价格[H]显示为实际运行参数，不锁死10。
- **[C]门槛文案**应为“所需攻击评级 AR≥X、所需防御评级 DR≥Y（每名上阵英雄分别满足）”或同等明确表达。必要时列出具体未达标成员及其AR/DR，而非“最低角色等级需求 N×每级评级”。
- 角色**等级Lv**、攻击/防御**评级AR/DR**、怪物**等级m**、角色**ATK/HP**为不同量纲，不能复用一个“最低等级”字段。现有“伤害/攻击/护甲/生命”说明要逐项追溯实际数据源：**旧Armor不参与新版伤害**，若显示“护甲”且无真实效果需改为实际属性或隐藏该行并报告，不得把旧Armor当成DR。
- 评级“小菜一碟…致命”若基于旧代理算法应标作当前原型提示[H]，不要当成真实Boss通关评级。数值未达、KP不足时Core必须拒绝扣款，UI显示原因。
- 与城堡卡区分：城堡卡保持**两行**“攻击城堡/需要怪物等级”，但挑战资格还取决于原P0路线前置和Lmax，不从UI删掉Core校验。

### 2. F-07 Lmin退休卡

- 当前`Lmin=1`，购买按钮必须禁用，Core/API、GM和存档校验保持一致；不允许因屏幕展示了禁用卡而开放升级命令。
- [P]未来的`全队最低英雄Lv≥目标Lmin`仅可作为说明的设计预览，不作为目前已生效条件的宣称，也不可误用于Lmax。
- 卡面的“退休怪物等级”宜显示**将被退休的当前最低级**和**退休后新的最低级**，防止出现“退休0级怪”这种用户不可理解表达。实现文字前先对齐实际源字段，若在产品语义上仍有歧义，保留禁用并登记待确认，不修改数值区间。

### 3. F-09 固定五格卷轴：一点击最近合法敌人

- 五格顺序稳定、可由合法配置驱动。未投放的定义显示“未投放”并禁用；已投放但库存0显示0并禁用；库存>0且有合法目标时单击即发，不二次确认。
- **[C]最近**：从当前战场实际活着、可被卷轴命中、归属敌方的合法目标中按**与卷轴作用方/既有目标选择定义一致的战场距离**排序；相等时使用稳定tie-break，不得仅取List中的第一个活怪。工程需阐明在卷轴无施法者概念时距离取自何处、为何可稳定复现；如果当前系统没有可用的距离参照，在上线“最近敌人”文案之前提交设计Owner裁决，而不是自行换成一个隐藏策略。
- 目标死亡/消失、当前无有效敌人、库存不足、重复连点：Core保持“失败不扣”、“每次成功只扣一张”、“不释放空效果”；UI立即刷新与存档。UI测试须真正点击槽位、显示目标与扣减，不只测Core的`UseScroll`。
- **没有新增**卷轴手动选目标、方向瞄准、自动施放或更多卷轴品类。

### 4. F-01/F-04 装备两条不同入口

| 入口 | 触发与显示 | 行为边界 |
|---|---|---|
| 英雄页→装备→“穿戴更好装备” | 始终面向当前选中的一名`HeroInstanceId`，显示6部位与其背包 | 显式一次点击，可更换该英雄当前全部**明确可替换**的装备，不受右栏5项合批阈值限制；跨ATK/HP保留人工选择 |
| 右侧成长队列 | 全队可替换数≤4→逐条显示，≥5→**一个大按钮**并列出最好的5件候选信息 | 点击批量只对全队不同`HeroInstanceId×Slot`明确升级生效；展示5件≠只能换5件，必须核对N件真正执行 |

“最好5件”的展示排序不可随便用ATK与HP绝对值作跨属性战力排名；应确保都是可明确更优的候选，按稳定确定性的规则展示5条并说明排序含义（例如“优先展示5项可换装升级”，不冒充统一战力）；对比字段/说明若受设计规则约束，提交视觉稿给设计OwnerReview。两入口点击后都必须刷新右栏、英雄装备槽、背包、Attack/MaxHp，保留被保护的跨属性候选。

### 5. F-02/F-03/F-05/F-06/F-08

- 不可升级英雄卡隐藏；可升级显示图标、名字/序号、XP费用、Lv、AR、DR；点击只升级指定英雄一级。
- 右上三格必须等宽且在常见长数值/缩放下不溢出；因已显示公共XP，不恢复个人XP。
- KP卡无钱时可以保留解释，不能把不可购买状态伪装可点击成功。
- 城堡卡只两行，其他说明在可访问的tooltip或可等效获取的反馈中；前置没过不允许挑战。
- 每次升级、装备、KP、卷轴、药剂、挑战城堡操作后全部相关区域即时刷新。

## 三、需要的实际Godot截图／视频证据

**最少页面**：①技能页S1已学S2未学/T锁定，②学S2后技能页+左下CD，③买T资格后两名同职英雄特性页状态，④局部洗点后，⑤星图无旧槽位，⑥英雄装备页穿戴前后，⑦右栏4件逐卡与5件合卡，⑧Lmax拒绝和通过，⑨Lmin禁用，⑩金币/KP/XP等宽，⑪卷轴5格库存0/正数/未投放/点击前后，⑫药剂待用/生效/满槽，⑬同一页面较小窗口/长中文文案时无遮挡。

**尺寸**：以现有项目真实支持的窗口范围为准，至少1440×900与一个较小、实际可运行的尺寸；若项目不支持某尺寸，报明最低支持尺寸及截图，不制造伪通过。检查窗口缩放/DPI下完整信息能否查看；**原工程说明Mini 480×240为另一模式草案，不得自行把WP8改成双窗口**。

**动态**：快速连续点击一次性操作（XP、KP、卷轴、装备）、库存零下限、存档重载、4同职实例ID切换、弹窗打开关闭，确认无重复消费、幽灵卡或上轮状态泄漏。

最终截图必须附文件实际路径（可被接收方打开）、场景/前置状态、操作动作、操作后可见变化；只有`HUD_SMOKE_OK`不等于真实视觉通过。
