## 0. 一句话目标

玩家**手动分配每个英雄的天赋点、购买本轮金币星图**，技能学会后由战斗AI**自动释放**；星图为整轮提供跨系统、可重复购买的成长空间，既不恢复旧的技能装配/席位购买，也不抢走KP对怪物掉落生态的控制权。

本WP先完成“代表内容能真实运转”的**机制闭环**，不提前强行定稿五职业全部技能、星图最终布局、全部节点价格或十小时成长曲线。

| 旧有`active_skill_max_slots`、`SkillIds`可编辑装配、星图`skill_slots` | [C] 学会即自动纳入AI；不买技能槽、不装配技能 | 删除旧槽位计价与装配权威，旧UI“编辑”入口若退役须转向英雄天赋查看；Review记录迁移 |

## 2. 每职业4技能＋1特性的固定结构

### 2.1 槽位的**机制意义**（不是可购买装备槽）

| 类型 | 玩家获得方式 | 玩家使用方式 | 经验目标 |
|---|---|---|---|
| 固定技能1：基础攻击 | [C]开局默认已学 | [C]战斗AI自动使用 | 永久有基础输出，不因尚未投资天赋而断供 |
| 固定技能2：短CD招牌 | [C]天赋点学习 | 自动施放 | 早期明显的职业辨识度与效率提升 |
| 固定技能3：辅助/特色 | [C]天赋点学习 | 自动施放 | 职业差异：Buff、AOE、控制、召唤等 |
| 固定技能4：长CD高影响技能 | [C]天赋点学习 | 自动施放 | 中后期阶段性高光，不依靠手动配置槽位 |
| 第5项：独立职业特性树 | [C]可由**本轮星图**按职业分别购买对应节点**解锁区域；玩家再分配英雄天赋点 | 特性效果走现有Buff/Trigger/Effect路径 | 支撑职业特色的持续强化或规则变化 |

“4技能”指职业预先固定的四个技能定义，**不代表开局四个都已学**；“+1”是特性/特性小树，不强行当成第五个主动施放槽。若具体职业某项特性产生主动效果，仍通过统一技能/效果调度，不新增装配商店。[P]

[C]普通基础攻击不被天赋洗点删除；未学技能不可出现在自动施放队列中。英雄和怪物的具体技能优先级由既有AI策略承载，不能因为天赋学习擅自使其覆盖别人的技能决策。

### 2.2 内容参考与首包最小样本

- 现有设计示例：**野蛮人** `猛击 / 旋风斩 / 吼叫 / 先祖召唤`，职业特性`狂暴`。这提供了战斗行为多样性，但本包不把示例技能全部定为已通过实机的最终内容。
- 死灵法师保留已提出的`剔骨之牙`及`骷髅`特性方向，具体四技能列表仍需职业完整设计时定稿。
- [P] WP4工程验收先选**一名代表职业**完成“基础攻→学习招牌技→自动施放→互斥天赋→局部洗点→特性解锁”端到端，再以第二个职业或四名同职业实例做泛化/归属测试。**所有目前允许玩家选用的职业至少保留合法基础攻击与可玩战斗链**；其余职业的完整4+1内容缺口以清单列明，不能显示空槽却报告“5职业全部完成”。
- [P] 一轮首包不提前设计巨量技能BD，优先复用现有Effect/Buff/Trigger/Projectile等合适实现，确有缺的仅按技能需求扩展。

### 2.3 按职业购买特性资格（2026-10-25新增[C]）

- [C] 星图职业特性节点以**职业定义 `ClassId`** 为解锁粒度，而非以 `HeroInstanceId` 为购买粒度，也不是全职业公用一枚节点。
- [C] 玩家购买某职业的特性解锁节点后，**本轮所有上阵且属于该职业的英雄实例**立即获得该职业特性树的**学习资格**。例如买“野蛮人特性解锁”后，队伍内两名野蛮人都可以在英雄页学习自己的狂暴特性，但法师、死灵法师不受影响。
- [C] **资格共享 ≠ 学习共享 ≠ 天赋点自动消费**：各英雄自己的天赋余额、已学节点、互斥选择、Buff来源、CD/召唤归属仍按 `HeroInstanceId` 独立维护，玩家逐英雄点击学习。
- [C] 同职业重复实例不得要求重复购买相同职业的星图解锁节点。购买一次只扣一次**Run金币**，存档重载不得再次扣款；正式重生清除本轮职业解锁资格与各英雄天赋学习状态。
- [P] 购买节点前可显示“当前队伍中该职业上阵人数”，便于玩家预判价值；无人上阵时是否允许购买，首版建议仍允许按正常星图前置购买，不自动创建角色。
- [O] 该节点的最终位置、前置、售价、重复升级阶数后置至正式星图内容及数值阶段，不影响第一版机制与行为验收。

## 3. 英雄天赋：点数来源、分配、互斥和免费改选

**资产与归属**：[C]英雄升级获得的天赋点归该HeroInstanceId；[C]本轮星图可向**所有本轮上阵英雄**发放额外天赋点，但每个英雄实际怎么花仍由玩家独立选择。星图购买不是自动加天赋。

### 3.1 典型技能小树结构

- [C]每个固定技能拥有自己的多级强化区域，技能基础学习与升级强化可区分；有限分支满足“玩法变体”的意义。
- [P]数据结构至少允许`SkillId / NodeId / MaxRank / Prerequisite / ExclusiveGroup / TalentCost / EffectModifier / RegionId`；字段名由工程自主适配。
- [C]**分支互斥**是同一技能小树里的明确玩家选择：例如同一招式分支A与B不能同时获得；禁止跨英雄误冲突。
- [C]普通**互斥改选免费**；**按技能区域免费局部洗点**，局外付费整角色洗点机制不再作为日常必要操作。
- [P]重置技能区域时，返还区域内已经花掉的点、移除该区域所有效果，重新校验前置和互斥；不改变英雄等级、不删除其他技能区域投入、不返回星图金币。无效操作应整体拒绝，不留半条Buff。
- [O]局部洗点是否有任何在战斗中冷却/仅非战斗允许的限制？**建议第一版允许玩家随时在英雄页执行，但战斗中重新装配须保证原子刷新**；这是UE与平衡细节，不阻挡机制开发。

### 3.2 必须处理的边界

1. 一名英雄购买分支A不会替另一名同职业英雄选择分支。
2. 旧存档加载后应保留旧等级和玩家已取得的天赋价值，旧主动节点尽量映射，不能映射则**经可复核转换/返还**；不凭新版方案偷偷清掉历史点数或重复发点。
3. 星图赠点后既得的已投资天赋，不能被“配置缺失/中间态重算”悄悄删除；重生统一清空本轮天赋与赠点。
4. 旧`CastTalent`必须完全退出生产施法权威（包含测试断言与UI回调），不能新旧技能互相叠加。
5. 技能来源、Buff来源、召唤物Owner必须识别**英雄实例ID**，而不是仅凭职业SpecId合并。

## 4. 星图：先可用内容与分支，再节点布局/价格

**强制顺序（用户已确认）**：可接入的系统 → 其中适合金币星图的属性/行为 → 是否形成有意义的分支 → 根据单轮时长/点击目标安排节点与重复成长 → 最后才定价格。

### 4.1 星图本轮所有权与边界

- [C]星图金币购买、本轮共享、Run存储，正式重生清零；所购增益作为合法Modifier/功能开关进入运行时快照。
- [C]星图不是账号永久进度；解锁永久职业、第五队员席位、永久便捷功能归Account成就。
- [C]怪物级别/刷怪数量/金币装备卷轴药剂的**掉落生态调节**主要由KP；星图可以提供角色战力、成长效率、卷轴**威力/容量/自动施放**、药剂能力、离线有效时长等。
- [C]从旧星图删除`party_slots`和`skill_slots`；不能以价格、先决条件变化“变相保留旧席位升级”。
- [C]用户已明确**多节点、小额高频成长**优于单节点天价；同内容分隔重复并在后期更强数值是可接受设计，不要求所有节点唯一。

### 4.2 内容树（建议类别）

详见同包《星图横向内容池与系统边界 V0.5》：按`进攻 / 生存 / 评级 / 英雄成长 / 卷轴 / 药剂 / 冒险效率 / 离线便捷 / 职业特性解锁`九类整理；这是**内容候选池**，不是节点图、已批准的属性列表或正式价格。

[P]建议第一轮原型至少完成三个具有可见效果的样例：`队伍ATK +?`、`公共XP加成 +?`、`一处**按职业共享资格**的特性区域解锁`。其中“+?”保留测试配置且要可追溯；不得硬编码M3的十小时/75次星图点击作为目标。

### 4.3 重复购买的体验设计原则

- 用户给出的合理例子：前期`攻击+1，可点5次`；中后期`攻击+5，可点3–5次`。这里是**设计手法示例**，不是正式ATK数值/次数配置。
- [P]同属性不同档位节点分隔布局，中间穿插功能节点或职业/防御节点；让玩家在“短期点数提升”和“下一条功能解锁”之间有目标。
- [P]节点有前置、购买阶数、当前和下一级效果、价格、影响对象、当前是否生效；金币不足/前置不足不会扣除。一次点击只购买对应节点的一阶，不做全树批量购买（保持玩家主动成长）。
- [P]同级节点分支可以引导差异化，**不要为此锁死唯一必点路线**；任何星图方案都不得让无星图AR/DR的普通英雄无法到达常规KP准入。
- [O]星图节点回退/重置在单轮内是否允许？本阶段不需要设计付费洗星图；实现不应暗自增加可套利退款命令。

## 5. 玩家UI与操作验证

- **顶部英雄页**：按HeroInstanceId打开当前英雄；四技能定义（已学/未学/可学、CD、强化进度）及独立特性树；天赋点数、互斥标识、局部洗点入口。不要恢复“技能装备槽数”购物。
- **左下队伍状态栏与CD区**：固定保留；上阵1–4人显示已学技能的图标和CD/释放反馈；不同同职英雄彼此独立。未学技能可以灰态或隐去但必须有可追溯说明，不能伪装已学习。
- **顶部星图页**：购买节点、显示金币余额、效果预览/购买结果，至少一个数值节点真实进入战斗快照；功能节点要能看到实际行为开关（如特性区域从锁定变开放）。
- **右侧成长队列**：提醒未花天赋点及值得购买的星图机会；购买/学习必须保留玩家显式操作，不与英雄升级、KP、城堡或换装批处理。
- **卷轴/药剂区**：星图只改变合法的效果/容量/自动化控制（若当轮已开放）；绝不能绕开WP6的“同种药剂禁止并发、使用期间占槽、手动丢弃释放槽”等确定规则。
