## 3. 优先审计对象（按改造依赖排序）

1. **存档/状态权威：** `AccountState` / `RunState`（以真实工程命名为准）能否分离？角色实例、公共XP、金币星图、KP怪区间、城堡进度归单轮；职业和成就点归账号；正式重生与放弃本轮是否已有区分。
2. **战斗与属性：** 原Armor护甲减伤和新AR/DR的入口/消费者/默认配置；DMG1/2/3数据通道；ATK/HP自然成长；元素抗性/暴击；等级归因与测试。
3. **英雄/队伍/XP/升级：** 4个起始槽、1–4人出发、重复职业且独立实例、轮内锁队；个人XP/自动升级→公共XP/玩家手动指定升级；全员评级准入检查；分支/洗点接口。
4. **全局怪物区间及KP：** `Lmin/Lmax`是否当前轮次唯一来源，区域/章节/城堡是否残留独立怪物等级权威；Lmax、Lmin购买是否区分规则，怪数/掉率/KP账本和无法挽回0收入的风险监测入口。
5. **技能与天赋：** 每职业4固定技能＋1独立职业特性，学习即自动生效，无技能槽编辑；旧CastTalent与SkillRuntime并存链；AI动作优先级，天赋局部重置与互斥分支数据模型。
6. **装备/掉落/回城：** 角色实例绑定、等级品质评分与候选保留、旧装回城售卖、右侧替换事件、装备大于4件批量入口。
7. **金币星图、成就与重生：** 本轮星图节点与账号永久成就点商品分层；旧party_slots/skill_slots效果哪些已废止；初轮4章结算→第二轮新职业/第5章的状态入口。
8. **卷轴/药剂/离线：** KP掉率 vs 星图强化与自动施放，药剂用后占槽、生效结束释放，运行后台与真退出2小时离线结算语义。
9. **UI与观测：** 完整Steam主窗口、右侧成长队列；各自主升级指令；多怪房间/失败重试/技能级事件、XP金币KP资源账本/累计点击等可观测入口。
10. **配置与测试可复用性：** P2-2所谓142 ACTIVE参数、23条消费链、31接口/16工作包/23旧CastTalent的准确当前状态，是否因工程推进产生变化。
