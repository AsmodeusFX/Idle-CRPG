# 游戏开发工作流

先读仓库AGENTS.md并识别工程根、引擎/语言版本、测试入口、配置权威和存档位置。仓库规则与用户当前授权决定范围。本Skill提供可迁移方法，不把Idle-CRPG数值当成其他游戏的标准。

## 从证据进入开发

- 把需求拆成可观察行为、不可破坏的状态边界、明确排除项；分清审计、方案与已批准实施。
- 读取相关代码、真实配置和最新裁决。区分正式内容、legacy、QA夹具、规划预算及实际运行结果；文档中的旧版本描述不自动代表现状。
- 用户要求先诊断时先提交原因、证据、最小修改点；已有批准则继续实施，不重复询问。新增重大冲突或不可逆动作才按实际需要澄清。
- 优先修复单一责任层：逻辑、配置、表现或时序。复用原命令、伤害、奖励和预约权威，不为修复问题创建平行系统。

## 实现边界

- 纯逻辑不依赖引擎节点；UI安排命令，表现读取状态；输入、动画、摄像机不能直接决定奖励或命中。
- 固定步长推进与逐帧插值分开；同Tick多单位竞争须有确定顺序。不要用列表下标混淆永久ID、战斗ID和候选索引。
- 资源、占用、目标切换和一次性奖励按事务边界结算。检查建立、释放、死亡、失效、跨场景、重置与读档。
- 配置字段变化同步字典、校验、引用和迁移；原型参数与最终策划明确区分，不用静默默认掩盖错误。
- 存档修改先确认正式检查点与完整测试快照的差异；自动验证使用隔离目录，保留原子写盘、备份及退出等待。

## 按任务补充证据

- 战斗/移动/拥堵：先记录首次获得目标、开始移动、停止与攻击的位置和原因，核对刷新范围、激活时序、射程、真实间距及投影。全房面积不能代替交战局部密度。
- 镜头/UI：区分逻辑坐标、屏幕像素和表现偏移；记录窗口/视口、缩放、字体、血条和实际截图。无图形环境时不得声称视觉验收通过。
- 数值/地图：按实际加载路径核对配置；规划量与生成量分别报告；没有种子/存档时不编造截图现场数据。

## 跨平台与验收

读取[跨平台验证](references/cross-platform.md)。在Idle-CRPG使用[项目路由](references/idle-crpg.md)，按影响范围加载设计与技术文档。

验证先检查编译和有意义的不变量，再跑项目要求的回归；测试必须验证行为，不能只匹配实现文本。旧测试冲突时说明规则为何变化，保留原测试保护的其他行为，补充新断言，不能删除失败断言来制造通过。

结束时报告改动、精确命令/退出码、环境、实际证据、未验证平台及异常。实现完成、自动检查通过、实际渲染通过和人工体验通过分别表述。新增经验归档到仓库规范，不把整段聊天复制成普遍规则。除非明确授权，不commit、push或merge。
