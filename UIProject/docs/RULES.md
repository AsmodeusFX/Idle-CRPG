# FGUI拼界面规则

## 资源管理

- Common包用于存放其他包都大概率用到的素材和组件
- _Preview包用于存放Unity侧特效和模型的占位预览图，不允许修改和添加资源，详见[prefab预览](#prefab预览)
- 引入新的组件时，尽量考虑复用性，结合应用场景起一个偏通用的组件名，并结合自定义属性提供外部配置能力。如：游戏首页侧边菜单列表尽可能都使用同一份组件

## 页面结构与列表使用

- 同一界面的内容切换优先使用控制器，共用部分避免重复制作。
- 列表用于程序根据数据动态生成的同结构条目；数量和功能固定、无需数据生成的控件使用独立实例。

## 分组与层级

- 控件较多时按功能区域打组，使用 `grp` 前缀和明确名称，便于识别层级。
- Group 用于组织相关控件；需要独立复用或封装内部逻辑时使用组件。

## 命名

- 如果组件需要代码逻辑，则修改默认命名，如果仅作外观效果，则保持默认命名
- 按钮用`btn`前缀，如: btnSubmit,btnLogin
- 列表用`lst`前缀，如: lstCharacter,lstEquip
- GLoader如果需要接图片，则用`img`前缀，如: imgIcon, imgClock
- 如果是需要程序改名的文本，则用`txt`前缀，如: txtName, txtTime
- 自定义控制器需要使用`con`前缀，如: conValid
- 控制器条目如果全部命名，则会生成一个C# enum代码，需要避免使用C#关键字
- 对于顶级大页面，一般情况下使用`View`后缀，如果页面是二级弹窗，并且需要模态，则使用`Dialog`后缀

## 交付标准

- 需要占位的资源，比如头像、武器图标，应设置好填充对齐等，并且需要选中发布时清除
- 需要状态完整，能直接交付给程序使用
- 尽量丰富动效，不要图省事，除非用户明确要求少用动销
- 需要考虑不同尺寸屏幕的适配，做好关联，需要能在`宽极限`和`高极限`合理展示内容
  - 设计分辨率和`宽极限`/`高极限`的具体尺寸以`settings/Adaptation.json`为准（`designResolutionX/Y`和`devices`），拼界面前先读，不要凭经验假设横竖屏

## 动效

- 带关联的元素可以直接做`XY`动效，屏幕尺寸变化时运行时会自动修正关键帧，不需要额外处理
- 用`Scale`做弹出动效时，记得给元素设置轴心（如`0.5,0.5`）
- 循环播放的动效（`repeat=-1`）会和退出动效抢同一属性，交付时注明：关闭前先停止循环动效，再播放退出动效

- 同一功能区域的动效保持方向和节奏协调，避免无目的的闪烁、位移和多层淡入。
- 动画结束或中断后，应恢复正确的显隐和交互状态，避免残留遮挡。

## 性能优化

- 对于组件级别的`效果`和`Shader特效`，如果组件同屏少于等于3个，则可以使用，如果同屏多于3个，则应避免


## 文本

- 如果使用外描边，尽量采用两个文本重叠的方式实现，上层不设置外描边，以实现“外描边”的效果。此功能通常需要配合[自动文本](#自动文本)使用（前提是程序或外部组件需要修改文本内容）

## Plugins规则

这里的规则不在FGUI官方范围内，来自plugins扩展。

### 自动文本

用于实现自定义属性到文本的自动解析。

1. 给组件添加自定义属性，如: name，类型为text
2. 创建任意多个文本组件，内容填`my name is {name=Lau}`
3. 激活允许使用模板
4. 外部对象使用此组件时，修改name属性，能看到变化

除自定义属性外，插件还会把组件的标题（Label/Button 的`title`）作为`{title}`变量，所以描边文字可以做成 Label 扩展组件：两层文本都填`{title=默认值}`并开启模板，外部只需设置 title。注意这只是编辑器预览，运行时需要程序同样给模板变量赋值，否则没有被直接赋值的那层会显示默认值。

### Shader特效

可以通过Inspector`Shader特效`，添加扫光效果



## 工具与校验（AI 拼界面时）

- **FGUI 编辑器开着时**，它会自动把新建的组件 XML 登记进`package.xml`并分配资源 ID。此时不要再手动往`package.xml`加条目，否则会出现重复条目（`path_collision`）。以编辑器分配的 ID 为准，并据此修改`src`/`ui://`引用
- **新建整页界面**：openfairygui MCP 的`addComponent`/`attachDisplayNode`要求每个节点填写全部字段，单个操作的文档就超过 10 万字符。整页新界面建议参照现有组件 XML 直接编写，小范围修改再用 MCP 事务（先预检、再应用、再校验、最后保存）
- **交付前必须校验**：在 UIProject 目录下执行`../../Tools/ofgui/node_modules/.bin/ofgui validate . --json`，要求`status: valid`且`complete: true`。这是 shell 启动脚本，直接执行即可，不要用`node`去运行它
- `Tools/ofgui`里有对 @openfairygui 0.7.0 的本地补丁（`patches/apply-ofgui-patches.cjs`，`npm install`时会自动执行）。升级 ofgui 版本后如果补丁报“anchor not found”，需要重新检查上游是否已经修复
